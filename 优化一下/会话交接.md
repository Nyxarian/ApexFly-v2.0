## 7. 日志怎么读

### `[V]` 行（500ms 一行，垂直轴全部信息）

```
[V] raw=<mm> | h=<cm> vz=<cm/s> v=<0|1> | req= mode= st= sw=0x ct=0x stick= h_sp= gt=ms fs=ms fr= | vzsp= corr= i= thr=
```

| 字段 | 含义 |
|---|---|
| `st` | ⭐ 细分状态：**0** 普通 / **1** 定高在干活 / **4** 停手 / **5** 已进模式未使能 / **6** 失效保持 / **7** 失效下降 |
| `sw` / `ct` | 两层门禁位图，全通分别是 `0xF` |
| `fs` / `fr` | 失效计时 / 失效原因（0 无、1 ToF 失效、2 姿态超限、3 高度越界）。⚠️ **`fr=2` 时 `thr` 立刻 1000**，是设计不是 bug |
| `vzsp` | 外环输出（内环的目标垂速）。符号：命令上升为正；死区 2cm 内恒 0 |
| `corr` | 快层（垂速内环修正量）。⚠️ **符号必须与 `vz` 相反**，这是负反馈的唯一证据 |
| `i` | ⭐ 慢层（悬停油门估计器），钳在 **1150~1650**。台架上只有它能看出积分在不在工作 |
| `thr` | 基础油门。定高时 = `i + corr` 再钳到 [1150,1650]；普通模式跟杆走 |

## 8. 已经踩过的坑（别重犯）

| # | 坑 | 结论 |
|---|---|---|
| 1 | **`L6200E: Symbol HAL_UART_ErrorCallback multiply defined`** | 加全局符号前先全工程 grep。光流与 GPS **必须互斥编译**（同一个 `APEX_UART2_ROLE_FLOW` 开关控制两个 HAL 回调） |
| 2 | ⚠️ **CubeMX 重新生成会覆盖手改** | `usart.c` 里 `huart2.Init.BaudRate = APEX_UART2_BAUD` 和 `app_freertos.c` 里 `gpsTask` 的那个 `#if` **都不在 USER CODE 区** ⇒ 生成完必须回来确认（否则波特率打回 9600、光流一帧收不到） |
| 3 | **停手门槛必须 > 地面静止读数** | 门槛低于读数 ⇒ 停手永远进不去（2026-09-14 翻过车）。反向也不行：门槛太高会把低空悬停误判成停手 ⇒ 油门压最低 ⇒ **掉下来**。规矩是**撤垫块后重新实测**，门槛取"实测 + 1~2cm" |
| 4 | **打印绝不能进 250Hz 控制环** | 一行约 10ms，会吃掉两拍 4ms 预算。打印全在 `tof.c`（tofTask，500ms） |
| 5 | `USART3` 是 **5ms 轮询 + FIFO 关闭**（硬件只存 1 字节） | 串口命令**必须逐字节发、间隔 ≥10ms**，否则被吃掉。这就是"发命令又慢又脆"的根因 |
| 6 | **`.uvprojx` 是手改的** | 改之前 Keil 必须关着 |
| 7 | 仿真能抓产品代码的错 | H6 的"**永远起飞不了**"死循环就是仿真抓出来的。**烧录前先跑仿真**（见下一节） |

## 11. 成本纪律（给用户看的，AI 也要遵守）

**实测结论**（用 `measure_usage.js` 量的上一个会话）：

- 上下文长期卡在 **700K~790K**；**三次压缩只降了 10% / 3% / 6%** ⇒ **压缩救不了**。
- 换新会话，同样工作量**输入省约 18 倍**（拆成多个会话约 30 倍）。

**规矩：**
1. ⭐ **一个环节 ≈ 一个会话。**（H8/H9/H10 一个、H12/H13 一个、OF1~OF5 一个）
2. 换会话的触发：**一个环节做完并提交** / **上下文 > 200K** / **已经压缩过 1 次** / **换任务类型**。
3. AI 回复默认走压缩档；**长报告只在"要留档"时才写**。
   （上一个会话里，AI 自己的回复占会话体积的 **58%**，是最大单项。）
4. 换会话时**不要把旧日志/长工具回显粘过来** —— 给文件路径，或重新生成。
5. 本文件就是交接资料。**每次换会话前更新本文件的第 3、4 节。**
