# 串口回显测试（临时）

> 日期：2026-09-14 ｜ 类型：**临时脚手架**，不属于定高主线 ｜ 状态：🔨 代码完成，待烧录验证

## 1. 为什么插这一脚

用户要测新写的**上位机串口工具**，需要一个"发什么就返回什么"的对端来验证收发回路。
原来的串口是**纯打印**的，测不了回路。

## 2. ⭐ 为什么必须走中断，不能沿用现有的轮询（这是本次最有价值的一条）

| 事实 | 出处 |
|---|---|
| 115200 8N1 → **每字节只有 86.8µs** | — |
| 全项目**没人用 USART3 中断**：`USART3_IRQHandler` 只有启动文件里的 `[WEAK]`；`HAL_UART_Receive_IT` / `Receive_DMA` 一次都没被调用过 | `MDK-ARM/startup_stm32g474xx.s:389` |
| 收数据靠**黑匣子任务每 5ms 轮询一次 `RDR`** | `Modules/Flash/blackbox.c` → `Blackbox_PollUart()`，`BLACKBOX_UART_POLL_MS = 5` |
| USART3 的 **FIFO 是关掉的**，硬件只存 **1 个字节** | `Core/Src/usart.c`（`HAL_UARTEx_DisableFifoMode`） |

⇒ **5ms 能来 57 个字节，只能收到 1 个。** 这就是项目里一直存在的限制：
**用串口发命令必须逐字节发、间隔 ≥10ms。**

⚠️ 直接推论：**如果把回显塞进现在这个 5ms 轮询点，上位机发一串字符只会回来 1 个字节**，
很容易被误判成"上位机工具坏了"，而真正原因在飞控的轮询设计。
更关键的是：**轮询无论多快都不安全** —— 任何一个任务只要被抢占几百微秒
（250Hz 控制环每 4ms 必然跑一次），这期间到的字节就没了。
把回显任务提到最高优先级又会挡住控制环。

**所以回显必须走中断：ISR 只做"1 个字节进环形缓冲 + 通知任务"，回显任务慢慢往外发。**

### 三个必须守住的约束（都写在 `serial_echo.c` 的文件头）

1. **ISR 里只做两件事**：字节入缓冲、重新武装。绝不在这里发送（发送是阻塞的）。
2. **先重新武装、再给信号量**：HAL 一次只收 1 个字节，回调返回时必须已经重新使能 RXNE；
   而给完信号量返回时可能立刻切到回显任务，那一瞬间没在收就会丢字节。
3. **NVIC 优先级必须 ≥ 5**（`configLIBRARY_MAX_SYSCALL_INTERRUPT_PRIORITY`），
   否则在 ISR 里调 `xSemaphoreGiveFromISR` 会破坏内核。实际取 **6**。

### 为什么 ORE 必须自己兜住

USART3 一出溢出，**HAL 会把正在进行的接收中止掉、不再产生接收完成中断** ——
表现就是"回显突然装死"。所以 `USART3_IRQHandler` 里**先把 ORE 清掉再交给 HAL**
（HAL 看不到错误就不会中止接收），并在末尾兜一次重新武装。
这正是"断开再插回来照样能用"的关键。

⚠️⚠️ **两个坑（都是实际编译/思考时踩到的，别再踩）**：

1. **不能用 `HAL_UART_ErrorCallback` 这个全局符号** —— **GPS 已经在 `gps.c:152` 定义了它**
   （按 `Instance != USART2` 过滤，对 USART3 直接返回）。再定义一个会链接冲突：
   `L6200E: Symbol HAL_UART_ErrorCallback multiply defined (by gps.o and serial_echo.o)`。
   **第一次编译就是这么失败的。**
   ⇒ 教训：动手加 HAL 弱回调之前，**要把"本项目已自定义的 HAL 弱回调"整个列表查一遍**
   （`grep 'HAL_UART\w*Callback'`），不能只查自己想到的那几个符号。
   本项目现状：`HAL_UARTEx_RxEventCallback` 和 `HAL_UART_ErrorCallback` → `gps.c`（USART2）；
   `USART2_IRQHandler` → `stm32g4xx_it.c`；`USART3_IRQHandler` 无人占用（启动文件里是 WEAK）。
2. **不能用 `__HAL_UART_CLEAR_PEFLAG` 清标志** —— 那个宏靠"读 SR 再读 DR"来清，
   **读 DR 会把一个还没取走的字节吃掉**。只写 ICR 清单个 ORE（`__HAL_UART_CLEAR_OREFLAG`）才安全。

## 4. 已知副作用（测试期间）

| 副作用 | 说明 |
|---|---|
| ⚠️ **黑匣子的串口命令全部不可用**：`dump` / `dumpall` / `calmag` / `vm` | RX 被回显独占。**所以此测试不能和 H8 的验证混在一起做** |
| ⚠️ **`[ALT]` 被静音** | 而 **H17a 的验证正要靠它看 `req`/`mode`** ⇒ 顺序必须是 **回显测试 → 恢复 → 再验 H17a** |
| 启动时仍会看到少量一次性日志 | `[BB] ready ...`、`[TOF] init ok ...`、`[I2C2] scan ...` 等，只在开机出现，正好能看出板子起来了 |
| 每字节一次中断 ≈ **5% CPU** | 不影响控制环（回显任务 BelowNormal，控制环 High） |
