### 买的是什么

**Cheerson CX-OF**（淘宝"mini 光流"就是它）。不是杂牌——**ArduPilot 官方支持它**（`FLOW_TYPE = 4`）。

### 协议（已从商家资料确认）

```
0xFE | 0x04 | DX_L | DX_H | DY_L | DY_H | SUM | Quality | 0xAA
               └──── 4 字节光流数据 ────┘   ↑      ↑       ↑
                                     累加和  图像质量   包尾
```

| 项 | 值 |
|---|---|
| 波特率 | **19200**，8 数据位，无校验，无流控 |
| 更新率 | **40ms 一帧 = 25Hz**，有数据自动发（不用轮询） |
| DX / DY | **int16（有符号）**，是"从上次更新到现在的位移计数" |
| SUM | 中间 4 个字节相加取低 8 位 |
| Quality | 0~100，**< 30 建议舍弃** |

> ② 打印口的 **RX 引脚被光流占用** ⇒ 台架上想发命令得先拔那根线（飞行中不需要发命令）。

### ⭐ 第五条：尺度不用标，**零点偏移必须标**

商家 demo 里最关键的三行：

```c
speed_x = -flow_x;                                        // 只是取反，没有任何比例系数、没有除高度
sum_flow_x += vx * 0.05f;                                 // 把"流量"累加成"位移"
pos_pid_out_x = PID_calculate(..., 0.0f, sum_flow_x, ...); // 位置环目标是 0
```

**思路：把"累积光流"当成位置，用 PID 把它钉在 0。**

⚠️ **但必须分清两件事**：

| | 要不要标定 | 为什么 |
|---|---|---|
| **尺度**（1 个计数 = 多少米） | ❌ **不用** | 因为**目标永远是 0**，尺度错了只是环路增益不对，**不会造成漂移** |
| ⭐ **零点偏移**（静止时读数不为 0） | ✅ **必须标** | 环路会把"**读数**"压到 0。若静止时读数本来是 +3，它就会让飞机**真的往反方向移动**直到读数为 0 —— **这就是恒速慢漂的直接原因** |

PMW3901 这类传感器在静止时确实会报出很小的非零流量（像素噪声、光照不均、装配公差）。**不处理它，位置环就会变成"恒速漂移机"。**

**好在标定很简单**，而且我们已经有现成的模式可以照搬：

> 水平零点就是这么干的：**上电、静止时采几秒取平均，作为本场次的零点**。
> 光流用同一套：**每次上电、飞机静止时采几秒光流的平均，之后每帧减掉它。**

⇒ **不需要转台、不需要已知位移的滑动测试、不需要 counts-per-radian。**

代价：得到的是"**把相对地面的运动压到零**"（= 钉住），**不是**回到某个绝对坐标。长期仍有缓慢漂移——这是光流的固有性质。

### ⭐ 预期能到什么水平（先把期望定下来）

| 方案 | 松杆后实际表现 |
|---|---|
| **现在**（纯姿态，无位置反馈） | 起飞漂 2~5 米，之后持续缓慢漂 |
| **光流 + 位置环**（本表 OF1~OF12 的档次，≈ 商家 demo） | 原地游走 **±20~50cm**；短时间不会跑出 1 米 |
| **光流 + 加速度计融合**（再加 OF13） | **±10~20cm**，明显更"钉" |
| RTK | ±2~5cm（真厘米级，但贵、只能室外） |
| UWB | ±10cm（室内，要布站） |

**结论**：相比现在是**数量级改善**，但**"厘米级"要理解成"十几厘米级"**。真"几厘米"要靠 RTK / UWB。
想要"十几厘米"这一档，**零点偏移标定（OF5）和 IMU 融合（OF13）两个都要有**。

另外：**定点效果好不好，一半取决于地面**——有纹理的地板最好；纯色瓷砖/抛光地面/地毯差很多甚至失效；太暗（<60Lux）、水面、镜面直接失效；室外有风会顺风飘（我们没有风估计）。

## 排序规则（七条）

1. **先让数据"看得见"，再谈控制** —— 串口 → 解析 → 有效性 → 累积，前四步全是只读；
2. ⭐ **先标零点，再谈闭环** —— 光流的零点偏移不标就是恒速漂移，闭环前必须解决；
3. **先算出来，再发出去** —— 位置环先在台架上跑通、只打印，**不接姿态**，这一步零炸机风险；
4. **先无扰，再接管** —— 使能门禁与切换无跳变，必须排在"第一次接控制"之前；
5. ⭐ **高度估计先行，但不必等定高**（2026-09-18 更正）—— 定点依赖的是**高度估计**
   （光流要靠高度才能把流量换成速度），那是 H1~H6 的产物，**已经做完了**。
   原来的"定点只在定高模式下起作用、必须在定高模式+已解锁+杆不在待命段时做"**作废**
   （待命段已取消；定点也不必绑定高）。
   现在建议：**第一次接控制先跑在普通模式下** —— 油门由人管、垂直那一路不参与，
   出问题时只有一个新环在动，容易定位；
6. **权限从极小开始** —— 第一次接管只给 **±3°**，方向反了也能救；
7. **先验证，再整定** —— 每次改参数都必须有黑匣子波形作依据。

## OF1~OF5 验收步骤（2026-09-21：全部通过，保留作回归基线）

⚠️ **全程拆桨**（本阶段光流不接任何控制，拆不拆桨都安全；拆桨可以顺便听电机）。

### 烧录前

1. ⭐⭐ **断电，量 GPS 座 VCC–GND = 3.3V**，核对线序，再把光流插上（只接 **GND + TX** 两根）；
2. 确认 `Core/Inc/apex_config.h` 里 `APEX_UART2_ROLE_FLOW = 1`；
3. Keil 编译烧录（**只烧飞控，遥控端一行没动**）。

### 观测：只看 `[OF]` 一行

```
[OF] n=帧数 bad=累加和/格式 qrej=质量拒绝 | q=质量 dx dy | z=零点 | sx sy | v=可用 cal=标定态 a=age
```

| # | 操作 | 期望 |
|---|---|---|
| ① | 上电 | `[OF]` 行出现；`n` 持续增长；`q` **远大于 30** |
| ② | ⭐⭐ 上电静止至少 70 秒 | 前约 10 秒 `cal=1`，随后变 **2**；再静止 60 秒，`sx/sy` 不应持续单向增长 |
| ③ | ⭐⭐ **用手沿机头方向缓慢平移** | 对应轴 `s` **单调变化**；反向平移 → 反向变化 |
| ④ | 盖住镜头 / 对着纯色面 | `q` < 30 ⇒ `v=0`、`sx/sy` **冻结**、`qrej` 增长 |
| ⑤ | 拔信号线 | `v=0`、`a` 涨过 200ms；插回后自动恢复 |
| ⑥ | 拿着飞机晃动几下再看 `cal` | 若晃动正好落在采样期 ⇒ `cal=3`（判失败）→ 1 秒后自动重来，**不许留下坏零点** |
| ⑦ | 换一块地面重新上电 | 重标之后 `sx/sy` 仍能压住 |
| ⑧ | ⭐ **回归**：普通模式 / 定高模式各走一遍 | `[V]` 行与改动前**完全一致** |

### 停止条件（出现任一条先停下来）

1. 插之前量到的**不是 3.3V** ⇒ 先断电，不许插；
2. `q` 长期 < 30、或帧率远低于 25Hz ⇒ **接线/波特率/供电有问题，不要再往下做**；
3. 静止时 `sx/sy` **持续单向快速增长** ⇒ 标定没生效；
4. 平移测试方向与机头完全对不上 ⇒ 轴映射写错；
5. 普通模式或定高模式出现**任何**与改动前不同的现象。

### 软件侧已做的自查（不碰硬件）

- `arm-none-eabi-gcc -fsyntax-only -Wall -Wextra -Wformat=2`：**两种开关状态都全绿**
  （role=1 光流 / role=0 GPS）；
- ⭐ **符号互斥在目标文件层面验过**：`HAL_UARTEx_RxEventCallback` / `HAL_UART_ErrorCallback`
  在 role=1 时只定义在 `flow.o`、role=0 时只定义在 `gps.o`（用 `nm --defined-only` 查的，
  **不是靠读代码**）—— 这条是 2026-09 串口回显测试踩过 `L6200E` 之后专门加的检查；
- ⭐ **宿主机仿真 `sim_flow.c`：37 项全过** —— 驱动的是 `flow.c` 里**真的 `Flow_Task`**
  （外设与 RTOS 是桩，用"反向控制"让 `osDelay/taskYIELD` 去推进仿真世界，
  于是整场跑在同一个栈帧里、`Flow_Init` 只执行一次，而循环体是产品代码原文）。
  覆盖：正常帧流、**DMA 缓冲绕回**、坏校验/坏长度/坏包尾、**半截帧跨事件拼装**、
  **粘包**、帧中插噪声后的**重新同步**、质量门槛边界（29 / 30）、**标定期间不累积**、
  **质量失效时冻结而不是清零**、超时失效与恢复、**标定守卫与自动重试**、
  以及 250 帧窗口把单个异常计数的零点影响从 0.04 降到 0.004 的回归。

  ⚠️ 仿真抓出我**一条写错的判据**（把"累加和错 2 次"写成了 1 次）：帧中间插噪声会让窗口错位，
  而**错位窗口几乎都先在累加和这一步被拦下** ⇒ checksum 计数会多一次。
  这条差别本身有用：**"checksum 一直在涨"未必是波特率问题，也可能只是有噪声字节**。

## 可以并行 / 合并的

- **OF1 与 OF2 可以合并**：接线对了、字节进来了，直接往下解析就是；
- **OF3 / OF4 / OF5 可以合并**：都是"只读只算"，一起验也不冲突；
- **OF9（黑匣子）与 OF10（遥控器）可以并行**（不同仓库），但 **OF9 必须赶在 OF11 之前**；
