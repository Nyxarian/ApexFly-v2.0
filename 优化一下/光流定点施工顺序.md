## 前置事实（硬件与协议，写代码前必看）

### ⭐ 前置前提：定高已经是一个"独立模式"

2026-09-11 起，定高**不再是"一个开关"**，而是一个独立的模式：

| | 普通模式 | 定高模式 |
|---|---|---|
| 油门杆 | **直通油门**（1000~1600µs） | **四段式**：待命 0~100 ／ 下降 100~350 ／ 保持 350~650 ／ 上升 650~1000 |
| 速率 | — | 下降 **−2 → 0**、上升 **0 → +3** cm/s |
| 切换条件 | — | **已上锁 + 杆在待命段**（⇒ 一次飞行只能用一个模式） |
| 模式值 | 0 | 1 |

**对定点的影响**：

1. **定点只能在"定高模式"下起作用**（它管的是水平，垂直由定高管）；
2. 定点使能的条件应该复用定高的**第二层门禁**（已解锁 + 读数可信 + 姿态平稳 + **杆不在待命段**）；
3. ⭐ **定点开关的形态还没定**（是独立模式值？还是定高模式内的一个位？能不能空中切？）
   —— 见 `高度接入飞控方案.md` **§15.2 待讨论事项**；
4. 定高的"待命段"正好也是定点该停的时候（不控制），两者天然一致。

详设定高侧全部细节见 `高度接入飞控方案.md` §5、§6。

### 买的是什么

**Cheerson CX-OF**（淘宝"mini 光流"就是它）。不是杂牌——**ArduPilot 官方支持它**（`FLOW_TYPE = 4`）。

### 协议（已从商家资料确认）

```
0xFE | 0x04 | DX_L | DX_H | DY_L | DY_H | SUM | Quality | 0xAA
               └──── 4 字节光流数据 ────┘   ↑      ↑       ↑
                                     累加和  图像质量   包尾
```

| 项 | 值 |
|---|---|
| 波特率 | **19200**，8 数据位，无校验，无流控 |
| 更新率 | **40ms 一帧 = 25Hz**，有数据自动发（不用轮询） |
| DX / DY | **int16（有符号）**，是"从上次更新到现在的位移计数" |
| SUM | 中间 4 个字节相加取低 8 位 |
| Quality | 0~100，**< 30 建议舍弃** |

### 六条硬约束（踩了会烧模块或白干活）

| # | 事实 | 后果 |
|---|---|---|
| 1 | ⭐ **供电只能 2.7~3.3V，绝不能接 5V** | 飞控 TELEM 口一般给 5V → **必须有单独的 3.3V 取电方案** |
| 2 | **只发不收**（3 根线：VCC / GND / TX） | 飞控**只需要一个 RX**，不需要 TX —— 串口紧张时是好事 |
| 3 | ⭐ **延迟约 80ms**（ArduPilot 推荐 `EK2_FLOW_DELAY = 80`） | **位置环周期必须 ≥ 80ms ⇒ 只能做 10~12.5Hz**，这不是保守，是物理决定的 |
| 4 | **没有陀螺补偿**（商家 demo 里试过、注释掉了） | 姿态机动时光流会读到假运动 → **定点只能在松杆、姿态平稳时启用** |
| 5 | **没有高度输出** | 必须配测距 —— 我们有 ToF ✓ |
| 6 | **输出是"原始位移计数"，不是速度** | 见下面第五条：尺度不用标，**但零点偏移必须标** |

### ⭐ 第五条：尺度不用标，**零点偏移必须标**

商家 demo 里最关键的三行：

```c
speed_x = -flow_x;                                        // 只是取反，没有任何比例系数、没有除高度
sum_flow_x += vx * 0.05f;                                 // 把"流量"累加成"位移"
pos_pid_out_x = PID_calculate(..., 0.0f, sum_flow_x, ...); // 位置环目标是 0
```

**思路：把"累积光流"当成位置，用 PID 把它钉在 0。**

⚠️ **但必须分清两件事**：

| | 要不要标定 | 为什么 |
|---|---|---|
| **尺度**（1 个计数 = 多少米） | ❌ **不用** | 因为**目标永远是 0**，尺度错了只是环路增益不对，**不会造成漂移** |
| ⭐ **零点偏移**（静止时读数不为 0） | ✅ **必须标** | 环路会把"**读数**"压到 0。若静止时读数本来是 +3，它就会让飞机**真的往反方向移动**直到读数为 0 —— **这就是恒速慢漂的直接原因** |

PMW3901 这类传感器在静止时确实会报出很小的非零流量（像素噪声、光照不均、装配公差）。**不处理它，位置环就会变成"恒速漂移机"。**

**好在标定很简单**，而且我们已经有现成的模式可以照搬：

> 水平零点就是这么干的：**上电、静止时采几秒取平均，作为本场次的零点**。
> 光流用同一套：**每次上电、飞机静止时采几秒光流的平均，之后每帧减掉它。**

⇒ **不需要转台、不需要已知位移的滑动测试、不需要 counts-per-radian。**

代价：得到的是"**把相对地面的运动压到零**"（= 钉住），**不是**回到某个绝对坐标。长期仍有缓慢漂移——这是光流的固有性质。

### ⭐ 预期能到什么水平（先把期望定下来）

| 方案 | 松杆后实际表现 |
|---|---|
| **现在**（纯姿态，无位置反馈） | 起飞漂 2~5 米，之后持续缓慢漂 |
| **光流 + 位置环**（本表 OF1~OF12 的档次，≈ 商家 demo） | 原地游走 **±20~50cm**；短时间不会跑出 1 米 |
| **光流 + 加速度计融合**（再加 OF13） | **±10~20cm**，明显更"钉" |
| RTK | ±2~5cm（真厘米级，但贵、只能室外） |
| UWB | ±10cm（室内，要布站） |

**结论**：相比现在是**数量级改善**，但**"厘米级"要理解成"十几厘米级"**。真"几厘米"要靠 RTK / UWB。
想要"十几厘米"这一档，**零点偏移标定（OF5）和 IMU 融合（OF13）两个都要有**。

另外：**定点效果好不好，一半取决于地面**——有纹理的地板最好；纯色瓷砖/抛光地面/地毯差很多甚至失效；太暗（<60Lux）、水面、镜面直接失效；室外有风会顺风飘（我们没有风估计）。

### 从商家 demo 里抄什么 / 不抄什么

| 抄 | 不抄 |
|---|---|
| ⭐ **按高度调增益**（flow ∝ 1/高度，所以增益要随高度增大） | **PID 参数**（`KKP=0.1`、`KP=12`、`KD=1`）——那是他们机架、他们量纲下的值 |
| **摇杆居中才使能**的门禁（他们用 ±30） | `-flow_x` 的**符号与轴映射**——必须自己实测 |
| 位置环 / 速度环两级 + 输出低通（约 2.5Hz）的结构 | 固定 6 档的高度表（我们做连续补偿更好） |
| Quality 判据 + 限幅 | 用"欧拉角差分"补偿光流（他们自己都注释掉了） |
| ⚠️ **但他们也没做零点偏移标定** —— 这是我们比 demo 做得更细的地方 | |

## 排序规则（七条）

1. **先让数据"看得见"，再谈控制** —— 串口 → 解析 → 有效性 → 累积，前四步全是只读；
2. ⭐ **先标零点，再谈闭环** —— 光流的零点偏移不标就是恒速漂移，闭环前必须解决；
3. **先算出来，再发出去** —— 位置环先在台架上跑通、只打印，**不接姿态**，这一步零炸机风险；
4. **先无扰，再接管** —— 使能门禁与切换无跳变，必须排在"第一次接控制"之前；
5. **定高先行** —— 定点依赖高度（增益补偿要用高度，而且没有定高就没法在空中验证）；
   ⭐ **定点只在"定高模式"下起作用**，所以**第一次接控制必须在"处于定高模式、已解锁、读数可信、杆不在待命段"的状态下做**；
6. **权限从极小开始** —— 第一次接管只给 **±3°**，方向反了也能救；
7. **先验证，再整定** —— 每次改参数都必须有黑匣子波形作依据。

## 三个关键节点

| 节点 | 在哪 | 为什么重要 |
|---|---|---|
| **第一个"零风险可验证"的里程碑** | **OF7 结束** | 到此为止**绝不接控制**，但解析、有效性、累积、轴符号、**零点标定**、位置环、门禁、无扰切换**全部验完了**。台架上就能做，不用飞 |
| **第一个"有炸机风险"的动作** | **OF11** | 位置环的输出第一次真的会推动姿态。之前所有环节都可以在桨叶拆掉或飞机固定住的条件下做 |
| **第一个"必须拿到数据才能继续"的点** | **OF12** | 从这里开始，每次改参数都必须先导黑匣子看波形 |

## 可以并行 / 合并的

- **OF1 与 OF2 可以合并**：接线对了、字节进来了，直接往下解析就是；
- **OF3 / OF4 / OF5 可以合并**：都是"只读只算"，一起验也不冲突；
- **OF9（黑匣子）与 OF10（遥控器）可以并行**（不同仓库），但 **OF9 必须赶在 OF11 之前**；
- **OF15 可以和整定并行**，但它动协议，要单独走一轮遥控器升级；
- **OF14 必须等定高整套做完**（H13~H19）。
