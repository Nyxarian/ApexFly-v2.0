# ApexFly V2.0 姿态链路优化实施顺序（详细版）

> 配套文件：`姿态链路优化清单（逐环节·含影响结果）.md`（问题清单）、`姿态链路优化备注（MPU6050-PID-电机）.md`（过程分析）
> 整理时间：2026-09-08
> 说明：本文件把 P0/P1/P2 展开成**可逐步执行的操作序列**，每一步都写明"改哪里、怎么验、错了怎么退"。
> 标记约定：**[软件]** = 只改代码即可（我可执行）；**[台架]** = 需要拆桨/系留/示波器等硬件操作（你执行）；**[飞行]** = 需要实际起飞的验证。

---

## 0. 为什么是这个顺序（先看这一节）

顺序的核心只有一条原则：**先把会改变"环路时序与数据质量"的软件问题清掉，再动校准，最后一次性整定 PID；算法增强放最后。**

理由（这三条决定了下面所有排序）：

1. **P0 清障会改变环路时序**——删掉每拍打印（16.5ms→10.5ms）、固定周期、dt 改微秒，都会改变采样与控制的相位特性。**在这之前整定 PID，等于拿一把会变的尺子量东西**，改完还得重调。
2. **P1 校准会改变姿态基准与噪声水平**——水平零点、零偏、陀螺量程、加计滤波，都会改变"测量输入"的偏置与噪声。**基准没定准就整定 PID，调出来的增益会在换基准后失效**。
3. **P2 算法增强会改变控制律本身**——中值积分、D 项改测量微分、anti-windup，每一项都会改变 PID 的动态特性，**必须放在 PID 整定之后、并逐项微调**。

### 依赖关系图

```
阶段 0  基线记录
   │
   ▼
阶段 1  P0 清障（删打印 → 混控下限 → 优先级/周期 → dt 微秒 → I2C 容错）
   │        └─ 完成后：环路时序稳定、可测量
   ▼
阶段 2  P1 校准与数据质量（加计标定 → 水平零点 → 零偏 → 量程 → 加计滤波）
   │        └─ 完成后：姿态基准准、噪声低
   ▼
阶段 3  PID 重新整定（台架 → 微风飞行 → 归档）
   │        └─ 完成后：有一套"在当前软硬件状态下有效"的参数
   ▼
阶段 4  P2 算法增强（每项做完微调，不重头整定）
```

### 三条铁律

1. **每次只改一项**，改完立刻用黑匣子/台架对比，不允许"一口气改五项再飞"。
2. **每改一项都留档**：`pid.csv` + 黑匣子场次号 + 一句结论，写进 `优化一下\调参记录.md`。
3. **凡涉及滤波、频率、控制律的改动，必须重新整定 PID**（清单里已逐项标注）。

## 3. 阶段 1：P0 清障（S1-1 ~ S1-6）

|---|---|
| 目标 | 控制环恢复稳定 10ms 节拍 |

| 回退 | 恢复该 4 行代码 |

### S1-2 PWM 400Hz ✅ 已完成（记录归档）

| 项 | 内容 |
|---|---|

### S1-3 混控下限统一 [软件] + [台架]

| 项 | 内容 |
|---|---|
| 目标 | 消除"事后逐路抬到 1050us"造成的差速扭曲 |
| 前置 | S1-2（需要先知道电调真实起转点） |
| 改动点 | ① `Modules/Control/mixer.h/.c`：给 `Mixer_Calculate()` 增加"最低有效油门"入参（或在函数内用 `minimum_pulse_us` 作为有效下限）；② `Modules/Motor/motor_test.c:55-66`：删除四行 `if (< 1050) = 1050` |
| 做法 | 台架先测四路电调**实际起转点脉宽**（逐路从 1000us 缓慢加，记录起转值），取四路最大值 + 余量作为"最低有效油门"（例如实测 1060 → 取 1080）；把它作为混控的统一下限参与 `correction_scale` 计算 |
| 验证 | 拆桨、大修正工况（手拨机体）：黑匣子 `m1–m4` 列的"两快两慢"差速应严格对称，且无某一路被钉在 1050 |
| 验收 | 大修正时四路脉宽满足混控公式比例（误差 <2us）；低油门段无停转 |
| 风险 | 下限设太低 → 某路停转（推力不对称）；设太高 → 姿态修正余量变小 |
| 回退 | 恢复逐路裁剪（把删掉的 4 行加回） |
| 耗时 | 1–2 小时（含台架测起转点） |

### S1-4 控制任务优先级 + 固定周期 [软件]

| 项 | 内容 |
|---|---|
| 目标 | 消除 radio 抢占导致的抖动；消除 `osDelay` 的周期漂移 |
| 前置 | S1-1（先有干净节拍，才能看清优先级的影响） |
| 改动点 | ① `Core/Src/app_freertos.c`：`motorTestTask_attributes.priority`、`radioTask_attributes.priority`；② `Modules/Motor/motor_test.c`：主循环 `osDelay(10)` → `osDelayUntil(下一拍绝对时刻)` |
| 做法 | **优先级建议**：`motorTestTask` → `osPriorityAboveNormal(32)`，`radioTask` → `osPriorityNormal(24)`（控制优先于链路，链路仍高于 mag/gps/blackbox）。若担心链路响应变差，可先只把 radio 降到 Normal 观察。<br>**周期**：在进入内层循环前记录 `uint32_t next = osKernelGetTickCount() + 10;`，循环末尾 `osDelayUntil(next); next += 10;` |
| 验证 | 黑匣子 `t_ms` 直方图更集中；`accepted_count/rejected_count` 无异常增长 |
| 验收 | 解锁段 dt 99% 落在 9–11ms；链路不丢帧（遥控遥测正常刷新） |
| 风险 | 控制任务变高优先级后若某拍耗时异常长，会挤压低优先级任务（blackbox 写 Flash 可能延迟） |
| 回退 | 优先级改回原值；`osDelayUntil` 改回 `osDelay` |
| 耗时 | 1 小时 |

### S1-5 dt 改用微秒计时 [软件]

| 项 | 内容 |
|---|---|
| 目标 | 把 dt 量化误差从 10% 降到 <0.1% |
| 前置 | S1-4（周期先稳定） |
| 改动点 | ① 新增微秒时基（可用 DWT->CYCCNT：`CoreDebug->DEMCR |= TRCENA`、`DWT->CYCCNT=0`、`DWT->CTRL |= 1`；170MHz 下 32 位计数器约 25s 溢出，两次采样间隔远小于此，用无符号差值安全）；② `Modules/Motor/motor_test.c`：`control_dt_s` 由 tick 差改为微秒差；③ `Modules/IMU/mpu6050.c` 的 `timestamp_ms` 可一并统一到同一时基 |
| 做法 | 新建 `Modules/De_Bug/timebase.c/.h`（或放在 debug 模块里）提供 `Timebase_Init()` / `Timebase_GetUs()`；在 `main()` 的 `USER CODE BEGIN 2` 里初始化 |
| 验证 | 串口/黑匣子打印实测 dt 与 tick 差对比；dt 抖动 <0.1ms |
| 验收 | dt 序列的标准差 <0.2ms |
| 风险 | 调试器 halt 时 DWT 可能停止（不影响正常飞行） |
| 回退 | 改回 tick 差 |
| 耗时 | 2 小时 |

### S1-6 I2C 超时与错误处理 [软件]

| 项 | 内容 |
|---|---|
| 目标 | 消除"单次 I2C 错误 → 飞行中整机重初始化"的炸机级风险 |
| 前置 | 无（可与 S1-3~S1-5 并行） |
| 改动点 | ① `Modules/IMU/mpu6050.h`：`MPU6050_I2C_TIMEOUT_MS` 20 → **2**；② `Modules/Motor/motor_test.c:207-214` 错误分支：单次错误 → 丢本拍 + `i2c_error_count++`；连续 ≥N 次（建议 10）才走上锁保护 |
| 做法 | 增加 `uint32_t i2c_fail_streak` 计数，成功清零；达到阈值才 `Motor_Disarm()` + 重新初始化 |
| 验证 | 正常飞行/台架无影响；人为制造 1 次读失败（可用调试器改返回值模拟）→ 应只丢一拍 |
| 验收 | 单次错误不影响解锁状态与油门；连续错误才保护 |
| 风险 | 超时设 2ms 太短可能在总线被拉长时误判（400kHz 下 14B 读约 0.4ms，余量充足） |
| 回退 | 超时改回 20ms；错误分支改回原样 |
| 耗时 | 1–2 小时 |

**阶段 1 出口条件**：dt 稳定 10ms、混控差速对称、I2C 单错无感。此时才可以进入校准阶段。

## 4. 阶段 2：P1 校准与数据质量（S2-1 ~ S2-5）

> 这一阶段的每一项都会改变"姿态测量输入"，所以**全部做完再整定 PID**。

### S2-1 加速度计六面法标定 [软件] + [台架]

| 项 | 内容 |
|---|---|
| 目标 | 消除加计零偏/尺度误差（静态姿态误差 1–2°） |
| 前置 | 阶段 1 完成 |
| 改动点 | 新增标定流程：建议在 `Modules/IMU/` 下新增 `imu_accel_cal.c/.h`；触发入口可用串口命令或遥控 PID 命令的保留操作码；结果存 Flash（见下方"存储位置"） |
| 做法 | 六面静置各采 200 拍，解算每轴零偏与尺度系数；存 Flash 后上电加载，在 `MPU6050_ReadData()` 之后、姿态解算之前应用 |
| 存储位置 | 现有布局：`0x000000/0x001000` PID 槽、`0x002000` 磁校准、`0x003000` 写指针、`0x004000` 起日志区。**建议**：与磁校准共用 `0x002000` 扇区（该扇区 4KB 只用了 128B），新增一条记录类型；注意扇区擦除是 4KB 粒度，**修改时要整扇区重写** |
| 验证 | 六面静置读数一致性（每面模长偏差 <0.5%，各轴零偏 <0.02g）；水平仪交叉验证 |
| 验收 | 标定后静态姿态误差 <0.5° |
| 风险 | 标定流程本身出错会引入更大误差 → 先台架验证再启用 |
| 回退 | 关闭标定应用（保留标定数据但不使用） |
| 耗时 | 半天（含台架六面操作） |

### S2-2 水平零点改造 [软件] + [台架]

| 项 | 内容 |
|---|---|
| 目标 | 消除"采集时不在真实水平 → 永久目标角偏置 → 单向漂移" |
| 前置 | S2-1（需要准确的加计重力方向） |
| 改动点 | `Modules/IMU/imu_level.c/.h`：由"静置 200 拍平均后相减"改为"用加计重力方向计算安装倾角"；结果**存 Flash**；采集时加准入条件 |
| 做法 | ① 准入条件：加计模长 0.98–1.02g、gyro 三轴 <0.5°/s、连续 100 拍倾角变化 <0.3°；② 计算：用重力向量与机体轴夹角得安装倾角，而不是用姿态解算输出平均；③ 上电从 Flash 加载，加载失败才重新采集并提示 |
| 验证 | ① 连续 5 次上电，零点一致性 <0.1°；② 台架用水平仪/水平尺交叉验证安装倾角；③ 故意把飞机放斜 3° 再上电，确认**不会**把 3° 当成零点 |
| 验收 | 零点可复现（多次上电一致）、可验证（与水平仪吻合）、且斜放不污染 |
| 风险 | 改动较大，若逻辑错误会导致姿态基准错乱 → 先台架充分验证再飞 |
| 回退 | 保留原"平均相减"逻辑作为编译开关 |
| 耗时 | 1 天 |

### S2-3 陀螺零偏采集改进 [软件] + [台架]

| 项 | 内容 |
|---|---|
| 目标 | 冷机起飞时零偏可靠 |

| 耗时 | 2–3 小时 |

### S2-4 陀螺量程改 ±500dps [软件] + [台架]

| 项 | 内容 |
|---|---|
| 目标 | 降低陀螺噪声、提高分辨率（噪声约降 4 倍） |
| 前置 | 阶段 1 完成（需要稳定的 dt 才能评估噪声改善） |

| 项 | 内容 |
|---|---|
| 目标 | 抑制电机振动进入重力修正；机动时不被错误重力拉偏 |

## 5. 阶段 3：PID 重新整定（S3-1 ~ S3-3）

> 前置：阶段 1（时序）+ 阶段 2（数据质量）全部完成。**不要提前整定，否则白调。**

### S3-1 台架整定（拆桨/系留）

| 轮次 | 目标 | 做法 | 验收 |
|---|---|---|---|
| ① 内环 P | 建立角速度阻尼 | 外环 Kp=0，只开 roll/pitch 内环 Kp，从 2.0 起逐步加到"轻拨快速衰减、无高频细抖" | 一次扰动 1–2 个摆动内停；无 5–15Hz 等幅抖动 |
| ② 内环 I（可选） | 消除稳态角速度误差 | 仅当松杆出现常值偏转时加 Ki 0.01–0.03 | 无 <2Hz 慢振荡 |
| ③ 外环 P | 建立角度刚度 | 外环 Kp 从 1.0 起（历史值 1.8 作参考），输出限幅（目标角速度）先设 100–120°/s | 手倾 20° 松手，1–2 次小幅超调内回到 ±1° |
| ④ 外环 I（可选） | 消除常值倾角偏差（抗风静差） | 小 Ki（0.005–0.01）+ 积分限幅降到输出限幅的 20–30% | 无低频呼吸式振荡 |
| ⑤ 偏航 | 先阻尼后航向 | 先 yaw_rate Kp（2–4），再 yaw_angle Kp（2–4，需磁力计已硬铁校准） | 机头不摆、松杆航向漂 <10°/30s |
| ⑥ 联动 | 综合验证 | 四路同油门（1100–1300us），手拨/拍击/轻推模拟扰动 12–15s | 修正连续、无方波抖振、无饱和骑墙 |

**每轮结束**：遥控 SAVE 到 Flash + 导出 `pid.csv` + 记黑匣子场次号 → 写进 `优化一下\调参记录.md`。

### S3-2 微风飞行验收（<2 级风）

| 检查项 | 标准 |
|---|---|
| 松杆姿态 | 95% 时间 ≤±3° |
| 高频抖振 | 无 5–15Hz 等幅细抖（黑匣子 rate 频谱） |
| 单向漂移 | 1 分钟内同方向漂移目测 <2m（或地速均值 <0.3m/s） |
| 打杆回中 | 2s 内回到 ±1°，往返摆动 ≤2 次 |
| 航向 | 松杆 30s 漂移 <10° |
| 链路 | 全程 connected=1，无失联 |

### S3-3 参数归档

- 导出并保存：`pid.csv`（场次头）、黑匣子场次 CSV、验收结论；
- 在 `优化一下\调参记录.md` 里记录：日期、场次号、六组参数、天气、现象、结论。

**阶段 3 出口条件**：微风下满足上述全部标准。此时才考虑 P2 增强。

## 6. 阶段 4：P2 算法增强（按风险从低到高）

> 每一项做完都要台架复验 + 必要时微调 PID（不需要从头整定）。

| 顺序 | 步骤 | 目标 | 改动点 | 验证 | 风险 | 耗时 |
|---|---|---|---|---|---|---|
| S4-1 | 内环旁路门禁 | 防止参数丢失时静默无阻尼 | `attitude_control.c`：内环未启用时拒绝解锁或告警 | 清空参数后解锁应被拒绝/报警 | 低 | 2 小时 |
| S4-2 | anti-windup + i_limit 调整 | 消除积分风车与过冲 | `pid.c`（饱和时冻结积分）、`pid_table.c`（i_limit 独立） | 长时间大偏差后无过冲 | 低 | 3 小时 |
| S4-3 | D 项改为对测量微分 + 低通 | 消除微分冲击、抑制噪声 | `pid.c` | 打杆无尖峰；Kd 可加大 | 中（需重调 Kd） | 半天 |
| S4-4 | 欧拉 → 中值积分 | 大角速度下姿态更准 | `imu_attitude.c` | 快速机动后姿态复现性提升 | 低 | 2 小时 |
| S4-5 | 目标角速率限制 | 打杆更顺 | `attitude_control.c` | 手感平滑、无冲击 | 低 | 2 小时 |
| S4-6 | 电压补偿 | 推力与电压解耦 | `motor_test.c` + `battery.c` | 电压下降时悬停点不变 | 中 | 半天 |
| S4-7 | 控制频率 250–500Hz | 质变：采样延迟降低、带宽提升 | `mpu6050.c`（DMA 读）、`mpu6050.h`、`motor_test.c`（周期）、`app_freertos.c`（优先级复核）、DRDY 中断 | dt 稳定 2–4ms；姿态噪声与响应改善 | **高（改动最大，PID 必须重整定）** | 2–3 天 |

> S4-7 建议单独作为一个"项目"来做，因为它会连带 I2C 驱动方式、中断、任务优先级、PID 全部重来。
