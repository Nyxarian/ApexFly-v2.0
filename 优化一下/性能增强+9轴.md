## 零、总览

### 0.1 为什么先做性能增强，再统一调参

**核心原则：调参要调在"最终的系统"上。**

| 改动 | 是否改变动力学 | 若放在调参之后 |
|---|---|---|
| #31 I2C DMA | 不改动力学，改 CPU 占用 | 影响小 |
| #32 EXTI 采样 | 改采样相位 | 影响小 |
| #10 DLPF 档位 | **改延迟** | 影响小（但会改噪声） |
| **#33 提频** | **改全部轴的动态特性** | **roll/pitch/yaw 必须全部重调** |
| 9 轴融合 | 只改 yaw | 只补调 yaw |

**结论**：#33 若放在 #30 之后，整定结果基本作废；放在之前则只需调一次。
所以顺序是：**先改系统 → 再统一调参**。

### 0.2 与环节总表的对应

| 本方案阶段 | 对应环节 | 说明 |
|---|---|---|
| 阶段 0 | 新增（前置闸门） | 磁力计数据质量评估，决定阶段 4 走哪条路 |
| 阶段 1 | **#31** | I2C DMA 读；承接原 #11（DRDY）、#12（读取原子性）的一部分 |
| 阶段 2 | **#32** | EXTI/DRDY 中断采样；承接 #11 |
| 阶段 3 | **#10 + #33** | DLPF 档位必须与提频同步改 |
| 阶段 4 | 9 轴融合（原 **#36** 的完整版） | 磁航向进姿态或进偏航环 |
| 阶段 5 | **#30** | 统一调参，一次到位 |
| 阶段 6 | **#34 / #35 / #36 剩余** | 调参之后的可选增强 |

### 0.3 总流程

```
阶段 0  磁力计数据质量评估          ← 闸门：不通过则阶段 4 降级
   ↓
阶段 1  #31 I2C DMA 读              ← 台架验证数据逐字节一致
   ↓
阶段 2  #32 EXTI/DRDY 中断采样       ← 台架验证每拍都是新样本
   ↓
阶段 3  #10 DLPF + #33 提频 250Hz    ← 台架验噪声/耗时，飞行验可飞
   ↓
阶段 4  9 轴融合（路线 a）            ⏭️ 【跳过】改按需
   ↓           替代 → 打开 yaw_rate / yaw_angle（路线 b），并入阶段 5
阶段 5  #30 统一调参                 ← 一次到位（轮 6 顺手把偏航两个功能上线）
   ↓
阶段 6  #34 电压补偿 / #35 输出平滑   ← 按需
```

### 0.4 三条铁律

1. **一步一验，不跳步**。每个阶段独立验证通过后才能进下一阶段；不允许"一次改四个再一起试"。
2. **每阶段都有回退路径**，且回退不需要重新设计（用宏切换或改回旧值）。
3. **阶段 0 不通过，阶段 4 降级**（见 0.5），但阶段 1~3、5 不受影响。

### 0.4.1 阶段 4 已决定跳过（2026-09-10）

阶段 0 实测通过后，评估结论是 **路线 (a) 9 轴融合不必要** —— 航向保持用路线 (b)
（磁航向进偏航角环，代码已存在）即可，零工程量、风险更低。

**详见第五节 5.0。** 阶段 4 改为"后续按需"。

> ⚠️ **注意：跳过 9 轴融合 ≠ 不用磁力计。** 磁力计仍然要用于偏航航向保持（路线 b）。

### 0.5 阶段 0 的分支决策

| 阶段 0 结果 | 阶段 4 走哪条路 |
|---|---|
| 静态噪声 < 2°、电流干扰偏移 < 3° | **路线 (a)**：9 轴 Mahony，磁力计进姿态融合 |
| 噪声大 / 电流干扰 > 3° | **路线 (b)**：保持 6 轴，磁航向只进偏航角环（现状路线，低风险） |
| 磁力计完全不可用 | 跳过阶段 4，yaw 只做速率阻尼（`调参.md` 轮 6a） |

## 一、阶段 0：磁力计数据质量评估（前置闸门）

### 1.1 目的

**这是整个方案里唯一可能推翻路线的环节。** HMC5883L 本身噪声约 ±2°，装在四轴上还要面对电机电流、电调、电池线产生的磁场。数据质量不行，无论走哪条路线都做不好。

**先花 0.5 小时测出来，比先写 200 行融合代码划算。**

### 1.2 前置条件

| 项 | 要求 |
|---|---|
| 供电 | **USB 供电即可，不需要电池**（前 3 项） |
| 串口 | USART3，115200-8N1 |
| 环境 | 远离铁磁物、大电流线、金属桌面 |
| 飞机状态 | 拆桨、静置 |

### 1.3 操作步骤

**第 1 步：硬铁校准**

```
串口输入：calmag start
缓慢绕三轴各转一圈以上（像转魔方，覆盖所有朝向）
串口输入：calmag status     ← 看三轴 span 是否足够
串口输入：calmag stop       ← 计算偏移并排队写 Flash
```

成功标志：
- `[MAG_CAL] done samples=... span=... offset=...`
- `[MAG_CAL] queued flash save at 0x002000`
- 断电重启后出现 `[MAG_CAL] flash loaded gen=N`

失败标志：`[MAG_CAL] rejected samples=... span=...; rotate farther on all 3 axes.` → 重转。

**第 2 步：静态噪声**

静置，看串口 `[MAG]` 打印的 `calhdg=` 字段（需要姿态调试任务，若没有可临时打开）。

| 指标 | 通过标准 |
|---|---|
| `calhdg` 波动 | **< 2°** |
| 采样计数 `ok` | 持续增长，无 `err` |

**第 3 步：转动连续性**

缓慢水平转动飞机（手拿着转一圈）。

| 指标 | 通过标准 |
|---|---|
| 航向变化 | 连续单调，**不跳变** |
| 回到原位 | 航向回到原值 ±2° |

**第 4 步：电流干扰（需要电池）**

| 条件 | 记录 |
|---|---|
| 电机不转 | `calhdg` = A |
| 电机中油门（拆桨）转 10 秒 | `calhdg` = B |
| 偏移量 | **\|B − A\| < 3°** |

> 这一条**最能说明 9 轴可行性**。偏移大说明磁力计离电机/电调太近，或者需要做"电机干扰补偿"（复杂度高，不建议）。

### 1.4 验收与分支

| 结果 | 分支 |
|---|---|
| 全部通过 | 阶段 4 走**路线 (a)** 9 轴 Mahony |
| 仅第 4 步不通过 | 阶段 4 走**路线 (b)** 磁航向只进偏航环（电流干扰时偏航环会受影响，但可加大倾角/门禁保护） |
| 第 2/3 步不通过 | 检查接线、安装位置；仍不行则**跳过阶段 4** |

### 1.5 实测结果（2026-09-10，已完成）

#### 硬件与标定

| 项 | 结果 | 判定 |
|---|---|---|
| 芯片 | **QMC5883P**（驱动自动识别，非 HMC5883L） | ✅ |
| 标度 | 1000 LSB/高斯（由 \|B\| 反推自洽） | ✅ |
| 地磁场 \|B_e\| | 0.495 高斯（由 span÷2 反推） | ✅ 正常 |
| 硬铁 offset | (−0.069, +0.119, +0.054)，\|offset\| = **0.148 高斯** | ⚠️ 偏大但可复现，标定已扣 |
| Flash | `gen=3`，重启后 `flash loaded gen=3` | ✅ |

#### 四个子测试

| 测试 | 实测 | 判定 |
|---|---|---|
| **T2 静态噪声** | **±0.3°**（门槛 2°） | ✅ **优秀** |
| **T3 转动连续性** | 陀螺转过 −351.5°，航向完整跟随；4343 拍中仅 1 次 32° 毛刺 | ✅ 通过 |
| **T4 电流干扰（空载）** | 油门 0→2000us→0 全程，航向仅 **±1.3°**（门槛 3°） | ✅ 空载通过 |
| T4 带载 | **未测**（带桨系留风险高） | ⏸️ 留到 #30 飞行看黑匣子 |

#### 映射（重要修正）

**旧映射 `mx=-x, my=y` 是错的**，实测后改为：

```c
*mx_gauss = -y_gauss;    /* 前 */
*my_gauss =  x_gauss;    /* 右 */
*mz_gauss =  z_gauss;    /* 下 */
```

实测依据（与机体朝向无关，只用地磁场方向）：
- 水平磁场完全落在芯片 −Y 上 → **芯片 −Y 指向正北**
- Z 读数为正的完整垂直分量 → **芯片 Z 指向正下**
- 结论：芯片电气轴 = **X→东、Y→南、Z→下**，与模块丝印标注差 180°

#### 关键教训（记下来）

| # | 教训 |
|---|---|
| 1 | **磁力计丝印不可信**，映射必须实测推导 |
| 2 | **换安装位置必须重做硬铁校准**，旧 Flash offset 立即作废 |
| 3 | **传感器要远离电池主回路**：原位置离总电流极近，低油门空载就偏 5.58°；挪开后全油门空载只偏 1.3° |
| 4 | **飞控串口每 5ms 才轮询一次接收**，长命令必须逐字节慢发（见 `工具/串口工具.html` 的"间隔 10ms/字节"） |
| 5 | 磁力计**未做倾角补偿**，做朝向测试时机体必须保持水平 |
| 6 | 测 `\|B\|` 是否恒定可判断环境干净程度（刚体在均匀场中旋转，`\|B\|` 必须不变） |

#### 遗留待办（不阻塞主线）

| 项 | 说明 |
|---|---|
| 软铁椭球拟合标定 | 当前硬铁标定后仍有 **7% 残留畸变**（软铁），会让航向有 ±5~10° 的朝向相关误差 |
| 绝对航向校验 | `chdg` 与 `bhdg` 差约 20°，**不影响偏航环**（环锁的是相对航向），等 GPS 可用时再校 |
| 带载电流干扰确认 | #30 飞行时导黑匣子看 `mag_hdg` 随 `thr` 的变化 |

#### 阶段 0 结论

> **路线 (a) 9 轴融合：条件性可行** ✅
>
> 磁力计硬件质量优秀、电流干扰（空载）已降到 1.3°、映射已确认。
> 唯一保留是带载干扰量级 —— 留到 #30 飞行验证。

## 二、阶段 1：#31 I2C DMA 读 —— ⏭️ 决定跳过（2026-09-10）

> **本阶段跳过。** 原目标"为 #33 提频腾出时间预算"改由 **I2C1 提到 400kHz** 承担。
>
> **为什么不靠 DMA**：DMA 只改变"谁在等"（CPU 忙等 → 任务阻塞在信号量上），
> **不改变 I2C 事务本身的墙钟延迟**。而当前的真实瓶颈是**总线速率**：
> `I2C1.Timing=0x40B285C2` 解码为约 **100kHz**（PRESC=4 → t_PRESC=29.41ns，SCLL=194、SCLH=133，
> SCL 周期 9.68µs），14 字节读按该速率约 **1.5ms**，占满 10ms 控制周期的 15%；
> 提到 250Hz（4ms）后就是 38%，必然超时。**只做 DMA 不修总线，提频照样做不成。**
>
> **替代方案**：`hi2c1.Init.Timing` 改为 `0x40621236`（CubeMX 官方值，Fast Mode 400kHz），
> 读耗时降到约 0.4ms，一次解决 CPU 占用与提频预算两个问题，且只改 1 个寄存器值、零结构性风险。
>
> **归属**：400kHz 作为 **#33 的前置步骤**执行（记为"轮 A"），不塞进 #32
> —— #32（DRDY 中断采样）与总线速率没有依赖关系。
>
> **#31 名下原承接项的去处**：#11（DRDY 中断）、#12（读取原子性）继续由 **#32** 承接。
> DMA 通路暂不实现；若将来 400kHz 仍不够（例如要上 500Hz），再回头评估。
>
> **以下 2.1~2.9 为原始方案，本次不执行，仅留档。**

### 2.1 目标

把 MPU6050 的 14 字节读取从**阻塞**改为 **DMA**，降低 CPU 占用，为阶段 3 提频腾出时间预算。

### 2.2 现状

| 项 | 现状 |
|---|---|
| 读取方式 | `HAL_I2C_Mem_Read()` 阻塞，超时 5ms |
| 数据量 | 14 字节 @ 400kHz ≈ 0.4ms |
| 占 10ms 周期 | 4% |
| 占 4ms 周期（提频后） | 10% |
| 占 2ms 周期（若提到 500Hz） | 20% |

### 2.3 前置条件

| 项 | 要求 |
|---|---|
| 阶段 | 阶段 0 完成（其实不依赖，但建议先做） |
| 固件基线 | #1~#29 已验证（提交 `d5c59ea`） |
| 工具 | 能对比改造前后的原始数据 |

### 2.4 改动点

| 文件 | 改动 |
|---|---|
| `Modules/IMU/mpu6050.c/.h` | 新增 DMA 读取路径：`HAL_I2C_Mem_Read_DMA()` + 静态缓冲区 + 完成通知 |
| `Core/Src/i2c.c` | 使能 I2C1 的 DMA 通道（CubeMX 配置） |
| `motor_test.c` | 调用点改为"DMA 启动 + 等待完成"或"读取上一拍结果" |
| `.ioc` | 配置 I2C1 TX DMA（若用 Mem_Read_DMA，走 TX 通道发地址 + RX 通道收数据） |

### 2.5 关键设计决策（实现时定）

| 方案 | 说明 | 延迟 | 复杂度 |
|---|---|---|---|
| **A. DMA + 等待完成** | 启动 DMA，阻塞在信号量上等完成 | 不变（仍 0.4ms） | 低 |
| **B. 流水线** | 本拍末尾启动下一拍读取，下一拍开头取结果 | 增加 1 拍 | 中 |
| **C. DRDY 驱动**（配合阶段 2） | 芯片有新数据 → 中断 → 启动 DMA → 控制拍开始时数据已就绪 | 最小 | 高 |

**建议**：阶段 1 先做 **A**（验证 DMA 通路正确），阶段 2 再升级到 **C**。

### 2.6 验证方法（台架，不需要电池）

| # | 方法 | 通过标准 |
|---|---|---|
| 1 | **静态逐字节对比**：改造前后各采 10 秒原始数据，对比 accel/gyro 的原始码值序列 | 统计特性一致（均值、方差、量级），无错位 |
| 2 | 转动飞机，看姿态角是否连续 | 无跳变、无卡顿 |
| 3 | 连续运行 10 分钟 | 无 I2C 错误累积、无数据冻结 |
| 4 | 测量控制环单拍耗时 | 比改造前**下降**（CPU 时间，不是墙钟） |

### 2.7 验收标准

- 原始数据统计特性与改造前一致；
- 无新增 I2C 错误；
- 控制周期稳定（`dt` 抖动不增大）。

### 2.8 回退

保留阻塞读代码路径，用编译宏 `MPU6050_USE_I2C_DMA` 切换，回退只需改宏。

### 2.9 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| DMA 与下一次请求冲突 | 数据错乱 → **姿态失控** | 单缓冲 + 完成标志，未完成不发新请求 |
| DMA 通道与其它外设冲突 | 传输失败 | 查 DMA 请求映射表，确认 I2C1_TX/RX 独占通道 |
| 缓存一致性 | 读到旧数据 | STM32G4 无 D-Cache，风险低；仍需 `volatile` + 内存屏障 |

## 三、阶段 2：#32 EXTI/DRDY 中断采样

### 3.1 目标

用 MPU6050 的 **Data-Ready 中断**驱动采样，保证每拍拿到的是**新样本**，且采样相位与芯片内部更新对齐。

### 3.2 现状

| 项 | 现状 |
|---|---|
| `IMU_INT` | PB0 / EXTI0 已配优先级 6 |
| `HAL_GPIO_EXTI_Callback()` | **明确忽略它**（`radio.c:344-353`） |
| 采样方式 | 靠 `osDelayUntil` 盲等，不检查 Data-Ready |
| 后果 | 可能读到与上一拍相同的样本（重复积分/重复控制），或跨更新边界读到"半新半旧"数据 |

### 3.3 前置条件

| 项 | 要求 |
|---|---|
| 阶段 | **不依赖阶段 1**（#31 DMA 已跳过）；建议先完成轮 A（400kHz），再进本阶段 |
| 硬件 | PB0 已接到 MPU6050 的 INT 脚（现有工程已配，需实测确认有脉冲） |

### 3.4 改动点

| 文件 | 改动 |
|---|---|
| `radio.c` 或新建 `imu_int.c` | EXTI0 回调 → 任务通知（`vTaskNotifyGiveFromISR`） |
| `motor_test.c` | 控制循环从 `osDelayUntil` 改为等待任务通知（带超时兜底） |
| `mpu6050.c` | 设置 `SMPLRT_DIV` 使 DRDY 频率 = 控制频率；读前检查 `INT_STATUS.DATA_RDY` |
| `mpu6050.h` | 新增 INT 使能配置 |

### 3.5 关键设计决策

**采样率对齐**：MPU6050 内部采样 1kHz（DLPF 决定），用 `SMPLRT_DIV` 分频：

| 控制频率 | SMPLRT_DIV | 实际 DRDY |
|---|---|---|
| 100Hz | 9 | 100Hz |
| **250Hz** | **3** | **250Hz** |
| 500Hz | 1 | 500Hz |

这样 **一次 DRDY = 一帧控制**，时序最干净。

> ⚠️ 注意：改 `SMPLRT_DIV` 会改变采样率，必须与阶段 3 的 DLPF 档位一起考虑（DLPF 的内部采样率必须是 1kHz 才能这么分频；98Hz 档和 188Hz 档都是 1kHz）。

### 3.6 验证方法（台架，不需要电池）

| # | 方法 | 通过标准 |
|---|---|---|
| 1 | 用示波器/逻辑分析仪看 PB0 | 有稳定脉冲，频率 = 预期 DRDY 频率 |
| 2 | 连续采样，统计 `sample_count` 与中断计数 | 两者一致（每拍一个新样本） |
| 3 | 控制周期实测 | 与 DRDY 周期一致，抖动 < 5% |
| 4 | 断开 INT 线 | 循环靠超时兜底继续跑，不卡死 |

### 3.7 验收标准

- 每拍都是新样本（无重复）；
- 控制周期由 DRDY 驱动，抖动显著小于盲等；
- INT 失效时有超时保护，不会死锁。

### 3.8 回退

用宏 `IMU_USE_DRDY_IRQ` 切回 `osDelayUntil` 盲等。

### 3.9 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 中断频率高（250~1000Hz） | CPU 占用、优先级反转 | 中断里只发通知，不做任何 I2C 操作 |
| INT 线噪声/悬空 | 误触发或丢失 | 硬件上拉 + 软件超时兜底 |
| 中断优先级与 I2C DMA 冲突 | 数据竞争 | 明确优先级：EXTI(6) > 任务；DMA 完成用任务通知 |

## 四、阶段 3：#10 DLPF 档位 + #33 控制频率提升

> **这两个必须一起改。** 只提频不改 DLPF，42Hz 滤波器会成为瓶颈；只改 DLPF 不提频，噪声上去了延迟没降多少。

### 4.1 目标

控制频率 100Hz → **250Hz**（先 250，不要一步到 500），同时把 DLPF 从 42Hz 提到 98Hz 或 188Hz。

### 4.2 前置条件

| 项 | 要求 |
|---|---|
| 阶段 | 阶段 2 完成（DRDY 在跑）+ **轮 A 完成（I2C1 已到 400kHz）** —— 后者是硬前置，替代原 #31 的腾预算作用 |
| 时间预算 | 实测控制环单拍耗时 **< 4ms 的 50%**（即 < 2ms），留足余量 |
| 基线 | 记录当前 100Hz 下的黑匣子数据，用于对比 |

### 4.3 改动点

| 文件 | 改动 | 说明 |
|---|---|---|
| `mpu6050.c` | `CONFIG` 寄存器：0x03 → 0x02（98Hz）或 0x01（188Hz） | 权衡噪声与延迟 |
| `mpu6050.c` | `SMPLRT_DIV` 按新频率设置 | 见 3.5 |
| `motor_test.c` | `IMU_SAMPLE_PERIOD_MS` 10 → **4** | 250Hz |
| `motor_test.c` | `IMU_DELTA_TIME_S` 0.01 → **0.004** | ⚠️ 别漏 |
| `motor_test.c` | `MOTOR_DT_MIN_S` / `MOTOR_DT_MAX_S` | ⚠️ **必须改**：现在是 [5ms, 30ms]，4ms 会被判为异常 |
| `motor_test.c` | 黑匣子采样分频 | ⚠️ 250Hz 写 Flash 快 2.5 倍，见 4.6 |
| `app_freertos.c` | 复核 `motorTestTask` 优先级与栈 | 高优先级 640 字，栈够 |
| `tim.c` | **不改**（TIM8 已 400Hz，独立于控制频率） | — |

### 4.4 DLPF 档位选择

| CONFIG | 陀螺 | 加计 | 延迟 | 评价 |
|---|---|---|---|---|
| 0x03（现状） | 42Hz | 44Hz | ~4.9ms | 延迟大，100Hz 勉强 |
| **0x02** | **98Hz** | **98Hz** | **~2.8ms** | **推荐起点**：延迟降 43%，噪声增幅可控 |
| 0x01 | 184Hz | 188Hz | ~1.9ms | 噪声明显上升，需先看 #17 加计低通是否够用 |

**建议**：先改 **0x02**，测噪声；可接受再考虑 0x01。

### 4.5 验证方法

**台架（不需要电池）**

| # | 方法 | 通过标准 |
|---|---|---|
| 1 | 静态 5 分钟，统计陀螺/加计噪声 | 噪声上升但在可接受范围（对比 100Hz/42Hz 基线） |
| 2 | 实测控制环单拍耗时 | < 2ms（4ms 周期的 50%） |
| 3 | 实测 dt 抖动 | 中位数 4.00ms，抖动 < 5% |
| 4 | 快速转动飞机，看姿态跟随 | 无明显滞后改善/恶化 |

**飞行（需要电池）**

| # | 方法 | 通过标准 |
|---|---|---|
| 5 | **用旧增益直接飞** | 能稳定悬停（提频后相位裕度更大，不应变差） |
| 6 | 黑匣子对比 | 姿态噪声、修正量的形状与 100Hz 基线相当或更好 |

> **关键**：提频后旧增益可以直接飞——因为提频只会**增大**相位裕度，不会减小。所以本阶段可以独立飞行验证，不需要先整定。

### 4.6 ⚠️ 黑匣子采样率的连带影响

`Blackbox_SubmitSample()` 在控制环里每拍调用。提到 250Hz 后：

| 项 | 100Hz | 250Hz |
|---|---|---|
| 写入速率 | 6.4 KB/s | **16 KB/s** |
| 8MB Flash 可记录时长 | ~21 分钟 | **~8.3 分钟** |

**对策（二选一）**：
- 接受更短的场次；
- 在控制环里加采样分频（如每 2 拍记一次 → 125Hz），保持记录时长。

**建议**：调参期间用 250Hz 全记（场次短但数据密）；调参完成后改为分频。

### 4.7 验收标准

- dt 稳定在 4ms，抖动 < 5%；
- 控制环单拍耗时 < 2ms；
- 旧增益下能稳定飞行；
- 黑匣子记录正常，无丢样（`drop=0`）。

### 4.8 回退

所有改动集中在一个提交里，`git revert` 即可回到 100Hz。**注意**：DLPF 和 `SMPLRT_DIV` 也要一起回退。

### 4.9 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 4ms 周期塞不下 | 任务超时、姿态卡顿 | 先实测耗时；不够就停在 100Hz 或降到 200Hz |
| `MOTOR_DT_MIN_S` 忘记改 | **dt 被钳到 5ms → 积分/微分全错** | 改动清单里列为必改项 |
| DLPF 改档后噪声变大 | 姿态抖 → 增益上不去 | 先 0x02；不行退回 0x03 并接受延迟 |
| 黑匣子写满变快 | 场次变短 | 见 4.6 |
| 磁力计任务（50Hz）与新频率不同步 | 航向数据更旧 | 阶段 4 一并处理 |
