# ApexFly V2.0 · 高度接入飞控系统 —— 研究方案

> 本文只做方案研究，**不含任何代码改动**。结合现有代码逐条推演，给出可选方案、取舍理由、量化依据与待拍板清单。
> 对应 `定高与油门专题.md` 的第一部分（现状）与第二部分（方案草案），这里是**细化到可实现、可验证**的版本。
> 记录日期：2026-09-11。前序文档：`优化一下/定高与油门专题.md`（第 18 节 = 高度显示已完成的现状）。

## 0. 先看结论

### 0.1 三个问题的直接回答

| 问题 | 回答 |
|---|---|
| **1. 怎么接入** | **增量式接入**：高度控制器输出的是"油门修正量（µs）"，叠加在一个**基准油门**上，而不是直接输出目标油门。基准油门由内环积分器自动学到（即悬停油门），因此**不需要新增协议参数**。 |
| **2. 串级怎么接** | 外环 `高度误差 → 目标垂速(cm/s)`，内环 `垂速误差 → 油门修正(µs)`，两者都在 250Hz 控制环里跑。**积分器只放内环**（它同时就是"悬停油门学习器"），外环 P 为主、D 默认关闭。 |
| **3. 代码放哪** | 新建两个模块：`Modules/Control/vertical_est.c/.h`（高度/垂速状态估计）与 `Modules/Control/vertical_control.c/.h`（模式状态机 + 双环 + 安全门禁）。`motor_test.c` 只负责"把油门来源从手动映射切到垂控输出"，不写控制律。 |

### 0.2 三个最重要的研究发现（先看这三条）

**① 垂速信号不能靠"高度差分"来凑，这是整个方案的技术核心。**

实测账（地面台架，`d` 抖动 66~73mm）：

- 原始噪声 ≈ ±1.75mm（1σ）；经 α=1/4 低通后 σ ≈ **0.66mm**；
- 相邻样本差分求垂速：σ_v ≈ 0.66mm×0.707 / 0.06s ≈ **0.8 cm/s**（1σ）→ 噪声本身**可接受**；
- ⚠️ 真正的问题不是噪声，是**滞后**——但必须先分清两条通道（2026-09-11 实测更正）：
  - **显示/遥测**通道走滤波值：低通 τ≈330ms + 测量与读取约 60ms ≈ **390ms**。数字稳但慢半拍，对人眼无所谓；
  - **控制/估计器**通道走原始值（H2 已定）：只剩"测量 20ms + 读到手的 42ms" ≈ **60ms**。
  - ⚠️ 本文早先写的"300ms 有效滞后、限制带宽到 0.5Hz"，是把这两条通道混在一起算的，**已更正**。
- 真正卡住"纯 ToF 差分"那条路的不是低通滞后，而是**原始值的噪声**：
  实测峰峰值 3~5mm，做相邻两拍差分（83ms）就是 **3.6~6 cm/s** 的垂速噪声。

**结论**：阶段 2 可以先用"纯 ToF + 差分"跑通闭环（增益必须刻意压低），但阶段 3 必须上**加速度计融合**，把高频响应交给加速度计、低频交给 ToF。好消息是——

**② `IMU_Attitude_VerticalAccelUp()` 已经存在**（`Modules/IMU/imu_attitude.h` 第 114 行），直接返回"向上为正的垂直线性加速度（m/s²）"，已经用四元数投影并扣掉重力。也就是说融合估计器的输入**已经现成**，不需要新增 IMU 接口。

**③ 协议、遥测、参数、黑匣子全都"已经预留好了"，阶段 1~2 可以做到零协议改动。**

| 已有资产 | 位置 | 现状 | 定高能不能直接用 |
|---|---|---|---|
| `altitude_cm` | 遥测 payload 偏移 6，int32，厘米 | ✅ 已用（高度显示） | 直接继续用 |
| `vertical_speed_cms` | 遥测，int16 | ⬜ 恒填 0 | 填估计器输出即可，**包长不变** |
| `flight_mode` | 控制帧 payload[9] 与遥测 payload[24]，各 1 字节 | 遥控端硬编码发常量 `1`，飞机端**原样回显**（`radio.c:240`） | ⭐ **现成的双向模式通道，零协议改动** |
| PID 参数 ID 25~28 | `vz_kp / vz_ki / vz_kd / hover_pwm_us` | 存在但没人用 | ⭐ 正好就是内环三增益，**不用新增 ID** |
| 黑匣子样本 | `altitude_cm / vz_cms / target_vz_cms / vz_correction_us / altitude_state` | 字段齐全。⚠️ 2026-09-15 起 `vz_correction_us`（快层）与 `vz_target_cms` **已由恒填 0 改成填真值**（H10 并入 H11）；`altitude_state` 自 H6 起就是真的。⚠️ **慢层的悬停油门估计值（`i`）在样本里没有对应字段**，只有串口 `[V]` 能看到 —— 要在飞行整定时用它得加一列（改 `BLACKBOX_RECORD_SCHEMA`） |

## 1. 现状盘点（动手前必须认全的事实）

### 1.1 现在的垂直轴是**纯开环**

```
油门杆 → 线性映射 → 速率限制 → throttle_us → 混控基础油门 → 四路电机
```

全程**没有任何反馈**。飞机悬停在哪，取决于"当前油门对应的推力"和"当前重量/电压/空气密度"是否刚好相等。

- 推力大于重量 → 一直上升；小于 → 一直下降。
- 那个"刚好"的点随电池电压下降、随气温、随载荷变化，所以**手动根本捏不住**，只能不停地修。
- 这不是"参数没调好"，是**结构上做不到**：开环没有误差可言，也就没有"修"的依据。

### 1.2 油门链路（代码级现状，`motor_test.c`）

| 步骤 | 代码 | 数值 |
|---|---|---|
| 摇杆映射 | `MotorTest_MapStickToThrottleUs()`（第 253 行） | 0~1000 → **1000~1600µs** 线性 |
| 速率限制 | `MotorTest_ThrottleRampLimit()`（第 188 行） | 上升 **800**、下降 **300** µs/s（不对称） |
| 姿态门禁 | 第 492 行 | `throttle_us <= 1100µs` 时**姿态环整个复位**、四路等值输出 |
| 姿态叠加 | `AttitudeControl_Update(throttle_us, ...)` | 在基础油门上叠加三轴修正，再进混控 |

⭐ 两个直接后果：

1. **`MOTOR_ATTITUDE_ENABLE_PWM_US = 1100µs` 是硬边界**：垂控输出一旦掉到 1100 以下，姿态环会被复位，然后再抬起来又要重收敛。所以**垂控输出必须钳在 1100 以上**，否则会触发"姿态环反复复位"的怪现象。
2. **速率限制器是有状态的**（`throttle_slew_us`），三处复位点与 `throttle_us = MOTOR_PWM_MIN_US` 成对出现。垂控接入后必须**再加一处复位**（退出定高时），否则会从残留值爬升。这是 `定高与油门专题.md` 1.5 节踩过的同类坑。

### 1.3 两个"名不副实"的东西，定高前必须先理顺

| 项 | 现状 | 为什么必须先解决 |
|---|---|---|
| **`hover_pwm_us` 参数** | 名字是"悬停油门"，实际被当成**满杆油门上限**（当前值 1600）在用（`pid_table.c:289`） | 定高真正需要的恰恰是"悬停需要多少油门"，而这个参数干的是"最高油门"的活。两者语义冲突 |
| **`target_vz_cms` 黑匣子列** | 名字是"目标垂速"，实际在记**磁航向**（`blackbox.h` 第 8 行有备注，CSV 列名 `mag_hdg`） | 定高一开始记录真值，这一列的语义就变了。**离线分析脚本 `bb_*.js` 是按磁航向读的**，改语义时必须同步改脚本，否则历史数据与新数据会串 |

**建议的处理顺序**：先做 1.3 的"正名/迁移"，再动高度环。理由见下面 6.3——这一步不做，定高做出来会和现有油门参数互相打架。

### 1.4 ToF 的能力边界（实测，来自第 18 节）

| 项 | 数值 | 对定高的影响 |
|---|---|---|
| 更新率 | **约 12Hz**（4 步 × 约 21ms 一轮；实测 `n=` 每 500ms +6） | 远低于 250Hz 控制环 → 必须靠估计器补 |
| **控制通道滞后** | ≈ **60ms**（测量 20ms + 读到手的 42ms），走 `distance_raw_mm` | ⭐ 估计器的真实输入延迟，**不是** 390ms |
| 显示通道滞后 | ≈ **390ms**（低通 τ≈330ms + 60ms），走 `distance_filtered_mm` | 只影响屏幕与遥测，**不影响控制** |
| 原始值噪声 | 峰峰值 **3~5mm**（个别 8~10mm） | 差分求垂速的主要误差来源 |
| 滤波后噪声 | 峰峰值 **0~1mm**（最大 2mm），约 3~4 倍降噪 | 显示用 |
| 噪声（台架） | 原始 ±1.75mm(1σ)，低通后 ±0.66mm | 可接受；**但飞行中振动/桨流/地面纹理未实测** |
| 量程 | 短距档 ≈ **1.3m** | 定高只能做"低空定高"，约 **≤1.2m** |
| 最小测距 | ≈ **4cm** | ⚠️ 放在平面上读数只有约 **8mm**（安装偏置），**低于最小测距** → **0~4cm 工作在规格外**；定高的最低可用高度约 4cm |
| 倾斜误差 | `d = h / cosθ` | 30° 时偏大 15% → **必须补 cosθ** |
| 失效表现 | `fresh=0`，保持上一次读数 | 必须能被上层识别并**主动退出定高** |

### 1.5 可以复用的现成件（不要重造）

| 现成件 | 位置 | 复用方式 |
|---|---|---|
| `IMU_Attitude_VerticalAccelUp()` | `imu_attitude.h:114` | ⭐ 垂直加速度，直接喂估计器 |
| `IMU_Attitude_GetQuaternion()` | `imu_attitude.h:134` | 需要 R33 做倾斜补偿时用（或直接用 roll/pitch 近似） |
| `CascadePid_t` / `Pid_t` | `cascade_pid.h` / `pid.h` | 双环直接复用同一份 PID 实现 |
| `CascadePid_SetInnerDeliveryScale()` | `cascade_pid.h:70` | ⭐ 现成的 anti-windup 通道：把"实际允许的油门余量比例"喂回去 |
| `ToF_GetAltitudeCm()` | `tof.h:68` | 控制环只读、不碰 I2C2 锁（现状已满足） |
| `PidTable` ID 25~28 | `pid_table.c` | 内环三增益 + 最高油门，**零协议改动** |
| 黑匣子 250Hz 记录 | `blackbox.c` | 调参全靠它；字段已齐全 |

### 1.6 姿态链路成熟度（定高可以照抄的部分）

姿态环已经验证过的做法，高度环应**逐条对齐**：

- DRDY 驱动的固定 250Hz、`dt` 实测（`MOTOR_DT_MIN_S/MAX_S` 6~12ms 合理性门限）；
- 串级结构：外环出"目标速率"、内环出"执行量（µs）"；
- 输出限幅 + 积分限幅**分离**（`PidParam_t` 里**没有** `i_limit`，由 `attitude_control.c` 按 `out_max` 比例推导，见 `attitude_control.h:41-47` 的说明）——高度环必须沿用这个约定；
- 解锁门禁：`AttitudeControl_IsInnerLoopEnabled()` 保证"参数丢了不带病起飞"——高度环将来也应有一句同类门禁。

## 2. 问题一：接入方案

### 2.1 三种接入形态对比

| 形态 | 做法 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| **A. 位置式** | 控制器直接输出"目标油门 µs"，完全接管 | 概念简单 | 进入/退出模式时油门会**跳变**；PID 要独自承担整机重量（积分器从 0 爬到悬停油门）；一旦传感器坏掉，油门来源整个断掉 | ❌ |
| **B. 增量式** | 输出"修正量 ∆µs"，叠加在基准油门上 | 传感器失效时**退回基准油门就能继续飞**；修正量小、限幅容易；进入/退出冲击小 | 需要一个基准油门 | ✅ **推荐** |
| **C. 全串级增量式** | B 的完整形态：高度→垂速→∆µs | 在 B 的基础上把"响应快慢"和"最终落点"分开管 | 参数多一组 | ✅ **推荐（就是 B 的落地形式）** |

### 2.2 推荐结构

```
                     ┌──────────── 手动通道（现在的逻辑，不动）────────────┐
摇杆 0~1000 ─────────┤ MapStickToThrottleUs → ThrottleRampLimit          ├─┐
                     └───────────────────────────────────────────────────┘ │
                                                                           │ 二选一
                     ┌──────────── 定高通道（新增）──────────────────────┐ │
摇杆中位/上下 ───────┤ 目标高度积分 → 外环P → 目标垂速 → 内环PI → ∆µs    ├─┤
                     └───────────────────────────────────────────────────┘ │
                                                                           ▼
                                              基础油门 throttle_us ──→ AttitudeControl_Update()
```

### 2.3 基准油门从哪来（三个候选，这是接入方案的关键决策）

| 候选 | 做法 | 评价 |
|---|---|---|
| 1. 参数给定 | 把 `hover_pwm_us` 正名成"悬停油门"，直接当基准 | 简单，但悬停油门随电池电压/载荷变，**写死的值迟早不准** |
| 2. **内环积分器自动学习** | 基准 = 积分器输出，稳态时它自动收敛到"当前重量所需的油门" | ⭐ **推荐**。零协议改动、自动适应电压下降、天然无扰切换 |
| 3. 电池电压补偿 | 用 `Battery_GetMillivolts()` 对基准做一阶补偿 | 可选增强；有 2 之后不是必需，但能减轻积分器在电压下降时的工作量 |

⭐ 选 2 的好处：**"悬停油门"这个一直打架的参数就不用新增了**——积分器就是悬停油门估计器。`hover_pwm_us` 继续当"最高油门"，语义不动，1.3 节的冲突自然消解一半（只剩名字难看，改名是纯 UI/文档问题）。

#### ✅ 2026-09-15（H10）：选 2 已落地，实际形态与本文原描述不同

**已实现**（`vertical_control.c`，v0.18）。但落地时发现**不能直接用 `Pid_t` 的内部积分**，
所以拆成了两个部件：

| 层 | 是什么 | 范围 | 由谁驱动 |
|---|---|---|---|
| **慢层** | 手写积分器 `vertical_throttle_base_us`（= 本节说的"悬停油门估计器"） | 1150 ~ 1650 | 协议参数 `vz_ki` |
| **快层** | 垂速内环 P（§3.4） | ±50 | 协议参数 `vz_kp` |
| **输出** | 慢层 + 快层，**再整体钳一次** | 1150 ~ 1650 | — |

⚠️ **为什么不能直接用 `Pid_t` 的内部积分**：`pid.c` 的积分钳位是**对称的**（±`i_limit`），
而 1150~1650 相对 0 **不对称**。硬套只能玩"把积分当偏移、中心挪到 1400"，可读性差、以后必被改错。
⇒ 因此传给 `Pid_ApplyParams` 的 `ki` **写死 0**，让 `pid.c` 的内部积分永不运行
（两个积分器同时跑会打架）。这一点在代码注释里写死了，**别当成笔误改掉**。

⚠️ **本节原写的"零协议改动"没有完全成立**：慢层确实没新增参数（复用 `vz_ki`），
但**满杆油门默认值由 1500 改成了 2000**（用户决定），遥控端该参数的编辑范围也从 1050~1700
对齐成 1200~2000。理由见 §3.4 末尾。

⚠️ 慢层初值取 **1250**（`VERTICAL_THROTTLE_START_US`）⇒ 刚进控制启用时油门不跳变；
不活跃（普通 / 停手 / 门禁②没过）时**慢层回初值**，不留残值。

### 2.4 无扰切换（bumpless transfer）—— ⭐ 2026-09-11 改版：大幅简化

**规则变了**：模式**只在地面上、且油门杆在最低位时才允许切换**（见 5.2）。而"杆在最低位"的含义就是**不加油门**（和普通模式把杆收到底完全一样）。所以：

| 场景 | 切换前后的油门状态 | 要做什么 |
|---|---|---|
| **主动切换**（飞行员在地面切模式） | 两边都是"不加油门" | ⭐ **什么都不用做**，天然无扰 |
| **自动退出**（读数失效等，**可能在空中发生**） | 控制器可能正输出一个大油门 | ⚠️ **必须处理**，见 6 节（做法**待讨论**） |

⇒ 原来那套"进入时记录当前油门、预置内环积分器初值、要求摇杆在中位"**全部不需要了**——因为切换那一刻油门本来就在最低。

**唯一还需要无扰处理的是「自动退出」**：

```
throttle_slew_us := 控制器当前输出油门
   → 否则手动通道会从残留的旧值开始爬（1.2 节那个坑）
```

⚠️ **操作提醒**：**如果最终采用"交还手动"**，自动退出后飞行员**要立刻接管油门**——因为油门会开始朝"杆位对应的值"走（此刻杆通常在中段，对应约 1300µs，比悬停油门低），飞机会往下掉。

✅ **2026-09-15（H12 / v0.19）结案：最终没有采用"交还手动"**，所以上面这条提醒**不适用**。
实际做法是"保持 2 秒 → 按 30µs/s 平缓降到 1000"（见 §6.1b），飞行员接管的手段是**上锁**。
⭐ **而且"退出必须无扰"这件事不需要写任何交接代码**：`motor_test.c` 的 `throttle_slew_us`
是文件级状态，**只在 `if (!armed)` 分支被重置**，所以在模式翻转时它仍然保持着控制器的最后输出，
下一拍限速器会从那里平滑过渡 —— 只要**别去碰它**就天然无扰（代码注释里已写明，防止后人加复位）。
（⚠️ 但这条**取决于 §15.1 的待讨论结论**：如果改成"自动降落"，这条提醒就换成"注意飞机会自己往下走，随时可以打杆接管"。）

> ⚠️ 用户对"自动退出"提出了不同的想法：**不要交还手动，而是直接执行自动降落程序**。
> 这比"交还手动"更符合直觉（飞行员措手不及地接管油门确实危险），但**有一个物理约束必须先说清**，
> 详见 6.2 节 ⭐ 与 **第 15 节「待讨论事项」**。

### 2.5 接入点（代码级）

改动**只有一处**，就是把 `motor_test.c` 里这一句的来源换掉：

```c
/* 现在（第 484 行） */
throttle_target_us = MotorTest_MapStickToThrottleUs(link.command.throttle);
```

## 3. 问题二：串级结构

### 3.1 为什么必须串级（不串级会怎样）

被控对象是**双积分**的：

```
油门 ∆µs ──(推力)──► 垂向加速度 ──积分──► 垂向速度 ──积分──► 高度
```

- **只用高度单环 P**：面对双积分对象，P 控制必然振荡（没有阻尼来源），只能把增益压到极低 → 慢到没用。
- **高度单环 PD**：D 项理论上提供阻尼，但高度信号要么**慢**要么**脏**——
  用滤波值是 390ms 前的速度去阻尼当前运动；用原始值则是把 3~5mm 峰峰的抖动微分放大成油门抖动。增益稍大就自激。
- **串级**：让内环用**更快的垂速信号**去提供阻尼，外环只负责"慢慢把高度拉到位"。这是把两个积分分别管起来的标准做法，也是姿态环已经验证过的结构。

### 3.2 两环接口定义

| | 外环（高度环） | 内环（垂速环） |
|---|---|---|
| **输入（设定）** | 目标高度 `h_sp`（cm）<br>⚠️ `h_sp` 由**杆的变化率积分**而来，见 5.1 | 目标垂速 `vz_sp`（cm/s） |
| **输入（测量）** | 估计高度 `h_est`（cm） | 估计垂速 `vz_est`（cm/s） |
| **输出** | `vz_sp`（cm/s） | `∆µs`（油门修正） |
| **增益单位** | Kp：1/s | Kp：µs/(cm/s)；Ki：µs/cm |
| **典型限幅** | ⚠️ **±20 cm/s**（抗扰动用，**比杆的速率上限大一个数量级**，见 3.3） | 动态，见 3.4 |
| **频率** | 250Hz（与内环同拍） | 250Hz |
| **D 项** | **默认关闭**（高度信号滞后大且噪声不低，D 没有意义） | 默认关闭或极小（噪声放大） |
| **I 项** | **无**（积分放在内环，见 3.5） | ✅ 有，且它就是悬停油门学习器 |

### 3.3 ⭐ 两个限幅不是一回事（容易搞混）

| 限幅 | 值 | 管什么 |
|---|---|---|
| **杆的速率上限**（5.1 节的三段映射） | **+3 / −2 cm/s** | 目标高度**"移动"的快慢**——飞行员想让高度变多快 |
| **外环输出限幅** | **±20 cm/s** | 允许以多快**消除高度误差**——抗扰动 |

⚠️ **外环输出限幅必须明显大于杆的速率上限**。否则：飞机被一阵风压下去 30cm，外环也只能要求 3cm/s，得爬 10 秒才回得来。

- **纯 P**：`vz_sp = clamp(Kp_h × (h_sp − h_est), −20, +20)`。
- Kp_h 的物理含义是"高度误差 10cm 时希望以多快的速度去修正"。
- **死区**：`|h_sp − h_est| ≤ 2cm` 时输出 0。
- **推杆爬升时的稳态滞后**：因为外环要"有误差才出命令"，所以按 +3cm/s 爬升时，实际高度会**落后移动的目标约 3/Kp_h**——这是正常的，不影响爬升速率。

#### ✅ 2026-09-15（H13 / v0.20）已实施 —— 但**增益与死区形式都和本文原写法不同**

**① 死区用"硬死区"**（`VerticalControl_OuterSetpoint()`）：界内不发力、界外按**满误差**算。
不是"界外再减掉 2cm"的连续死区 —— 后者平滑，但会留下一个**固定的系统偏差**
（稳定停在目标**下方 2cm**，因为要维持"误差 = 死区"才有输出）。
硬死区的代价只是边界上有个 `Kp_h × 死区` 的小台阶（0.3 × 2 = **0.6cm/s**，很小）。
**稳态精度就是死区宽度（±2cm）**，要更准得上 `h_ki`（ID 31 已预留，H15 的活）。

**② ⚠️⚠️ `Kp_h` 的默认值由 0.6 降到 0.3，而且首飞 `vz_kp` 要用 2 而不是 20。**
本节原写"取 0.6 → 10cm 误差 → 6cm/s，比较温和"——**那是延迟为 0 时的结论**。
真实回路延迟是消不掉的（ToF 一步 20ms、4 步一个测量周期 = **83ms**，再加差分垂速、
低通，以及限速器 ±50µs 满幅要走 125ms）：

```
悬停点附近 d(推力比)/du = 2/415 = 0.00482 /µs   ⇒ 修正量每变 1µs，向上加速度变 4.7 cm/s²
内环 corr = −Kp_v·vz 的闭环时间常数 = 1/(Kp_v × 4.7)
Kp_v = 20  ⇒ 11 ms，而回路延迟 80~150ms  ⇒ 比延迟快 8~15 倍 ⇒ 相位裕度必然为负
```

仿真（`sim_h13_takeoff.js`）确认：延迟 0 时 `20 / 0.6` 完全稳定；**延迟 60~80ms 时进入极限环**
（末段垂速 ±27cm/s）；扫 `vz_kp` 在 80ms 下只有 `2` 稳。
⇒ **首飞参数：`vz_kp = 2`、`h_kp = 0.3`**（都别用设计值/默认值）。
⇒ `pid_table.c` 的 `DEFAULT_H_KP` 已随之改成 0.3（默认值必须是"安全值"而不是"设计值"）。
⚠️ **真正该动的是 `vz` 的来源**（H16 加计融合），不是继续调增益。

**③ 外环用 `Pid_t`**（不是手写纯 P），所以 `h_ki / h_kd`（ID 31/32）都是**活的**。
⚠️ 注意 `pid.c` 的 D 是**对测量值求导**，这里测量值是 `h_est`，
所以 `h_kd` 实际相当于一个 `−h_kd × vz` 的速度反馈项 —— H15 开它时要记得这一层含义。

**④ ⭐ 外环接上之后，"定高模式能不能起飞"才第一次成为可能。**
本节没写这件事，但它是 H13 的直接后果：**悬停油门估计器只在该层有垂速误差时才学习**，
所以 H13 之前 `vz_sp ≡ 0` ⇒ 飞机在地面上 `vz = 0` ⇒ 误差 0 ⇒ 慢层不动 ⇒
油门停在初值 1250（悬停要 1450）⇒ **永远离不开地面**。
接上外环后：`h_sp` 有误差 ⇒ `vz_sp > 0` ⇒ 慢层开始学 ⇒ **推杆后约 7 秒离地**
（1.35s 退停手 + 约 5.7s 憋油门），离地后最大爬升 8.4cm/s、无过冲。
⚠️ 那 5.7 秒是"悬停油门必须自己学"的代价，**必须写进首飞流程**。

### 3.4 内环（垂速 → 油门修正）—— H9 实施 / **H10 重构为「两层 + 绝对区间」**

#### ✅ 现状（H10 / v0.18，以代码为准）

内环**不是一个 PID，而是两层之和**（落地说明见 §2.3）：

```
电脑给的油门 = 慢层（积分器 = 悬停油门估计器，钳 1150~1650，初值 1250，由 vz_ki 驱动）
             + 快层（垂速 P：∆µs = Kp_v × (vz_sp − vz_est)，钳 ±50，由 vz_kp 驱动）
             → 再整体钳到 [1150, 1650]
```

| 项 | 值 | 依据 |
|---|---|---|
| 慢层区间（= 定高模式的油门权限） | **1150 ~ 1650** | `VERTICAL_CONTROL_THROTTLE_MIN/MAX_US` |
| 快层限幅 | **±50µs** | `VERTICAL_INNER_CORR_LIMIT_US`，与 H14 首飞的"±50 起步"对齐 |
| 慢层初值 | 1250 | `VERTICAL_THROTTLE_START_US`，进控制那一刻不跳变 |
| `vz_sp` | **仍固定 0** | `VERTICAL_INNER_VZ_SP_CMS`，H13 才接外环 |

**地板 1150 的理由**：必须 > 混控有效下限 **1100**，否则会命中 `motor_test.c` 的
"四路等值 + `AttitudeControl_Reset()`"分支 ⇒ 飞机在空中**没有姿态修正**。留 50µs 余量。

**天花板 1650 的理由**：悬停估计 **1420**（据"1450 左右就能起飞"倒推）+ 230µs 余量；
且**刻意不跟 `max_throttle_us` 走** —— 那个参数同时是普通模式的满杆油门，
跟着它会让"调手动手感"意外改变定高行为。也不给更高：基础油门越接近物理上限 2000，
留给姿态差速的空间越小（混控在余量不足时统一缩放三轴修正，**被牺牲的永远是姿态**）。

⚠️⚠️ **积分与输出必须用同一把锁**（都是 [1150,1650]）。
只钳输出不钳积分 = **windup**：积分偷偷涨到几千而表面看不出来，表现成"长期顶在天花板"，
条件一变立刻猛冲。仿真里有一条**显式断言**：顶到天花板后反向 0.1s 内 `i` 必须立刻开始下降。

⚠️ **anti-windup 不需要额外接线**（更正 H9 的说法）：`pid.c` 的第 1 层 anti-windup
（条件积分）本来就在跑；第 2 层 `delivery_scale` 是给**混控缩放姿态修正**用的，
高度环的输出没有"被打折"这回事。⇒ H9 写的"推迟到 H10"**更正为"高度环不需要它"**。

⚠️ **满杆油门默认 1500 → 2000**（用户决定）：当年取 1500 是因为"1450 就能起飞、再高用不到"，
但 1000~1500 映射下**一格杆 = 0.5µs，而 TIM8 只分辨 1µs**（`motor.c` 文件头）⇒
那一半分辨率是花不出去的。改成 1000~2000 后一格杆 = 1µs，正好等于电调分辨率。
代价两条：悬停点从杆量 ~900 挪到 ~450；软启动 0.625s → 1.25s。

### 3.5 积分放哪一环（结论：放内环）

| 放外环（高度环带 I） | 放内环（垂速环带 I） |
|---|---|
| 积分器负责消除"高度稳态误差" | 积分器负责消除"速度稳态误差" = **自动收敛到悬停油门** |
| 仍然需要一个固定的基准油门 | 不需要任何固定基准油门 |
| 电压下降时积分器要爬很久 | 电压下降立刻表现为速度误差 → 积分器直接补上 |

**结论**：积分放内环。这样"悬停油门"不用标定、不用参数、自动适应电池电压，还顺便解决了 2.3 节的基准来源问题。

### 3.6 ⭐ 垂速信号从哪来（整个方案的技术核心）

#### 三个候选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **1. 高度差分 + 滤波** | `vz = (h[k] − h[k−1]) / T` + 低通 | 零新增代码、零新风险 | ⚠️ 差分噪声大（见下面的量化账）；要压噪声就得加重滤波，又换来滞后；增益必须压低、响应迟钝 |
| **2. 加速度计 + ToF 互补滤波** | 加速度积分出高频 h/v，ToF 低频修正 | 滞后降到 ~50ms、噪声被 ToF 长期锁住、**接口已现成** | 需要处理加计振动与零偏；多一个可调参数（交叉频率） |
| **3. 卡尔曼（h, v, 加计零偏）** | 三状态滤波器 | 能估计加计零偏、噪声最优 | 代码量与调参复杂度最高，收益相对方案 2 有限 |

#### 量化账（2026-09-11 实测更正）

以飞机静置时串口实测的**峰峰值**为准（H2 的验证数据）：

```
原始值        峰峰 3~5 mm（个别 8~10 mm），σ ≈ 1.0~1.7 mm
滤波值        峰峰 0~1 mm（最大 2 mm）        ← 约 3~4 倍降噪
相邻差分      4mm / 0.083s ≈ 48 mm/s = 4.8 cm/s   ← ⚠️ 这是"纯差分"路的噪声底
控制通道滞后  20ms(测量) + 42ms(读到手的延迟) ≈ 60 ms   ← 可接受
显示通道滞后  低通 τ≈330ms + 60ms ≈ 390 ms              ← 只影响屏幕
```

- **结论要改过来**：不是"滞后致命、噪声没事"，而是**反过来**——
  控制通道的滞后只有约 60ms（因为估计器吃原始值，不走低通），
  真正的障碍是**差分噪声约 4.8 cm/s**（对"最大爬升只有 +3cm/s"来说就是**比命令还大**，所以必须再滤，一滤就又回到滞后）。
- 所以"纯 ToF 差分"这条路的天花板很低：**它能跑通闭环、能验证链路和安全逻辑，但不要指望手感**。
- ⭐ **2026-09-15 实测更正（H9 实施前）**：上面那个 **4.8 cm/s 是"未滤波差分"的理论上界**，
  **不是 `vz_est` 的实际噪声**。从 5 份串口审计日志里量了 **592 个"停手 + 杆最低 + 读数有效"**的静置样本：

  | 量 | 实测 |
  |---|---|
  | `vz_est` 标准差 σ | **0.47 cm/s** |
  | 峰峰值 | **3.0 cm/s** |
  | p5~p95 宽度 | 1.6 cm/s |
  | 同时刻 `h` 的峰峰值 | 1.0 cm（读数 2.3~3.3cm） |

  ⇒ **估计器里那道垂速低通已经把它压下来约一个数量级**，真实噪声底比旧估计好得多。
  ⚠️ 这是**打印样本（500ms 间隔）**上的统计。之所以能代表控制环的输入：`vz_est` 只在 12Hz 有新数据、
  且已过一阶低通，500ms 采样足以反映**控制环实际吃到的抖动**，而不是被采样率掩盖掉的高频。
  ⭐ **这个数直接决定 H9 的 Kp 上限**：Kp = 100（参数表默认）时噪声就能推出 **±150µs**，远超 ±30 限幅，
  表现成"限幅长期顶死、真实误差被淹没"。要不因噪声长期顶限幅，Kp 必须 ≤ **约 20~60**
  （按 σ=0.47 算 ≤63、按峰峰半幅 1.5 算 ≤20）。
  ⇒ **H9 从 Kp = 20 起步**，用**遥控**改（不动代码默认值 100 —— 那是留给 H16 互补滤波之后的）。
- ⚠️ 上面全是**台架静置**数据。飞行中桨流、振动、地面纹理都会让 ToF 噪声明显变差，**这个数字还没在飞行中量过**。
  ⇒ 也正因为采样这么脏、而台架上飞机又不会真的动，**H9 台架能验的只有符号**，
    增益一定要首飞（H14，修正量限 ±50µs）才整定得了。

#### 推荐路线（分两步，不要一步到位）

```
阶段 2：方案 1（纯 ToF 差分），增益刻意压低，先跑通"能稳住"的闭环
        —— 验证链路、验证安全逻辑、拿到第一份飞行数据
阶段 3：升级到方案 2（互补滤波）
        —— 沿用同样的双环结构，只替换 vz_est 的来源，控制律一行不改
阶段 4（可选）：方案 3
```

⭐ 这个顺序的好处：**控制律与估计器解耦**。阶段 3 换估计器时不需要重新整定双环，风险可控。

#### 互补滤波的具体形式（阶段 3）

```
预测（250Hz，用加计）：
    a_up   = IMU_Attitude_VerticalAccelUp(&attitude, &imu_data)   // m/s²，向上为正
    vz_est += a_up × dt
    h_est  += vz_est × dt

修正（12Hz，收到新 ToF 时；靠 `valid_count` 变化触发，**不是每拍都做**）：
    err    = h_tof − h_est
    h_est += K_h × err
    vz_est += K_v × err / dt_tof     （或用标准互补形式，见下）
```

更稳的写法是按交叉频率 ω_c 取系数（ζ≈0.7）：

```
K_h = 2ζ·ω_c·dt          （dt = 250Hz 周期）
K_v = ω_c²·dt
```

ω_c 取 **0.5~1.0 rad/s** 起步（比 ToF 的 12Hz ≈ 75 rad/s 低约两个数量级，安全）。

⚠️ **必须注意的两件事**：

1. **喂给估计器的应该是 ToF 的"原始值"而不是低通值**。低通的 τ≈330ms 滞后会把估计器拖慢，而互补滤波自己就会对 ToF 通道做低通，前面再滤一遍属于重复。→ 这已由 H2 落地：`ToFSnapshot_t` 同时提供 `distance_raw_mm` 与 `distance_filtered_mm`。
2. **必须靠 `valid_count` 判断"是不是新数据"**。控制环 250Hz、ToF 只有 12Hz，如果每拍都对表一次，等于把距离通道的权重放大 **约 21 倍**，加速度计就白装了。详见第 13.3 节。
3. **加计零偏会让 h_est 慢慢漂**，靠 ToF 修正项拉回来；如果发现漂得明显，说明零偏超出互补滤波的纠正能力，那就得上方案 3（把零偏也当成状态估计）。

### 3.7 倾斜补偿（`h = d·cosθ`）

- 机身倾斜 θ 时，镜头测到的是 `d = h / cosθ`，**偏大**。
- 用现成的 `body.roll_deg / body.pitch_deg`：

```
h_vertical = d × cos(roll) × cos(pitch)
```

- 补偿量级：10° → 1.5%；20° → 6%；30° → 15%。**悬停 1m 时 30° 就是 15cm 误差**，所以做定高必须补。
- 补偿放在**估计器入口**（用 ToF 修正时对 `h_tof` 先做补偿），这样垂速和高度是同一套坐标。
- ⚠️ 大倾角本身就是"读数不可信"的信号（3.8 节的门槛），补偿只在小角度下有意义。

### 3.8 频率分配与滞后预算

| 环节 | 频率 | 滞后 |
|---|---|---|
| 加速度计 / 姿态 | 250Hz | ~4ms |
| 垂速估计器 | 250Hz | ~4ms（互补滤波后 ~50ms） |
| 内环（垂速→µs） | 250Hz | ~4ms |
| 外环（高度→垂速） | 250Hz | ~4ms |
| ToF 测量（原始值，控制用） | **12Hz** | 20ms 测量 + 42ms 读到手的延迟 ≈ **60ms** |
| ToF 低通（**仅显示用**） | — | τ ≈ **330ms** |

**滞后预算结论**：

- **控制通道的真实滞后只有约 60ms**（因为 H2 已定：估计器吃 `distance_raw_mm`，不走低通）。
  所以限制"纯 ToF 差分"的不是滞后，而是**差分噪声约 4.8 cm/s**——要压噪声就得加重滤波，一加重又把滞后换回来了。
- 走方案 1（纯 ToF 差分）：增益必须压低 → 外环 Kp_h ≤ 0.6、内环 Kp_v 很小，响应会明显迟钝（这是**预期行为**，不是 bug）。
  ✅ **2026-09-15（H13）把这句话量化了，而且结论比原写法更严**：内环那个"很小"到底多小，
  用相位裕度算得出来 —— `d(推力比)/du = 2/415` ⇒ 修正量每变 1µs 加速度变 4.7cm/s² ⇒
  内环 `corr = −Kp_v·vz` 的闭环时间常数 = `1/(Kp_v × 4.7)`。
  `Kp_v = 20`（H9 的设计值）时只有 **11ms**，比通道滞后快 8~15 倍 ⇒ **相位裕度必然为负**。
  仿真确认：延迟 0 稳、40ms 轻振荡、**80ms 明显振荡（末段垂速 ±27cm/s）**。
  ⇒ **首飞 `vz_kp = 2`（不是 20）、`h_kp = 0.3`（不是 0.6）**。
  ⚠️ 注意上表里"ToF 20ms 测量 + 42ms 延迟 ≈ 60ms"是**高度通道**的滞后；
  **垂速通道更差** —— 差分垂速要跨两个采样点，等效延迟约 **83ms**，
  再叠加低通与限速器（±50µs 满幅 125ms）⇒ 内环面对的是 **100ms 量级**的滞后。
- 走方案 2（互补滤波）：噪声交给 ToF 长期锁、高频交给加计 → 内外环都可以正常整定。
  ⭐ H13 的延迟结论把这一条的**优先级提高了**：H16 不只是"让波形好看"，
  它是"增益能不能加上去"的**前提**。

## 5. 摇杆与模式

### 5.1 摇杆语义（⭐ 2026-09-12 定稿：三段式）

**核心决定：定高是一个独立模式。** 切进这个模式后，油门杆**不再直通油门**，而是**三段式**。

**普通模式**（一字不改）：杆 0~1000 线性映射到基础油门 1000~1600µs。

**定高模式**：

| 段 | 杆位 | 名称 | 杆在说什么 | 目标高度变化率 |
|---|---|---|---|---|
| 1 | **0 ~ 350** | **下降** | 我要往下走 | **−2 → 0** cm/s（杆越低降得越快） |
| 2 | **350 ~ 650** | **保持** | 我不想动 | **0**（`h_sp` 冻结） |
| 3 | **650 ~ 1000** | **上升** | 我要往上走 | **0 → +3** cm/s（杆越高升得越快） |

段与段之间**速率连续**（在 350 和 650 处都是 0），边界不会抖。中段占 30% 行程，不回中的杆也停得稳。

⚠️ **满杆下拉 = 5cm/s 缓慢下降，不是停油门、更不是掉下来。** 这是取消"待命段"带来的**安全性提升**。

#### ⭐ 为什么取消了"待命段"（2026-09-12 改版）

原方案是四段式，最低的 0~100 叫"待命"（不加油门）。取消它，三条理由：

1. **它和"停手"重复了。** 地面上的正确行为是"什么都不做"，这件事已经有了更好的实现——**停手状态机**（见 5.4），它用**高度读数**判定，而不是杆位。用杆位兼职"地面判定"会在"被扰动压到地面、杆还在中位"时失效。
2. **它制造了"空中收杆就掉下来"这个人造风险。** 取消后最低位是 −5cm/s 缓降，飞行员慌乱中把杆收到底也不会失控。
3. **它让门禁和摇杆语义互相纠缠**（"切换要杆在待命段" vs "控制要杆不在待命段"），一个条件落在模式层、一个落在杆位层，读代码要来回翻。

**代价**：地面上"不推杆就不动"不再由杆位保证，改由**停手状态机**保证。所以停手逻辑的正确性变成关键——**H6 验"停手状态位 + `h_sp` 行为"，H8 验"地面不推杆时输出恒为 1000µs"**（油门接管之后才验得了）。

⚠️ **注意"停手"≠"上锁"**（用户已明确：**不做落地自动上锁**）：

| 状态 | 电机 | 高度控制 | 想再飞 | 误判代价 |
|---|---|---|---|---|
| **停手**（`h_est ≤ 门槛`） | **停转（1000µs）** | 关闭（内外环冻结） | 推杆约 1.3s 后即恢复 | 低空误判 → 停机落下，桨停转，落地无损伤，**还能再起飞** |
| **上锁**（人工决定） | 停转 | 关闭 | 必须先重新解锁 | 空中停车，**救不回来** |

⇒ 落地后**只停手、不自动上锁**：门槛贴着地面读数（不垫高约 1~2cm），拿这种低高度读数去触发"空中停车"，风险不成比例；而**停手已经能保证"飞机不会自己再飞"**。

**目标高度从哪来**（和俯仰环逐级对照）：

```
杆位 → 目标高度的"变化率"(cm/s) →（积分）→ 目标高度 h_sp
h_sp = clamp(h_sp, 0, 120)   // 厘米。上限留 1.3m 量程余量；
                             // ⭐ 下限是 0 而不是 2：地面 h_est≈0.8cm，
                             //    下限若高于它，外环会永远存在正误差，把飞机在地面上顶起来
```

⭐ **和俯仰环的唯一差别就在这一层积分**：俯仰环的杆**直接**给"目标角度"（外环设定值）；定高的杆给的是"目标高度的变化率"（外环设定值**之前**）。原因：高度无界，没法像角度那样一一映射到杆的行程上；而"杆=速度"能做到**中位就是 0、松手就稳住**。

**速率为什么取这么小（+3 / −2 cm/s）**：

- `vz_est` 静止噪声 σ≈0.5cm/s，**1~1.5cm/s 已接近噪声下限**，再小就分不清"命令"和"噪声"；
- 用户明确要"越慢越好"，3/2 是"很慢但还稳得住"的档位；
- 代价：地面爬到 50cm 要 17 秒，50cm 降下来要 25 秒，想调高度会等得久；
- ⭐ 先用**编译期常量**，多飞几次确认舒适区间后，再决定要不要做成可在线调的参数（那要动协议）。

⚠️ 必然后果：**推杆爬升时，外环误差会一直很大、输出一直顶在限幅上**——这是**正确**行为（等于"按你要求的速度爬"），不要误以为"积分饱和了"。

### 5.2 模式通道：`flight_mode`，零协议改动

遥控端现在硬编码发 `APP_RADIO_DEFAULT_FLIGHT_MODE = 1`（`App_Radio_Task.c:43`），飞机端原样回显（`radio.c:240`）。这个字节**两端都空着**，正好当模式通道。

**建议定义**（写进 `apex_protocol.h` 注释）：

| 值 | 含义 | 方向 |
|---|---|---|
| 0 | 手动 / 普通模式（油门杆直通油门） | 遥控→飞机：请求；飞机→遥控：**实际状态** |
| 1 | 定高模式（油门杆三段式） | 同上 |
| 2 | 自动起飞（预留） | 同上 |
| 3 | 自动降落（预留） | 同上 |
| 0x80 | 位标志：请求被拒绝 / 已自动退出 | 飞机→遥控 |

⭐ **关键设计**：飞机回显的必须是**实际生效的模式**，不是请求的模式。这样：

- 定高因为激光失效自动退出时，遥控器上会立刻看到模式变回去——**飞行员有明确反馈**；
- 不需要新增遥测标志位（`flags` 字节的 8 个位已经全部用满：ARMED/GPS_FIX/HOME_VALID/BLACKBOX/IMU_READY/MOTOR_READY/GPS_TIME/MAG_CAL）。

#### ⭐ 模式切换的条件（2026-09-12 定）

```
必须同时满足：① 已上锁   ② 油门杆在最低位（≤50）
```

- **已上锁**：唯一能 100% 保证"在地面上"的判据（上锁 = 电机停转），**不依赖高度读数**；
- **杆在最低位**：待命段取消后（见 5.1），这条退化成"杆在物理最低位"，含义仍是**"不加油门"**——和普通模式把杆收到底状态一致，所以切换天然无扰。
  阈值写成 **≤50** 而不是 ≤0，是为了容忍摇杆的机械与校准余量；H6 落地时定稿为常量。

⇒ **一次飞行只能用一个模式**，飞行中间不能切换。
⇒ 所以 **H14 首飞流程变了**：**起飞前就选定定高模式**，不能像原来计划的那样"飞到 0.5m 再开定高"。

#### ⚠️ 定点模式怎么接进来（**待讨论**）

用户的意思：定点大概也是"在遥控器上选模式"，但**具体怎么操作要重新讨论**，先**备注**在这里。

我的**暂定建议**（未确认）：

```
flight_mode 低 4 位 = 模式：0 = 普通，1 = 定高
flight_mode 的 bit4 = 定点开关（只在模式 1 下有效）
```

理由：**定点不改变油门语义**（它只管水平），所以**空中开关它是安全的**（最坏就是回到纯定高、开始慢慢漂）；而地面纹理变差时，飞行员需要能**立刻关掉**它。
规则上就是：**0↔1 必须地面切；定点位随时可切。**

详见 **第 15 节「待讨论事项」** 与 `光流定点施工顺序.md` 的 OF8。

### 5.3 门禁：⭐ 必须拆成两层（2026-09-11 改版）

**为什么要拆**：模式切换发生在**地面（上锁）**，而控制只在天上（解锁）才需要。
混成一层会自相矛盾——"要求已解锁才能切换" vs "切换必须在地面"。

**① 模式切换门禁**（决定"能不能切到这个模式"）：

| # | 条件 | 依据 |
|---|---|---|
| 1 | **已上锁** | ⭐ 唯一能 100% 保证"在地面上"的判据，**不依赖高度读数**（飞机静置时读数只有 8mm，用高度判不可靠） |
| 2 | **杆在最低位**（≤50） | 待命段取消后（5.1），这里退化成"杆在物理最低位"，含义仍是"不加油门"；且和普通模式"杆收到底"状态一致 → 切换天然无扰 |
| 3 | 高度估计可信（`VerticalEst.valid`） | 复用估计器那套 300ms 去抖的判据，比直接看 ToF 的 `fresh` 稳 |
| 4 | 高度 **≤ 120cm** | ⚠️ **下限已去掉**：因为要支持"在地面上切进定高"，而地面 `h_est≈0.8cm` |

**② 控制启用门禁**（决定"定高控制器要不要真的开始调油门"）：

| # | 条件 | 依据 |
|---|---|---|
| 1 | 已解锁 | 上锁时不控制 |
| 2 | 高度估计可信 | 同上 |
| 3 | 姿态平稳：`\|roll\|`、`\|pitch\|` < **25°** | cosθ 修正才有意义 |
| 4 | **不处于「停手」状态** | 停手时控制器不动作、油门压最低（见 5.4）。⭐ 这一条**取代了**原来那条"杆不在待命段" |

> ⚠️ 原来这里还有一条"输出油门 > 1100µs"，已**移出启用门禁**：它是**故障判据**（输出长期低于 1100 说明推不动），本来就属于 §6.1 的退出条件，而且**在停手期间豁免**——停手本来就要把油门压到 1000（见 5.4），不豁免必误退。

> 说明：门禁 ① 通过 = "模式是定高"；门禁 ② 通过 = "控制器真的在干活"。
> 两个状态要分别可观测（打印/遥测），否则出了问题分不清是"没切进模式"还是"切进去了但控制器没动"。

**运行中要退出的条件** → 见 6 节。⚠️ **退出的具体动作待讨论**（用户倾向于"自动降落"而不是"交还手动"）。

### 5.4 ⭐ 停手（地面待机）状态机 —— 2026-09-12 新增

**它解决什么问题**：取消"待命段"之后，"飞机在地面上时控制器该干什么"必须有明确定义，否则会出两个**确定性**故障：

| 若不定义停手 | 会发生什么 |
|---|---|
| 杆在最低位 → 速率 −2 → `h_sp` 钳到 **0**，而 `h_est ≈ 0.8cm` | 外环误差为**负** → 内环把油门往下压 → 输出掉到 1100 以下 → **命中 §6.1「输出<1100 持续>500ms」→ 定高在地面自己退出** |
| 地面 `h_sp` 若钳在下限 2cm（旧值） | 外环永远有 **+1.2cm** 正误差 → 油门被顶着往上加 → **飞机在地面上就想起飞** |

**规格**：

```
进入：h_est ≤ 6cm   ⚠️【台架测试值；撤垫块后按"实测读数 + 1~2cm"重定，**不要照抄 2cm** —— 见下面"门槛与地面读数绑死"】
      且 **本拍没有在命令爬升**（目标变化率 ≤ 0）
      且 **不在「起飞保护」期内**（见下）
      三条同时连续满足 ≥ 500ms
      动作：h_sp := 0            ← 归零，**不是**对齐到 h_est（理由见 §15.3 第四个坑）
            油门钳到 MOTOR_PWM_MIN_US（1000µs，电机停转）
            ⚠️ 不是 MOTOR_PWM_IDLE_US（1100µs）：停手是"什么都不做"，
               唯一语义一致的取值是普通模式杆收到底的那个值；1100 是"怠速、桨还在转"，
               与停手矛盾。旧文写 1100 是错的，2026-09-14 随 H8 更正。
            外环 P 冻结、内环 PID 冻结（积分值保持，不清零）
            ⚠️ 必须冻结：地面上 h_sp(0) < 地面读数，内环积分会往下灌死

维持：每拍  h_sp += rate × dt
            h_sp = clamp(h_sp, 0, 120)
      ★ 这一句不能省 —— 停手期间**照样要积分**：解手那一刻 h_sp 立刻就是外环的设定值，
        不积分的话它是个陈旧值，等于给外环一个凭空跳变的设定值。
        （2026-09-15 H14 之前它还有一个作用："唯一的出口"，那个出口已经改成杆量判据了。）

退出：⭐ **2026-09-15（H14）改成「已解锁 + 油门杆从低位推过 200」（边沿）**
      · 旧出口 `h_sp > 4cm` **已删除** —— 它要求把杆推到**上升段（>650）**并保持约 0.8 秒，
        而杆在下降段（0~350）和中间段（350~650）推得再多，油门恒 1000µs、**电机一点都不转**。
        飞行员要的是"推一点就转起来"，所以杆的位置本身就该是判据。
      · **必须是边沿**（上一拍杆 ≤ `VERTICAL_GROUND_STICK_LOW`=100、这一拍推过
        `VERTICAL_GROUND_EXIT_STICK`=200），不能只判电平：否则"锁着时先把杆推到 1000、
        再解锁"会在解锁那一拍直接解手给 1250µs。
      · 解手后油门仍**全程由控制器给**（1000 → 0.31s 到 1250 → 花 8~13 秒自己学悬停油门）。
        **本环节不做"手动起飞段"** —— 那是被否掉的另一条路。
      ⚠️ 为什么不能靠 `h_est`：停手把油门压到最低，飞机离不开地，`h_est` 永远涨不上去 ——
        会永久卡死在停手（见 §15.3 第一个坑）。旧方案说"退出必须用 `h_sp`"就是这个道理；
        换成杆量判据之后这个约束自然消失（杆是人给的，不依赖飞机是否离地）。

起飞保护：退出停手那一刻置位；`h_est > 10cm`（真的离地了）或 **`stick ≤ 100`（飞行员把杆收回来了）**
          时清除。置位期间**不许再进停手**。
          ⚠️ 不加它会出现"飞机永远起飞不了"的死循环（见 §15.3 第三个坑）。
          ⚠️ **清除条件必须用杆量**：旧版写的是"`rate < 0`（杆回到下降段）"，而**杆在下降段时
             `rate` 正好是负的** ⇒ 解手那一拍保护立刻失效 ⇒ 500ms 后又判回停手
             ⇒ 电机转一下停一下**来回抖**。这处是 H14 最容易写错的地方（有专门的仿真断言守着）。
          ⚠️ **上锁（`!armed`）时直接把保护清零**：上锁是"一次飞行"的硬边界。不清的话
             "解手后没飞起来 → 上锁 → 再解锁"会带着上一次的 `true` 出来 ⇒ 进不了停手
             ⇒ 解锁后门禁②直接全通、油门给 1250，**地面上电机转起来**。

豁免：停手期间不判 §6.1 的「输出 < 1100µs 持续 > 500ms」

不做：不自动上锁。上锁永远由人决定
```

**为什么进入要 500ms 去抖**：起飞擦地时 `h_est` 可能瞬时跌破 2cm。无去抖会出现"停手 ↔ 控制"的 1.5Hz 抖动（周期 = (4−2)/3 cm/s ≈ 0.67s）。

**为什么不定"杆必须在最低位"作为进入条件**：会漏掉"被气流或障碍物压到地面、而杆还停在中位"这种情况。进入判据用的是**高度读数 + "没有在命令爬升"**，而不是"杆在最低位"——杆在中位时变化率是 0，照样能进。

> ⭐ **2026-09-15（H14）补充**：改成"推杆解手"之后，这条决定**依然有效、而且更要坚持**。
> "落地就进停手"要求进入条件**不能**依赖杆量：若把"杆 ≤ 100"加进**进入条件**，
> 那么"杆停在中位（350~650）落地"就永远进不了停手 ⇒ **飞机已经在地上了、电机还在转**。
> 那"刚解手、杆还停在下降段，会不会 500ms 后又判回停手"由谁挡？由**起飞保护**挡着
> （它的清除条件改成了"杆 ≤ 100"）。⇒ 分工是「**进入看高度、滞回看杆量**」，两件事别混。

**为什么还要看"没在命令爬升"**（2026-09-12 写代码时用仿真发现，第二个坑）：飞机在地面上、飞行员推杆要起飞时，`h_est` 还是 0.8cm。只看高度的话，推杆 500ms 之后会被重新判成停手，把刚发出的爬升指令按回去。

**为什么还要"起飞保护"**（同一次仿真发现，第三个坑）：退出停手只说明"命令了爬升"，飞机此刻**还在地面上**（`h_est` 仍是地面读数）。不阻止重进的话就是：退出 → 500ms → 又被按回停手 → `h_sp` 被抹掉 → 油门压最低 → 飞行员再推杆……**电池电压低或载重大（推力偏弱、500ms 内离不了地）时必然发生，结果是飞机永远起飞不了。**

**⚠️ 进入门槛与"地面读数"绑死，是个已知的脆弱点**（2026-09-14 台架实测暴露，第四个坑）：
门槛必须**高于飞机静止在地面上时的读数**。实测：
**2026-09-14 不垫高约 1cm、垫高约 4cm；2026-09-15 同一台架实测 2.4~3.2cm（中位 2.8cm，2137 个样本）**
—— ⚠️ **两次"垫高"的读数不一样，说明这个数字跟垫块高度/镜头安装状态走，不能照抄**。
阈值写死成 2cm 时，在垫高的台架上永远不成立 —— 表现为 `st` 一直是 1（控制器在干活）、
`gt` 一直 0ms、停手一次都进不去。**台架上先用 6cm；撤掉垫块后按"实测读数 + 1~2cm"重定。**
详见 §15.3 第四个坑。

**进入门槛 2cm 低于 ToF 最小量程 4cm**，属于"用规格外读数触发"——**已接受**：地面读数是稳定的 8mm，只是不保证精度。
残余风险：空中读数若误跌到 2cm 以下，飞机会停手并落下——落点只有 2cm，无实质伤害，推杆即可恢复。

**退出停手后的行为**：内环从**冻结时保留的积分值**继续（那是悬停油门估计器，不能清零），外环从 `h_sp` 重新开始。
⚠️ **2026-09-15（H14）起"退出停手"本身不再需要等待**：旧版要等 `h_sp` 从 0 爬到 4cm
（杆在上升段时约 **1.3s**），现在**推杆过 200 就解手**（一拍之内）。
但 ⚠️ **离地之前"憋油门"的那 8~13 秒仍然存在** —— 那是"悬停油门必须自己学出来"的代价，
与出口条件无关（见 H13 的第 ③ 条与施工表的飞前清账）。

> ⚠️⚠️ **2026-09-15（H10）更正：上面这句被实现成了相反的做法，而且是刻意的。**

> 可能改成"**同一场内保留、模式切换/上锁时清零**"。届时改的是
> `vertical_control.c` 的 ⑨ 分支（不活跃时是否回初值），不是这里这句。

**与姿态环的一个交互（已核实代码）**：`motor_test.c` —— `MOTOR_ATTITUDE_ENABLE_PWM_US = MIXER_PWM_EFFECTIVE_MIN_US = 1100`，判据是 **`throttle_us <= 1100`**（**含等号**）。所以停手把油门设成 **1000** 时，**姿态环会被旁路、三轴修正量清零**。在地面上这正是想要的。

### 6.1b ✅ H12 已实施（v0.19）：本节的条件全部落地，但**做法不是"退出"**

> ⚠️⚠️ **如果只读一节，读这一节。** 上面那张表的"→ 退出"是 2026-09-11 的写法，
> 2026-09-15 实施时按用户的决定改成了 **"不退出、先把油门稳住再慢慢收"**。
> 起因是 **H10 真机实测暴露的 41/451 个样本（9% 的时间）处于"空中停车"**。

**三级台阶**（`vertical_control.c`）：

```
st=1 控制启用 ──门禁②失效──► st=6 失效保持（2 秒）
                                 · 油门**锁存**在失效前一刻的实际输出
                                 · 姿态环照常工作（thr 恒 > 1100 ⇒ 不被旁路 ⇒ **水平着地**）
                                 · 慢层/快层**冻结**（不积分、不 Pid_Reset）
                                 ├─ 门禁恢复 ──► 回 st=1（`i` 不丢、油门**零跳变**）
                                 └─ 2 秒未恢复 ──► st=7 失效下降
                                                    从锁存值按 **30µs/s** 降到 1000，
                                                    **单向不回头**，到底停住
```

**为什么不是"立刻退出、交还手动"**：飞行员接管的动作（切模式 / 收杆）**只在地面上允许**
（§5.2 的门禁①要求上锁 + 杆最低），空中"交还"等于"看着它掉"。
**为什么不是"立刻 1000"**（H8~H10 的行为）：那是空中停车，而且 1000 还会命中
`motor_test.c` 的 `thr <= 1100` 分支**旁路姿态环** ⇒ 飞机**翻滚着**砸下来。

| 项 | 取值 | 依据 |
|---|---|---|
| 保持时长 | **2000ms** | 用户定。ToF 的失效有相当一部分是瞬时的（反光地面、丢帧、`re-init`），它们本来什么都不用做。⭐ 保持段油门锁在悬停值 ⇒ **不增加落地速度**，只晚 2 秒落地 |
| 下降斜率 | **30µs/s** | `sim_failsafe_ramp.js` 的物理模型：从 1.0m 落地速度 **立刻停车 4.43 m/s → 30µs/s 的 1.86 m/s**（冲击能量降到 1/6）。取 20 只再降 0.22m/s，但"落地后桨还转"的时间多 7 秒，不划算。⚠️ 必须 ≤ 限速器 300µs/s，取 30 则限速器不参与 |
| 高度越界门槛 | 进入 **125cm** / 恢复 **115cm** | 与读数失效同一套。高度是连续量，进出用同一个门槛会在边界来回穿（`h_sp` 上限就是 120cm） |
| **姿态超限** | ⚠️ **不进保持段，直接 1000** | 用户定："姿态超 25° 一般就是撞上东西了，以现在的硬件基础很难找回，默认撞击炸机、不管了。" 逻辑上也站得住：保持段的用途是抓**瞬时**失效，而姿态歪着不是瞬时事件；若也走 2s+30µs/s，撞地之后桨还要转约 **16 秒** |

**⚠️ 一条必须记住的守卫：「没飞过就不许锁存」。**
地面上重新解锁而 ToF 还坏着时，停手判据要求 `est_valid` ⇒ **永远进不去停手** ⇒
`grounded` 恒 false ⇒ 若直接锁存，就会把油门在**地面上**顶到 ~1250µs，飞机自己窜出去。
判据用"**本次解锁后有没有真的飞过**"——**不能用高度**，高度正好在读数坏的时候不可用。
（这是 H12 自己引入的风险，必须和它一起记住。）

**结果**：`GetThrottleUs()` 只在三种情况下返回 1000 —— 未解锁、停手、以及"没飞过时的门禁不过"，
**三种都发生在地面上** ⇒ 待办 5 那条缺口结案。
⚠️ **仍未做**：真正的"自动降落/受控坠落"要等 **H16**（加速度计融合）才控得住下降速度，
所以现在用的是"开环降油门"，只能减小冲击、不能控制下降速率（见 §6.2 的物理约束）。

### 6.2 ⭐⭐ 失效之后怎么办 —— ✅ **2026-09-15 已定（原"待讨论"结案）**

**用户的决定**：读数失效时**不要交还手动**（"油门的数据不一定能够支撑飞机稳定"，
飞行员措手不及地接管油门确实危险）⇒ 改成 **"从前一阶段的有效油门开始，一点一点地下降至 1000"**，
即上面 §6.1b 的 **st=6 保持 2 秒 → st=7 按 30µs/s 平缓下降**。

> ⚠️ **物理约束（下面这段在实施后依然成立，只是从"路线选择"变成了"预期管理"）**：

**没有高度反馈时，"控制下降速度"是做不到的。**

- 推力 < 重力 → 飞机**持续加速下降**，不是匀速（气动阻力最终会平衡，但那是几米/秒量级）；
- 所以"按某个速率降油门"只能控制**下降的加速度**，控制不了**下降的速度**；
- 而且**不知道离地多高** → 不知道什么时候该停、该收多少油门 → 最后一定是"以某个速度撞地"。

⇒ 已实施的就是"**受控坠落**"，不是"降落"。**实测数字**（1.0m 起，`sim_failsafe_ramp.js`）：
**旧行为 4.43 m/s → 现在 1.86 m/s**；0.5m 起 **3.13 → 1.18 m/s**。
⭐ 比落地速度更重要的是**姿态环全程有效 ⇒ 水平着地**，以及**冲击能量降到 1/6**。

**三条路线里选了哪条**：

| 路线 | 做法 | 能不能真"控制下降速度" | 状态 |
|---|---|---|---|
| ~~A. 保持油门不变~~ | 冻结内环积分器和目标高度 | ❌ 不能，但慢漂而非加速下坠 | ⚠️ **没有采用**（用户要的是"降到 1000"而不是"一直悬着"）。但它的**前半段**被吸收了 —— 就是 st=6 的 2 秒保持 |
| **B. 开环降油门** | 按固定速率把油门往下调 | ❌ 不能（会加速下降） | ✅ **已实施**（30µs/s，见 §6.1b） |
| **C. 用加速度计做短时垂速反馈**<br>ToF 没了但 IMU 还活着，`IMU_Attitude_VerticalAccelUp()` 现成 | 降级成"惯性定高/惯性下降" | ✅ **能** | ⏳ **留作 H16 之后的可选升级** |

⚠️ **仍然待评估的一条**（不是缺陷，是取舍）：下降段**单向不回头** ——
一旦保持期满开始降，即使读数恢复也不再回定高。理由是"高度越界"会在 125cm 上下反复进出，
而"读数失效"恢复后油门要重新爬回悬停值，两件事都不好收尾。
⇒ 代价是"读数掉了 3 秒又回来"这种较长的抖动救不回来（2 秒以内可以）。
若实测发现这类抖动很常见，可以再评估给下降段加"恢复 + 去抖"。

### 6.3 ⚠️ 操作提醒（都要写进留档）

1. **一次飞行只能用一个模式**：0↔1 的切换必须在地面、上锁、杆在最低位（≤50）时做；
2. ⚠️ **失效之后定高不会自己回来**（见 §6.1b）：下降段是单向的，一次失效 = 一次飞行结束。
   **飞行员接管的手段是「上锁」**（立刻停桨），不是切模式、也不是打杆 ——
   失效期间 `mode` 仍保持 1，因为切回普通模式的话杆在中位就是 1500µs，飞机会往上窜；
3. ⭐ **在空中把杆收到最低位 = 以 5cm/s 缓慢下降**，不会掉下来、也不会停油门——这是取消待命段之后的**保护**，不是 bug；
4. ⭐ **2026-09-15（H14）起解手是"推杆过 200"，不再需要等**：旧版要等 `h_sp` 从 0 爬到 4cm（杆在上升段时约 1.3s）。⚠️ 但**从解手到离地仍要等 8~13 秒**（悬停油门得自己学出来），那一段才是"等"的大头；
5. **落地不会自动上锁**（用户已定）：飞机落地后停在停手状态、桨仍在怠速转，**上锁必须人工操作**。
   ⚠️ 失效下降落地后也是**一样**：从落地那一刻的油门降到 1000 还要十几秒，**这段时间桨仍在转**，
   所以"看到落地就上锁"是有意义的动作（这与你已有的习惯一致）；
6. ⭐ **硬规矩（H14 首飞流程里有）**：**装桨后必须先放地面、确认 `st=4 停手`，再解锁**。
   代码里**没有**强制这一点（`!armed` 分支不看高度）。

### 7.2 什么时候必须改协议

只有两种情况需要动 `apex_protocol.h`（版本 0x07 → 0x08，**遥控端必须同步升级**）：

1. 需要在**线调**外环增益与速率限幅（新增 ID 30~35）；
2. 需要新增遥测字段（例如"目标高度"给遥控器画指示）。

⭐ 阶段 1~2 **两者都不需要**。建议**先飞行验证定高是否可用**，确认有价值之后再花代价加调参通道——否则可能白改一版协议。

### 7.3 整定顺序与方法（地面台架 + 首飞）

**地面（桨叶装好但飞机固定住，或低油门不产生升力的台架条件）**：

1. 先只开**外环 P**、内环 Kp 极小、Ki=0：确认符号正确（抬手时修正量方向应让油门**减小**）。
2. 加内环 Kp：给一个小的目标垂速阶跃，看实际垂速是否跟得上、有没有振荡。
3. 最后加内环 Ki：消除稳态偏移，观察积分器收敛值 ≈ 悬停油门（这是**重要的交叉验证**：如果收敛到 1000 或 1600，说明符号或量纲有问题）。

⚠️ **2026-09-15（H13）改了两条**：
- 第 1 条里"内环 Kp 极小"的那个"极小"是 **5**（不是设计值 20）——
  理由见 §3.8 的量化结论；台架拆桨**验不出这一条**（没有真实推力回路），
  所以它只能靠保守起步 + 首飞观察。
- ⭐ 第 1 条现在**能在台架上真的闭环一次**：把飞机整体抬高 20cm 再放下，
  看 `vzsp` 是否立刻变负、`i` 是否跟着下降 —— 这是外环符号的第一次真实检查。

**首飞**（保守到激进）—— ⚠️ **2026-09-12 改版流程；2026-09-15 又按 H13 补了参数与等待时间**

因为模式切换要求"上锁 + 杆在最低位"，**半空中开不了定高**。所以首飞流程改成：

```
① 地面：上电 → 上锁 → 杆最低 → 切到定高模式
② ⚠️ 遥控里确认 4 个参数：vz_kp=2、h_kp=0.3、vz_ki=5、MAX THROTTLE=2000
   （⚠️ Flash 里可能存着旧值，LOAD_SAVED 会把 20/0.6/1500 带回来 —— 看显示值确认）
③ 解锁 → 杆仍在最低位 → 飞机进入「停手」→ 油门 1000µs，电机停转，不动
④ 推杆过 200 → **立刻解手**（`st=1`，电机转起来）。⚠️ 杆停在下降段/中间段也一样解手；
   再推到上升段，控制器开始把悬停油门学出来（8~13 秒后离地）
   → ⚠️⚠️ **此时飞机不会立刻动**：慢层要先"学会"悬停油门，约 **5.7 秒**后油门才够
   → 所以**推杆后总共约 7 秒才离地**，这不是故障
⑤ ⭐ **推杆把目标抬到 15~30cm 就立刻把杆回中段**（h_sp 会冻结在中段）
   ⚠️ 一直推着不松手的话 h_sp 会涨到 120cm 上限、飞机跟着一直往上爬（滞后 5cm）
⑥ 飞机自己平缓爬上去（最大约 8cm/s）→ 停在目标 ±2cm 内
⑦ 想降下来 → 杆拉到 0~350（最慢 2cm/s）；落地 → h_est ≤ 门槛 持续 0.5s → 自动进入停手
```

| 次 | 内容 | 目标 |
|---|---|---|
| 1 | **地面选定定高模式**，解锁后先确认停手；再用"上升段"把目标抬到 15~30cm 后回中段，**等约 7 秒**；修正量限幅极小（±50µs） | 确认不炸；⭐ 确认**停手行为正确**（地面上不推杆时输出恒为 1000µs、电机停转）；⭐ 确认**推杆后约 7 秒才离地是正常的** |
| 2 | 逐步放开限幅到 ±150µs | 确认能稳住、观察黑匣子 |
| 3 | 用黑匣子数据整定外环 Kp、内环 Kp/Ki —— ⚠️ **先加 `vz_kp`（5→10→…），再加 `h_kp`（0.3→…）**；一旦看到"高度在目标附近来回抽"就退回上一档 | 响应与稳定性 |
| 4 | 试"杆回中 = 松手稳住"、试推拉改变升降快慢 | 手感 |
| 5 | 故障注入：**举到 1.3m 以上**（⚠️ 不是"遮挡镜头"，那条不可靠） | 验证自动退出 |

⭐ **每飞一次都必须导黑匣子看波形再改参数**，不要凭感觉连改。

## 13. ToF 对外接口（H2 完成后的实际形态）

> 2026-09-11，对应施工顺序表 H2。这一节是 **H3 估计器的输入契约**，写估计器之前先看这里。

### 13.1 快照结构体多了什么

| 字段 | 类型 | 含义 | 给谁用 |
|---|---|---|---|
| `distance_filtered_mm` | `uint16_t` | **低通滤波后**的距离（原 `distance_mm` 改名） | 显示、遥测、黑匣子 |
| `distance_raw_mm` | `uint16_t` | **未滤波**的原始距离 | ⭐ 状态估计器 |
| `valid_count` | `uint32_t` | 每测到一次有效数据加一，单调递增（初始化/重初始化都不清零） | ⭐ 估计器判断"是不是新数据" |
| `altitude_cm` | `int32_t` | 由**滤波值**换算的厘米值（含义与来源都没变） | 控制环、遥测 |
| `fresh` | `bool` | 最近一次**测量是否有效**（注意：不等于"这一拍有没有新数据"） | 失效判断 |

`ToF_GetAltitudeCm()` 的行为与返回值**完全没变**，仍基于滤波值——所以遥控器与黑匣子的显示一字不动。

### 13.2 两条硬约定（改 ToF 模块时必须遵守）

**约定一：估计器只喂原始值，不喂滤波值。**

低通 α=1/4 在 12Hz 下时间常数是 **约 330ms**（4 拍）。这个滞后对显示是好事（数字才稳），喂给估计器就是把估计器一起拖慢；而互补滤波自己就会对距离通道做低通，前面再滤一遍属于重复。

**约定二：在 `tof.c` 里必须「先写 `distance_raw_mm` → 再更新滤波 → 最后自增 `valid_count`」。**

上层靠 `valid_count` 判断"有没有新数据"。按这个顺序写，只要计数器变了，`distance_raw_mm` 必然已经是这一条新数据，不会出现"计数器是新的、距离还是旧的"这种错配。

⚠️ 这个顺序是**人为约定，不是编译器保证的**。将来往这段里插别的写操作、或者把这三步拆到不同函数里，都可能破坏它。改这里要回头复查一次。

### 13.3 ⭐ 为什么非要那个计数器（H3 最容易踩的坑）

`fresh` 只表示"最近一次测量是否有效"，它在两次测量之间**一直是 true**。所以光看 `fresh`，上层分不清"刚测的新数据"和"83ms 前那一个"。

互补滤波的修正项**每来一条新数据只能应用一次**。控制环跑 250Hz、ToF 只有 12Hz，如果每拍都应用一次，等于把距离通道的权重大了 **约 21 倍**，加速度计就白装了——现象是"加速度计明明接进去了，响应却一点没变快"，很难查。

**正确用法**：

```
uint32_t c = snap.valid_count;
if (c != last_valid_count)
{
    last_valid_count = c;
    /* 用 snap.distance_raw_mm 做一次互补滤波修正 */
}
```

### 13.4 实测结果（H2 验证数据，2026-09-11）

飞机静置时串口实测（`[TOF]` 行，打印周期 500ms）：

| 项 | 实测值 |
|---|---|
| 有效测量率 | **12 次/秒**（`n=` 每 500ms 增加 6）——比原先假设的 16.7Hz 低，因为一轮实际占 **4 步**不是 3 步 |
| 原始值峰峰值 | 多在 **3~5mm**，个别到 8~10mm |
| 滤波值峰峰值 | 多在 **0~1mm**，最大 2mm → **约 3~4 倍降噪** |
| 测距状态 | 全程 `status=0`，无一次失效；最小测距（约 4cm）不构成风险 |
| 举高可见性 | 手举约 4cm：`raw` 70→111mm、`filt` 69→105mm，**`filt` 明显慢半拍**（滞后可见） |

慢的那个变化量反而更大（实测举高段出现过 `raw pp=9 / filt pp=11`），那是正常现象不是噪声。

### 13.6 已评估但决定不做：ToF 提速（12Hz → 约 16.7Hz）

**做法**：`TOF_WAIT_STEPS` 从 2 改成 1，并在 READ 步加"没测完就退回 WAIT 再等一拍"的自纠正轮询。一轮从 4 步降到 3 步，测量率 12Hz → 约 16.7Hz。

**评估结论：不做。** 三条理由：

1. **收益很小**：控制通道的滞后只有约 60ms，提速省下约 20ms。在互补滤波的交叉频率（ω_c = 0.5~1.0 rad/s）上，
   `ω_c × 0.02 ≈ 0.01 rad ≈ 0.6°` 相位——**没有任何可感知的区别**。
   （之前把"低通 330ms"算进控制通道，得出了"提速能省 110ms"的结论，那是错的：估计器吃原始值，不走低通。）
2. **有反作用**：采样变快会让"相邻两拍差分求垂速"的噪声变大——
   同样 4mm 抖动，除以 62ms 比除以 83ms 大 **34%**，对"纯 ToF 差分"那条路是负面的。
3. **成本不成比例**：一次改动就要一个编译 + 烧录 + 验证周期，外加轮询状态机的改动风险。

**什么时候值得回头做**：如果将来 H14 首飞发现定高响应迟钝到没法用。
但那时候正确的解法是**上加速度计融合（H16）**，而不是抠这 20ms——融合是把高频响应整个交给加速度计，量级完全不同。

## 14. 高度/垂速估计器（H3 完成后的实际形态）

> 2026-09-11，对应施工顺序表 H3。新增模块 `Modules/Control/vertical_est.c/.h`。

### 14.1 它在链路里的位置

```
tofTask（激光，约 12Hz）
     │ distance_raw_mm + valid_count
     ▼
VerticalEst_Update()        ← 只做估计，不产生任何控制量、不写电机
     │ height_cm / vz_cms / valid
     ▼
将来由定高控制器消费（H9 起）；本阶段只打印出来看
```

**H3 只造"眼睛"，不接"手"**：飞机行为一字未变。

### 14.2 算法与常量

```
来了新数据且可用：
    h_meas = 原始距离 ÷ 10                        （毫米 → 厘米）
    vz_raw = (h_meas − h_est) ÷ 距上次有效样本的秒数
    vz_est = vz_est + (vz_raw − vz_est) × 1/4     （一阶低通）
    h_est  = h_meas                               （零阶保持，不再加滤波）
读数不可用：h_est / vz_est 冻结不动，valid 置 false —— 不外推
```

| 常量 | 取值 | 理由 |
|---|---|---|
| `VERTICAL_EST_VZ_LPF_ALPHA` | **1/4** | 12Hz 下时间常数约 333ms；静止垂速噪声从约 2cm/s(1σ) 降到约 **0.4cm/s**。用户明确要"更稳"，所以取这一档（1/2 会到约 166ms／噪声约 0.7cm/s） |
| `VERTICAL_EST_MAX_AGE_S` | **0.300** | 约 3.6 个采样周期。**单次丢数据（约 83ms）不判失效**，连续丢三四次才判。H12 的安全退路复用同一个数值 |
| `VERTICAL_EST_MEAS_DT_MIN_S` | 0.020 | 差分时间分母的下限，防止两条数据挨太近时把噪声放大成巨大垂速 |
| `VERTICAL_EST_DT_MIN/MAX_S` | 0.005 / 0.100 | 单拍 dt 的合理区间，超出按标称 20ms 算，防任务被抢占后算出垃圾 |

**为什么 h_est 不再加一层滤波**：原始值峰峰只有 3~5mm（0.3~0.5cm），对"稳住高度"够用；再加一层只是白送滞后。真正的平滑归 H16 的融合。

**为什么靠 `valid_count` 而不是 `fresh`**：见第 13.3 节。若每拍拿同一个数据去差分，分子恒为 0，会算出假的 0 速度，而且噪声被反复平均掉，看起来"很稳"其实是假的。

#### ⭐ 有效性判据为什么要用"自己累加的计时"，而不是 ToF 的 `age_ms`

第一版写的是 `valid = primed && fresh && age_ms ≤ 300`，**仿真发现这样 valid 会短促抖动**：

- 单次读失败 → `fresh` 立刻变 false → valid 掉一下（约 83ms）→ 下一拍读成功又变 true。
- 上层的控制环会被这种抖动反复打断；而现实中激光偶发丢一拍是很常见的。

**改成**：本模块自己累加 `since_sample_s`（每拍 +dt，用掉一个样本就归零），

```
valid = primed && ready && (since_sample_s ≤ 0.300)
```

三个好处：

1. **单次丢数据不抖**（83ms < 300ms），连续丢三四次才判失效；
2. **不依赖 ToF 任务还活着**——`age_ms` 是 ToF 任务算的，任务万一被饿死它就停在旧值不动了；
   而 `since_sample_s` 照样往前走，能兜住"读数一直不刷新"这种情况（H5 搬进控制环后这条尤其重要）；
3. 阈值含义更直白：**"距上一次拿到可用数据多久了"**，而不是"ToF 自己觉得这个数多旧"。

### 14.2b 离线数值仿真结果（`sim_vertical_est.js`）

用实测噪声（σ=1.2mm）、实测节奏（20.8ms/步、约 83ms 一个样本）复刻算法跑出来的：

| 场景 | 结果 | 验收 |
|---|---|---|
| 静置 20 秒 | `vz_est` σ=**0.39cm/s**、峰峰 **2.39cm/s**；`h_est` σ=1.2mm、峰峰 8mm；valid 100% | ✅ <5cm/s、<3cm |
| 匀速 10cm/s 上升 → 下降 | 稳态 **+10.01 / −8.8~−10.2**；符号正确；h_est 与真值差 **0.06cm** | ✅ |
| 阶跃响应 | vz 到 63% 用时 **0.33s**，与理论 τ=4 拍完全吻合 | — |

### 14.3 挂在哪里：H3 挂 tofTask，**H4' 已搬进控制环**

**H3 当时选方案 A**（挂在 `tofTask`，约 12Hz）：打印现成、完全不碰控制环，风险最低。
代价是留了一笔债，H5 要来还。

**H4 把顺序改了。** 原因：倾斜补偿要用机体系姿态角 `body.roll_deg/pitch_deg`，
而**姿态角只有控制环算得出来，tofTask 根本没有**。按原顺序（H4 → H5）做，就得先造一条
"姿态发布通道"给 tofTask 用，而 H5 一搬家这条通道立刻变废码。

所以 **H4 和 H5 合并成 H4'**，一次做完：

| H5 搬进控制环 + 测耗时 | |

**搬迁的实际改法（已做）**：

1. `motor_test.c` 每拍调 `VerticalEst_Update(body.roll_deg, body.pitch_deg, control_dt_s)`；
   初始化时调 `VerticalEst_Init()`（和外层 IMU 重初始化同步）；
2. `tof.c` 删掉 `VerticalEst_Init()` / `Update()` / `Reset()` 三处调用；
3. ⭐ **打印不搬，仍然留在 `tof.c`**——"谁驱动"和"谁打印"是两件事：
   驱动在控制环（因为要姿态角），观察在低优先级任务（因为控制环禁止打印）。
   `tof.c` 不再拥有估计器，只是每 500ms 读一次它的状态打出来。

**顺带省掉一条耦合**：原来 `tof.c` 在 ToF 重新初始化时会调 `VerticalEst_Reset()`，
搬进控制环后这就成了跨任务 Reset（控制环在 Update）= 竞态。
改成**估计器自洽**：距上次样本超过 `VERTICAL_EST_RESTART_GAP_S`（0.5 秒）再收到数据，
就自动重新起步（`h` 直接贴新值、`vz` 归零、不做差分）。

这条同时修掉了 H3 日志里暴露的一个尖峰：

```

[TOF] raw=64mm ... | h=6.4cm vz=+14.9cm/s v=1 sc=3      ← ⚠️ 重初始化后 vz 飙到 +14.9
```

那 +14.9cm/s 就是"拿新读数去减旧高度"算出来的。**这种尖峰喂给控制环就是一次真实的油门猛冲**，
所以顺手修掉是有价值的，不是顺手改代码。

#### 验证结果（串口实测，飞机静置 + 手举升降）

| 验收项 | 实测 | 结论 |
|---|---|---|
| `vz` 抖动 | 静置段约 **−1.5 ~ +1.4 cm/s**（比仿真的 ±2.4 还小） | ✅ 远小于 ±5cm/s |
| `h` 稳定 | 同一平面上 0.8~1.0cm 之间 | ✅ |
| **匀速抬起符号** | `n=2391→2463`：h 从 21.9 爬到 41.2，`vz` 全程 **+1.0~+4.7**；随后下降段全程 **−0.2~−4.3** | ✅ **最关键的一条通过** |
| `sc` 与 `n` 同步 | 一直相差 1（第一个样本只用来起步） | ✅ |
| 读数失效 → `v=0` | `n=2961 fresh=0 age=421ms → v=0`，h/vz 冻结 | ✅ |

**H3 验收通过。**

#### 结论 1：⭐ 平坦平面的读数只有约 8mm，低于最小测距

镜头固定在**机架最下方**，所以飞机放在任何平面上，读数都是约 **8mm**（≈1cm），而不是之前以为的 2cm，更不是 65mm。

⚠️ 这条**推翻了本文早先几处的"安装偏置约 2cm"**，`tof.h/.c`、`vertical_est.h`、`blackbox.h` 的注释和 `定高与油门专题.md` 都已按 8mm 更正。

**连带影响（对将来定高很重要）：**

| 高度段 | 状态 |
|---|---|
| 0 ~ 4cm | **工作在规格外**（芯片仍给数、状态也报"完成"，但精度不保证） |
| 4cm ~ 1.3m | 规格内 |
| > 1.3m | 测不到 → 读数失效 → `v=0` |

→ **定高的最低可用高度大约就是 4cm**；**起飞的头 4cm 和降落的最后 4cm 都在规格外区**，
H18（自动起飞）/ H19（自动降落）的逻辑必须考虑这一点。

#### 结论 2：⭐ 「用手挡住镜头」不能作为失效判据，已从验收清单移除

实测发现：手挡在镜头前时，芯片**多数情况下报"测距完成"（`status=0`）、给出一个 17~30mm 的有效读数**，
只有偶尔才报失败。因为——

| 情况 | 镜头下方 | 传感器读到 |
|---|---|---|
| 飞机放在平面上 | 平面，约 8mm | 8mm |
| 手挡在镜头前 | 手，约 20mm | 20mm |

**这两件事在传感器眼里是同一件事**：下面 X 毫米处有个东西。它没有能力区分，我们也不该假装能区分。

所以：**不加"最小可信距离"门限**（曾提议 4cm，会直接把飞机放地面时的高度读数废掉）。
`v=0` 只在**传感器真的测不到**时触发（超量程 / 无反射 / 通信失败），验收改测这一条。

#### 结论 3：ToF 重新初始化是会发生的，且可能不只是"挡镜头"引起的

日志里出现过一次 `[TOF] too many misses, re-init.`（连续 10 次测不到，约 0.83 秒）。
重新初始化会把 `sc` 归零、h/vz 重新起步——**将来飞行中出现这情况，等于高度读数短暂归零**。
H12 的安全逻辑必须把"ToF 重新初始化"当成一次独立的失效事件，不能只看 `v`。
（另见 14.5 第 4 条：H5 之后要复查多上下文问题。）

**用户的意图**：不交还手动（飞行员措手不及地接管油门确实危险），而是**直接执行自动降落程序**。

| 约束 | 后果 |
|---|---|

| 不知道离地多高 ⇒ 不知道何时该停、该收多少油门 | 最后一定是"以某个速度触地" |

⇒ 所以能做到的是"**受控坠落**"，不是"降落"。**目标应该定成"以尽量小的垂直速度触地"**，这个期望要摆正。

**三条候选路线（已选 B）**：

| 路线 | 能真正控制下降速度吗 | 依赖 | 备注 |
|---|---|---|---|
| **A. 冻结内环积分器 + 什么都不动** | ❌（但是**慢漂**，不是加速下坠） | 无 | ⚠️ 未采用 —— 用户要的是"降到 1000"而不是"一直悬着"。但它的**前半段被吸收了**：`st=6` 的 2 秒保持就是"冻结 + 什么都不动" |
| **B. 开环按速率降油门** | ❌（会加速下降） | 无 | ✅ **已实施**（30µs/s）。⚠️ 当时写"不推荐"是因为担心"加速下降"，但物理模型算下来：**从 1m 落地速度 4.43 → 1.86 m/s、冲击能量降到 1/6**，而且**姿态环全程有效 ⇒ 水平着地** —— 比"立刻停车"好得多 |

      所以落地后桨还会转十几秒 —— **看到落地就上锁**能立刻结束它。
- [ ] ⏳ **遥控器怎么提示飞行员？** —— **部分做了**：飞控侧原因码已进遥测 `flight_mode` 的 bit5-6
      （`[V]` 里是 `fr=`），但**遥控端解析 + 弹窗按用户要求缓做**。
      ⇒ 现在飞行员只能从"模式没变、飞机自己往下走"察觉；**将来加弹窗只改遥控端，飞控不用再烧**。
- [x] **飞行员随时接管的手势是什么？** ⇒ **上锁**。⚠️ 不是打杆、也不是切模式：
      ① 打杆没用（失效期间杆不再影响油门）；② 切模式在空中本来就禁止（§5.2 门禁①要求上锁 + 杆最低）。
      ⚠️ 后果要说清：**失效之后这次飞行的定高就结束了**，救不回来（这是取舍，见 §6.2 末尾）。

### 15.2 定点模式的开关形态

### 15.3 ⭐ 停手的四个坑与结论（**已定**，仅作教训留档）

> 2026-09-12。这一节不是待讨论项，是**已经踩过的坑**，写下来防复发。

**第一版（我提的，错的）**：退出条件用 **`h_est > 4cm`**。

| | |
|---|---|
| 逻辑 | 停手时若高度涨过 4cm，说明飞机已经离地 → 退出停手 |
| 死锁 | ⚠️ **停手会把油门压到最低（1000µs，电机停转）**，所以飞机**永远离不开地** → `h_est` 永远停在 0.8cm → **永久卡在停手，推杆也起不来** |
| 谁发现的 | 用户 |

**根因**：停手期间被冻结/钳死的是**油门**，而 `h_est` 是**油门的后果**。用一个"被自己掐死的量"当出口，必然死锁。

**第二版（现方案）**：退出条件用 **`h_sp > 4cm`**。

| | |
|---|---|
| 为什么对 | `h_sp` 是**摇杆积分的产物**，它**不依赖飞机是否真的动了** —— 停手期间它是唯一还会变的东西（见 5.4 的"维持"那一句） |
| 语义 | "飞行员发出了爬升指令" 是停手唯一合理的出口，而不是"飞机真的起来了" |

**第三版：H6 写完之后，在 PC 上跑状态机仿真又抓到两个坑（同一个根因的两面）**

第二版解决了"卡死"，但**没解决"退出之后立刻又被抓回去"**。仿真跑到第 5、6、8 个场景才暴露：

| 项 | 内容 |
|---|---|
| 现象 | 退出停手只说明"命令了爬升"，飞机**此刻还在地面上**（`h_est` 仍是 0.8cm）→ 退出 → 500ms 去抖一满 → 又被判成停手 → `h_sp` 被抹成 0.8、油门压最低 → **飞机永远起飞不了** |
| 触发条件 | 电池电压低、载重大，也就是"**推力偏弱、500ms 内离不了 2cm**"——正是最需要它起飞的时候 |
| 修法 1 | 进入条件加"**本拍没有在命令爬升**"（`rate ≤ 0`）：杆在上升段时不进停手 |
| 修法 2 | 加"**起飞保护**"：退出停手后直到"真的离地（`h_est > 10cm`）"或"飞行员放弃（`rate < 0`）"之前，禁止重进 |
| 为什么两条都要 | 修法 1 只管住"杆在上升段"；飞行员把杆放到**保持段**（`rate = 0`）时它就不管用了，而那时飞机同样还在地面上 |

⭐ 这两个坑**只在台架仿真里花了十分钟就抓出来了，代价是零**。如果等首飞才发现，就是一次"怎么推都不起来"的迷惑现场。

**第四版：2026-09-14 台架实测暴露"门槛与地面读数绑死"**

H6 烧进去第一次跑，日志显示 `st` 一直是 1、`gt` 一直 0ms——**停手一次都没进去**。

| 项 | 内容 |
|---|---|
| 现象 | 台架把飞机**垫高**了，地面读数从约 1cm 变成约 **4cm**，而门槛写死是 **2cm** → 进入条件永远不成立 |
| 后果 | ⚠️ H6 阶段无害（修正量恒 0、飞机行为不变），但 **H8 一接管油门就会在地面自己退出定高**：地面上 `h_sp=0` 对 `h_est=4cm` → 外环要求下降 → 内环把油门压到 1100µs 以下 → 命中「输出<1100 持续>500ms」 |
| 顺带暴露 | 地面上 ToF 已经贴着**最小量程 4cm**，读数在 12~47mm 之间跳——本来就工作在规格外区间 |
| 修法 1 | 台架门槛改成 **6cm**（⚠️ **测试值**，恢复不垫高后改回 **2cm**） |
| 修法 2 | ⭐ 进入停手时 **`h_sp := 0`**，**不再**对齐到 `h_est`。因为地面读数本来就不小（1~4cm），对齐出来的 `h_sp` 只要超过退出门槛 4cm，下一拍就立刻满足退出 → **进入/退出 2Hz 抖动** |

**由此得到的四条通用规则**（以后写任何状态机都要套）：

1. **出口判据不能用"被本状态掐死的量"**——先问一句"这个量在我卡住的时候还能不能变"；
2. **进入时要决定设定值放哪，而且要想清楚"它会不会已经满足退出门槛"**。
   对齐到当前值（`h_sp := h_est`）看起来最"无扰"，但只要"当前值"可能高于退出门槛，
   就会变成"进入即退出"。这里最终选择**归零**——退出的无扰性由退出门槛本身保证
   （退出时 `h_sp≈4cm`、`h_est≈地面读数`，外环误差仍然接近 0），不需要靠对齐；
3. ⭐ **退出之后要想清楚"会不会立刻又满足进入条件"**——出口和入口必须构成迟滞，
   不能出现"退出 → 满足进入 → 退出"的环。这里的做法是给退出加一个带清除条件的**保护期**；
4. ⭐ **和"绝对物理量"绑定的门槛，必须拿实测值去核对**。
   文档里"地面约 1cm"没错，但换成垫高的台架就失效了。门槛写死之前先问一句
   "这个量的实测范围是多少、会不会换场景"。

**顺带确认的两个设计点**：

- **进入门槛与退出门槛之间是迟滞带**。⚠️ 注意进入门槛是**按地面读数定的**（不垫高约 2cm、垫高台架现用 6cm），
  退出门槛是 `h_sp > 4cm`（**相对量**，`h_sp` 进停手时归零），两者不在同一个坐标系里，别拿它们直接相减。
  若不做 500ms 去抖，起飞擦地会出现约 1.5Hz 抖动（周期 = 4/3 ≈ 1.3s）；
- **不要求"杆在最低位"作为进入条件**——否则"被扰动压到地面、杆还在中位"这种情况会漏掉，飞机在地面上却仍在跑控制环。
  注意这里用的是"**没有在命令爬升**"（`rate ≤ 0`），不是"杆在最低位"：杆在中位时变化率是 0，照样能进。
