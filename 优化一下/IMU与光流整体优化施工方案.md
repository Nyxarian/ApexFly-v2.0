## 0. 使用规则

本方案按阶段执行。每次只做一个阶段：

```text
读方案 → AI 出本阶段具体改动 → 用户批准 → AI 改代码 → 用户编译烧录 → 用户真机验证 → 通过后再进入下一阶段
```

硬件动作由用户完成。AI 不烧录、不擦除、不探测目标板、不占用串口，也不把未验证结果写成已验证。

当前工作区已有 OF15 相关未提交改动。本方案默认先保留这些改动，不把 IMU/光流优化与 OF15 混成一个无法回退的大改动。

## 1. 当前问题和结论

### 1.1 IMU 水平基准问题

当前启动流程大致是：

```text
陀螺仪零偏采样
→ 姿态解算
→ 静止采集 200 次 roll/pitch
→ 把平均 roll/pitch 减掉
→ 当前停放姿态变成软件的 0°
```

涉及文件：

- `ApexFly v2.0/Modules/Motor/motor_test.c`
- `ApexFly v2.0/Modules/IMU/imu_level.c`
- `ApexFly v2.0/Modules/IMU/imu_level.h`
- `ApexFly v2.0/Modules/IMU/imu_attitude.c`
- `ApexFly v2.0/Modules/IMU/imu_attitude.h`

这不是完整的加速度计校准，也不是固定安装角校准，而是“每次上电动态水平清零”。地面不平时会把地面坡度写入姿态零点，起飞后产生固定方向的水平推力和漂移。

### 1.2 加速度计校准缺口

当前没有正式的六面或多姿态加速度计校准，尚未保存：

- 三轴加速度计 bias；
- 三轴比例误差；
- 轴间不正交误差；
- 温度相关修正。

当前的加速度模长归一化和 Mahony 重力修正不能代替这些校准。

### 1.3 光流测量层现状

OF1~OF5 的串口、帧解析、质量门禁、250 帧零点标定、遮挡冻结和方向测试已有真机证据。当前主要风险在光流进入控制后的物理模型：

- 光流约 25Hz，位置环约 12.5Hz；
- 输出有 2.5Hz 低通，闭环响应有延迟；
- 当前没有高度补偿；
- 当前没有完整的陀螺旋转补偿；
- 使用计数单位，控制增益依赖测试高度；
- 当前定点修正只叠加到普通模式，定高模式暂不叠加；
- 地面纹理、光照、反光和 ToF 高度质量会直接影响结果。

### 1.4 总体判断

目前不能把“定点效果不好”直接归结为光流协议错误。更可能是：

```text
IMU 水平基准错误
＋光流高度/旋转模型不完整
＋光流链路延迟
＋定点参数尚未经过飞行整定
```

必须先修 IMU 基准，再验证基础姿态，最后重新整定定点。

## 2. 总体目标

### 2.1 目标

1. 地面坡度不再被当作 IMU 水平基准。
2. 陀螺仪零偏、加速度计误差、飞控安装角分别处理。
3. 光流静止、方向、质量、有效性和高度关系可观测。
4. 光流控制能够区分真实平移和姿态旋转造成的假位移。
5. 普通姿态、定点、定高三条控制链逐级验证，不互相污染。
6. 每个阶段都能独立编译、验证、回退和提交。

### 2.2 最终数据链

```text
MPU6050 原始数据
    ↓
加速度计 bias / scale 修正
    ↓
机体安装方向变换
    ↓
重力姿态解算
    ↓
固定安装角 Trim
    ↓
姿态 PID
    ↓
光流位置/速度修正
    ↓
电机混控
```

光流链路：

```text
光流 dx/dy
    ↓
质量门禁与零点
    ↓
姿态旋转补偿
    ↓
高度补偿
    ↓
水平速度/位置估计
    ↓
位置环 + 速度环
    ↓
目标 roll/pitch
```

- 当前实际定点参数；
- 最近一份黑匣子日志；

- 能明确区分 OF15 改动和本方案改动；
- 能确认飞行时实际使用的参数，而不是只看源码默认值；

## 5. 阶段 1：取消每次上电动态水平清零

### 5.1 会导致什么

保留当前逻辑会继续把斜地面写成水平，任何定点调参都会被错误姿态污染。

### 5.2 现在怎么办

修改目标：

1. 保留每次上电陀螺仪零偏校准。
2. 停止把当前停放姿态作为新的 roll/pitch 零点。
3. 让 `IMU_Attitude_Update()` 产生的重力姿态直接进入控制链。
4. 移除或停用 `IMU_Level_Apply()` 对飞行姿态的覆盖。
5. 清理不再需要的 `level_ready`、水平采样门禁和相关死路径。
6. 不同时修改姿态 PID、混控和光流增益。

建议涉及：

- `Modules/Motor/motor_test.c`
- `Modules/IMU/imu_level.c`
- `Modules/IMU/imu_level.h`
- 必要时同步 `Modules/IMU/imu_attitude.c/.h`

### 5.3 优化后如何

上电后：

```text
静止 → 校陀螺零偏
当前加速度 → 得到真实重力方向
当前地面有坡 → 姿态保留坡度，不自动清零
```

### 5.4 拆桨验收

1. 水平平台上电，姿态接近 `roll=0、pitch=0`。
2. 将机架垫出小坡后上电，姿态应显示实际倾角。
3. 换相反方向垫坡，姿态符号应反向。
4. 同一块斜平台重复上电，姿态不能被清成 0°。
5. 普通模式关闭定点时，其他行为应与修改前一致。

### 5.5 停止条件

- 姿态符号反向；
- 水平平台静止姿态大幅漂移；
- 姿态无法初始化；
- 普通模式出现与本次修改无关的电机或混控变化。

### 5.6 五要素

| 要素 | 内容 |
|---|---|
| 目标 | 消除地面坡度污染水平基准 |
| 文件 | `motor_test.c`、`imu_level.c/.h`，必要时 `imu_attitude.c/.h` |
| 影响 | 姿态初始化和横滚/俯仰零点；不改光流协议 |
| 资源 | RAM/Flash 增量接近 0，可能减少代码路径 |
| 验收 | 斜面姿态保留真实倾角，普通模式基线通过 |

### 5.7 提交节点

用户真机验证通过后提交：

```text
v0.xx：取消上电动态水平清零，恢复真实重力姿态基准
```

## 6. 阶段 2：固定安装角 Trim

### 6.1 会导致什么

如果飞控本身相对机架有固定安装倾角，单纯取消动态清零后，控制器可能存在固定姿态误差。

### 6.2 现在怎么办

增加单独的：

```text
mount_roll_trim
mount_pitch_trim
```

要求：

- 只在确认水平的平台上采样；
- 不和遥控器 `roll_trim/pitch_trim` 混用；
- 保存版本号和 CRC；
- 上电加载；
- 只有重新安装飞控或改变机架结构时才重做。

可能涉及：

- `Modules/IMU/imu_attitude.c/.h`
- `Modules/Flash/blackbox.c/.h`
- 必要时新增 `Modules/IMU/imu_calibration.c/.h`
- `.uvprojx` 文件登记新文件时，Keil 必须关闭。

### 6.3 优化后如何

```text
地面坡度：保留为真实姿态
飞控固定安装误差：用保存的 mount trim 修正
换起飞地点：不改变 mount trim
```

### 6.4 验收标准

- 水平平台上姿态接近零；
- 斜平台上姿态显示斜率；
- 重启后 Trim 保持；
- 换起飞地点不需要重新 Trim。

## 7. 阶段 3：简化/六面加速度计校准

### 7.1 会导致什么

没有加速度计 bias/scale 校准时，重力方向本身会带误差，姿态在不同安装方向和温度下可能不一致。

### 7.2 推荐实施顺序

先做简化版本，不要一开始做复杂椭球拟合：

1. 上；
2. 下；
3. 左；
4. 右；
5. 前；
6. 后。

每个姿态要求：

- 陀螺仪接近 0；
- 加速度模长接近 1g；
- 连续采样后取平均；
- 运动中自动拒绝；
- 每个方向保存有效标志。

六面不要求绝对 90°。可以用泡沫、木板、两个支点、书本和垫片制作简易支架。保持静止比角度绝对精确更重要。

### 7.3 代码方向

新增或扩展校准数据：

```c
typedef struct
{
    float accel_bias[3];
    float accel_scale[3];
    float mount_roll_deg;
    float mount_pitch_deg;
    uint32_t version;
    uint32_t crc;
    bool valid;
} IMU_Calibration_t;
```

应用顺序：

```text
原始加速度
→ bias 修正
→ scale 修正
→ 归一化
→ Mahony 重力融合
```

涉及：

- `Modules/IMU/imu_calibration.c/.h`
- `Modules/IMU/imu_attitude.c/.h`
- `Modules/Flash/blackbox.c/.h`
- `.uvprojx`

### 7.4 验收标准

- 保存后重启仍能加载；
- 静止加速度模长更稳定；
- 不同方向摆放时姿态误差较小；
- 校准失败时明确报错，不写入坏数据。

## 8. 阶段 4：姿态健康和在线 bias

### 8.1 目标

让姿态估计知道当前加速度是否可信，避免把电机振动或水平加速误当成重力。

### 8.2 建议改动

1. 静止时允许继续学习陀螺仪 bias。
2. 加速度模长异常时冻结 Mahony 重力修正。
3. 增加角速度和振动门限。
4. 加速度校准完成后重新评估 `0.95~1.10g` 门限。
5. 黑匣子增加姿态健康字段或诊断记录。

这一阶段不直接改变姿态 PID 增益。

## 10. 阶段 6：光流高度补偿

### 10.1 会导致什么

光流计数和高度相关。同样的真实水平位移，在不同高度下产生不同计数。当前参数在约 15cm 高度下有效，换高度后控制强弱可能改变。

### 10.2 推荐方案

先确认 ToF 高度可信，再加入保守补偿：

```text
Kp_eff = Kp_base × 当前高度 / 标定高度
```

后续再考虑直接把计数换算成厘米和厘米每秒。

### 10.3 涉及文件

- `Modules/Control/position_control.c`
- `Modules/Flow/flow.c`
- `Modules/ToF/tof.c`

### 10.4 停止条件

- ToF 被底座遮挡；
- 高度值跳变；
- 高度失效时仍继续补偿；
- 定点输出因高度变化突然放大。

## 11. 阶段 7：光流旋转补偿

### 11.1 会导致什么

光流镜头看到的是地面图像变化。飞机横滚、俯仰、偏航时，即使没有平移，也可能产生光流计数。

### 11.2 推荐顺序

先做低风险版本：

1. 增加角速度门限；
2. 角速度较大时降低定点输出；
3. 姿态快速变化时暂停位置积分；
4. 再根据真实安装参数做完整旋转补偿。

完整旋转补偿需要确认：

- 光流模块安装角；
- 相机高度；
- 输出坐标定义；
- 光流延迟；
- 机体系角速度。

### 11.3 涉及文件

- `Modules/Flow/flow.c`
- `Modules/Control/position_control.c/.h`
- `Modules/Motor/motor_test.c`

## 12. 阶段 8：重新整定定点

### 12.1 前置条件

只有以下全部通过后才能调定点：

- 阶段 1 IMU 基准通过；
- 普通模式基础姿态稳定；
- 光流静止不持续漂移；
- 光流方向正确；
- `pc_state=ACTIVE`；
- `pc_gate=0x1F`；
- ToF 高度可信。

### 12.2 调参顺序

初始保持：

```text
速度内环阶段：位置 Kp/Ki/Kd 全0；速度只开 Kp，Ki/Kd 为0
位置外环阶段：固定已验证的速度参数，位置只开 Kp，Ki/Kd 为0
```

调参顺序：

1. 普通模式基础姿态稳定，定点实际处于ACTIVE且门禁全通；
2. 先固定目标速度为零，逐步验证速度Kp的刹车能力；
3. 速度内环稳定后固定参数，再从小值逐步验证位置Kp的回位能力；
4. 每轮落地上锁只改一项，检查目标角是否持续摆动或饱和；
5. 最后再评估低通频率和角度限幅。

不先打开 Ki。光流累计误差和高度尺度没有稳定前，Ki 容易产生持续积累。

2026-10-07 手动上锁修复（代码/主机仿真通过，待真机验收）：有效遥控帧明确请求手动上锁时，定点回WAITING并清零输出；重新解锁且门禁全通后捕获新原点。已有真实故障锁存不因手动上锁或重新解锁被清除，仍需关开定点请求。位置仿真56/56、光流39/39。用户飞行日志场次10/11全部st=3/fr=5，不能当作有效增益对比。

### 12.3 涉及文件

- `Modules/Control/position_control.c/.h`
- `Modules/Control/pid_table.c/.h`
- 遥控端参数页面和协议

## 13. 阶段 9：定点与定高整合

当前实现中，定点修正只叠加到普通模式，定高模式暂不叠加。最终如果要实现“定高 + 定点同时悬停”，需要明确整合：

```text
水平：光流定点
垂直：ToF 定高
姿态：统一进入 roll/pitch 目标
```

这一阶段必须放到最后。不能在 IMU 和普通定点还未稳定时同时打开两个闭环。

可能涉及：

- `Modules/Motor/motor_test.c`
- `Modules/Control/vertical_control.c/.h`
- `Modules/Control/position_control.c/.h`

验收：

- 定高和定点互不抢油门；
- 定点故障不会破坏定高失效策略；
- 定高故障不会留下旧的定点姿态目标；
- 两个控制器退出时都清空积分和目标角。

## 15. 用户真机验证顺序

### 15.1 IMU 阶段

1. 拆桨；
2. 水平平台上电；
3. 记录静止姿态；
4. 垫出小坡；
5. 记录姿态是否保留真实倾角；
6. 换反方向垫坡；
7. 验证符号；
8. 通过后再装桨做低风险普通模式测试。

### 15.2 光流阶段

1. 上电等待 `cal=2`；
2. 确认 Quality 高于门限；
3. 静止观察 `sum_x/sum_y`；
4. 前后左右手推；
5. 确认方向和副轴；
6. 遮挡镜头；
7. 拔掉 TX；
8. 确认冻结和锁存；
9. 恢复后按设计重新开关请求。

### 15.3 定点阶段

1. 关闭定点，记录普通模式基线；
2. 打开定点，确认 `ACTIVE`；
3. 保持摇杆回中；
4. 先只做短时低风险测试；
5. 记录光流、姿态目标、电机修正；
6. 按一次只改一个参数的原则整定。

### 15.4 停止条件

- 姿态方向反了；
- `flow_sum` 静止时持续快速单向增长；
- Quality 长期低于门限；
- `pc_state` 未进入 `ACTIVE` 却有姿态修正；
- 定点输出方向与实际偏移相反；
- 输出达到 ±8° 仍继续偏移；
- 姿态或光流故障后没有按设计清零/锁存；
- 普通模式出现未解释的新现象。
