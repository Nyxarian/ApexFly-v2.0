## 1. 本阶段结论

这轮工作把“每次上电把当前地面当成水平”的处理，改为重力姿态、加速度计校准和固定安装角修正分别处理；同时补齐光流高度比例、旋转冻结、定点状态机和观测链路。

当前能够计算定点姿态修正，并在普通模式中送入姿态控制。遥控器可以修改、保存、加载位置与速度六项增益，串口和黑匣子可以查看定点实际状态。

“代码已经实现”不等于“飞行已经稳定”。2026-10-07两场完整飞行记录中的定点始终故障锁存，输出为零，所以不能把它们视为速度环整定成功，也不能据此认定增益过大。

最新完成的是正常手动上锁退等待修复：代码、仿真与语法检查通过，用户尚未提供修复后的编译、烧录和拆桨验收结果。

## 3. IMU处理结果

### 3.1 水平基准与传感器校准分开

- 上电仍采集陀螺仪静止零偏，但不再把当前摆放姿态强行清成水平。
- 六面校准处理加速度计三轴bias和scale，不等于机架安装角校准。
- 加速度计校准改变重力方向估计后，需要重新检查固定安装角修正。这解释了六面校准后平放角度曾重新出现偏差。
- 当前安装角修正为机体系 `roll=-0.14°`、`pitch=-0.87°`，属于代码中的固定常量；更换飞控、改变安装位置或传感器后需要重新检查。
- 当前六面算法不包含完整轴间不正交、温度模型或全矩阵安装旋转标定。

### 3.2 六面校准与保存

串口命令：

```text
calimu start
calimu next
calimu status
calimu save
calimu cancel
```

六面顺序为传感器原始轴 `X+ → X- → Y+ → Y- → Z+ → Z-`，不能直接把这些名称当成机架前后左右。

用户曾提供以下保存成功回显：

```text
[IMU_CAL] flash saved gen=1 bias=+0.04171,-0.08191,+0.02669 scale=1.00044,0.99864,0.98863.
```

这是一份历史保存证据，不是本次重新读取目标板Flash的结果。校准记录使用外部W25Q64末尾保留扇区中的64字节双副本，启动时读取有效记录；无需每次上电重新做六面采集。固定安装角修正与这份bias/scale记录分开。

### 3.3 姿态健康与在线零偏

已有诊断字段包括加速度模长 `an`、修正有效性 `ac`、健康状态 `ah`、静止状态 `st`、融合误差 `fe`、修正权重 `aw`、在线陀螺偏置 `gb` 和学习许可 `gl`。

在线学习仅在未解锁、静止、健康正常且加速度修正权重足够高时允许；时间常数约20秒，补偿限制为每轴±3°/s。解锁或运动时停止学习，避免把真实运动吸收为零偏。它不代替六面校准，也不在飞行中学习水平基准。

## 4. 当前定点控制链和参数

```text
光流原始帧
→ 校验、质量门禁、零点修正
→ 旋转门限抑制
→ 模块坐标转机体系
→ 高度比例缩放
→ 位置外环给目标速度
→ 速度内环给roll/pitch修正角
→ 输出低通
→ 普通模式下叠加到姿态目标
→ 原有姿态/角速度控制和电机混控
```

| 项目 | 当前代码值或规则 |
|---|---|
| 控制周期 | 姿态/电机任务250Hz；光流约25Hz；位置外环每两帧更新一次，约12.5Hz |
| 光流安装角 | 约54°，cos=0.5878、sin=0.8090 |
| 高度参考 | 14cm |
| 高度比例 | `hs=clamp(height_cm/14, 0.60, 2.00)` |
| 比例影响 | 同时缩放机体系光流位置和速度 |
| 高度限制 | 超过28cm后比例顶在2.00，不能视为更高高度也已完整补偿；当前量仍是光流计数，不是cm或m |
| 旋转冻结 | 三轴角速度最大绝对值达到25°/s时进入，降到15°/s及以下时退出 |
| 冻结行为 | 停止对应累积/控制更新，姿态修正清零，恢复后重新锚定 |
| 目标速度限幅 | 每轴±200 count/s |
| 姿态修正限幅 | roll/pitch各±8° |
| 输出低通 | 2.5Hz |
| 代码默认位置增益 | Kp=0.50，Ki=0，Kd=0 |
| 代码默认速度增益 | Kp=0.010，Ki=0，Kd=0 |
| 参数更新权限 | SET/SAVE/LOAD仅允许上锁状态操作 |
| 当前模式范围 | 普通模式支持定点；定高模式暂不叠加定点 |

默认值不是已经验证的最终飞行值。Flash保存参数会覆盖默认值，应以遥控回读及场次参数记录为准。

当前高度处理采用简化缩放模型；尚未证明高度变化过程中累计位置的连续性及跨高度闭环一致性。阶段6台架hs变化记录只能证明比例计算和钳位行为，不能代替这一项飞行验收。

## 5. 状态机与手动上锁修复

### 5.1 请求与实际状态必须分开看

| st | 含义 |
|---:|---|
| 0 | 定点请求关闭 |
| 1 | 等待有效使能条件 |
| 2 | 定点实际工作 |
| 3 | 故障锁存，禁止输出 |
| 4 | 摇杆离开中心，手动移动 |

| fr | 原因 |
|---:|---|
| 0 | 无故障 |
| 1 | 光流不可用 |
| 2 | 遥控链路故障 |
| 3 | 姿态超限 |
| 4 | 高度不可用/越界 |
| 5 | 控制许可失效 |

`gate=0x1F`表示五位门禁全通，但不会自动清除既有锁存。判断实际参与定点，应同时看 `st=2、fr=0、ok=1` 和修正输出；不能只看请求开关。

摇杆离开中心后，定点修正暂停；回中后按当前代码等待约200ms，再捕获新位置。因此推杆移动后松杆主要检验新位置的刹车和保持，不代表回到推杆前的原点。

### 5.2 旧问题与本次修复

旧路径可能为：

```text
定点ACTIVE → 正常手动上锁 → 许可失效 → fr=5锁存
→ 上锁改参数 → 再次解锁 → 定点仍不工作
```

修改参数命令本身不会触发锁存；不便来自参数操作前的正常上锁被当作故障。

本次新增的正常上锁判断是：链路正常、控制帧有效、遥控帧明确取消解锁请求。失联、内环禁用或IMU异常不能仅因 `armed=false` 就被当作正常上锁。

新的正常路径为：

```text
定点ACTIVE → 明确手动上锁 → WAITING，fr=0，输出/积分/旧锚点清零
→ 上锁改参数 → 再次解锁且门禁全通 → 在当前位置重新ACTIVE
```

Flow轮询在没有新光流帧或旋转冻结时也处理正常上锁。已有真实故障锁存不自动解除，后续光流失效不会覆盖已锁存的首次故障原因；仍需关闭、重开定点请求。

本次仅增加少量状态和分支，没有新增RTOS任务或动态内存，未修改Keil工程文件、遥控协议或增益。整工程最新Flash/RAM占用需由用户编译后的map确认。

## 8. 下一步执行顺序

### 8.1 先验收手动上锁修复

1. 用户Keil编译、烧录；测试全程拆桨，保持光流/ToF有效、摇杆回中。
2. 定点请求打开并解锁后，确认 `gate=0x1F、st=2、fr=0、ok=1`。
3. 手动上锁，确认 `req=1、st=1、fr=0、ok=0`，raw/out全部0。
4. 上锁修改一项参数，定点请求保持打开。
5. 平移机体到新位置后重新解锁，确认重新ACTIVE且在新位置锚定。
6. 连续重复两轮。
7. ACTIVE时遮挡镜头直到光流失效，确认st=3/fr=1；恢复光流、手动上锁/再解锁仍保持锁存；关闭、重开定点请求才允许恢复。

### 8.2 处理基础飞行问题

- 检查偏航变化是否为实际自转，查明并验证原因。
- 当前失联路径仍可能令 `armed=false` 后立即停桨，不能把本次调参便利性修复当成失联保护修复。
- 交接中的H12失效处理仍缺真机证据；若后续测试涉及定高，需先补该验收。

### 8.3 再做速度、位置整定

1. 普通模式基础姿态稳定，实际定点ACTIVE，有可靠光流与高度数据后，再开始飞行整定。
2. 速度环先：位置Kp/Ki/Kd全0，速度Ki/Kd为0；速度Kp=0.005仅作为首轮候选值，不是已证明安全的最终参数。
3. 刹车不足且无振荡时，每轮增大速度Kp约10%～20%；出现振荡、错误方向或输出持续饱和时结束该轮，不继续加。
4. 固定已验证的速度参数，再从位置Kp=0.10这个候选值开始，位置Ki/Kd仍为0，逐步检查回位和过冲。
5. 每轮落地上锁只改一项，记录实际六项参数、测试高度、机头方向、动作和场次编号。保持相同高度，暂不混入转向和高度变化。
6. 用黑匣子判断动态过程；当前串口每500ms打印一次，不足以排除快速振荡。
7. 合格参数在落地上锁后SAVE，断电回读验证，再重复同样动作。
8. 有效定点验收后再评估低通、角度限幅和跨高度一致性，最后另立阶段9方案整合定高。
