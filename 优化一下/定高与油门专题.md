## 1. 油门速率限制（不对称）—— 代码就绪，**飞行已验证**

### 1.1 之前是什么毛病

油门是"摇杆推多少、电机就出多少力"，**摇杆一动，力就一步到位**（4 毫秒内）。

从 1500 松到 1400 这么一点点，升力瞬间掉约 **31%**，飞机立刻以约 3 m/s² 往下加速。**降落时就是"稍微松一点就砸下来"。**

### 1.2 现在的做法

在"摇杆→油门"后面加了一层**限速**，而且**上升快、下降慢**：

| 方向 | 速率 | 效果 |
|---|---|---|
| 上升 | **800 µs/s** | 满行程约 0.75 秒（爬升要跟手） |
| 下降 | **300 µs/s** | 满行程约 2.0 秒（降落变"沉"不变"砸"） |

**映射本身一个字没改**，最高油门还是遥控器那个参数说了算。

### 1.3 飞行数据验证 ✅

2026-09-11 那次 80 秒记录的实测（看"每一拍油门变化了多少"）：

| 方向 | 实测每拍最大变化 | 理论上限 | 结论 |
|---|---|---|---|
| 上升 | **4 µs** | 3.2 → 取整 4 | ✅ 恰好卡在限幅上 |
| 下降 | **2 µs** | 1.2 → 取整 2 | ✅ 恰好卡在限幅上 |

**没有一拍超限。** 降落段实测 1439→1001 µs 用 1.52 秒，平均 288 µs/s。

### 1.4 ⭐ 踩坑记录（很重要，差点写错）

**第一版写成了"把取整后的整数存回去"，结果速率被系统性吃掉：**

| | 目标 | 实测 |
|---|---|---|
| 上升 | 800 µs/s | **750**（−6.3%） |
| 下降 | 300 µs/s | **250**（−16.7%） |

**原因**：每拍把小数部分丢掉，反复累积就丢了。比如每拍该走 3.2 µs，取整后只剩 3 µs，那 0.2 µs 永远丢了。

**改法**：**存回浮点数**（带小数），只有送给电机的那一个数才取整。

改完实测：**797.9 / 300.0 µs/s**，20 次往返推拉零累积误差。

### 1.5 三处复位（最容易漏的地方）

限速器有"记忆"，所以下面三个时刻必须清零，否则会出鬼：

| # | 时刻 | 漏了会怎样 |
|---|---|---|
| 1 | 任务初始化 | — |
| 2 | 外层重新初始化 IMU | 油门跳变 |
| 3 | **未解锁分支** | 🔴 **解锁瞬间从上一轮的残留值开始爬，看起来像"油门自己动"** |

## 2. 偏航环 —— 已定型，但有一条尾巴

### 2.1 参数与效果

| 参数 | 值 |
|---|---|
| `yaw_rate_kp` | **0.95** |
| `yaw_angle_kp` | **1.15** |
| `yaw_rate_ki` / `yaw_angle_ki` | 0 / 0 |
| 两个 `kd` | 0 / 0 |

| 指标 | 修复前 | 现在 |
|---|---|---|
| 自转速度 | **260 dps 且在加速** | **1.2 dps** |
| 偏航修正占用 | — | **42%**（余量充足） |

### 2.2 ⚠️ 尾巴：起飞时会自己转 60~90°

**现象**：不管机头朝哪，一离地就**顺时针转大约 90°**，然后停住。

**原因（已用数据确认）**：
- 飞机身上有一个**恒定的偏航力矩**（机械不平衡，转桨/换件带来的）
- 地面上被摩擦力顶住，看不出来
- **一离地，摩擦没了，它就开始转**
- 航向环只有 P（比例），**要出力就必须保留一个偏差** —— 转够几十度，反力矩才够抵消它
- 数据佐证：起飞后 1.5 秒转了 61°，偏航修正从 −3 µs 涨到 −75 µs 后不再增长

**和参数的关系**：
```
需要保留的角度偏差 ≈ 需要的偏航修正量 ÷ yaw_angle_kp
                   ≈ 84 µs ÷ 1.15  ≈ 73°
```

**结论**：**这不是参数没调好，是"只有 P 的控制器"对恒定力矩的固有局限。**

### 2.3 ⭐ 一个参数耦合的发现（将来要用）

想消掉这个 90°，常规做法是打开 `yaw_angle_ki`。但算下来**可能只能降到 45° 左右**，原因是个参数耦合：

```
外环积分上限 = yaw_max_rate_dps × 0.15 = 200 × 0.15 = 30 dps
但那个恒定力矩需要外环输出约 88 dps 才够
→ 积分打到 30 就封顶了，剩下只能靠 P 补 → 还是留 40 多度偏差
```

**第二颗旋钮**：把 `yaw_max_rate_dps` 调大，积分上限跟着涨。

| `yaw_max_rate_dps` | 积分上限 | 预期旋转 |
|---|---|---|
| 200（现在） | 30 dps | 约 45° |
| 400 | 60 dps | 约 20° |
| 600 | 90 dps | 接近 0° |

**✅ 关键**：这**不会让方向杆变灵敏** —— 打杆速率是**另一个独立常量**（`ATTITUDE_YAW_STICK_MAX_RATE_DPS = 200`），当初特意解耦过。

**（用户已决定暂不处理，因为手动能压住。留档备查。）**

### 2.4 偏航 Ki/Kd 的决策依据（留档）

| 轴 | Ki | Kd | 为什么 |
|---|---|---|---|
| 横滚 / 俯仰 | **0，保持** | 0.01，保持 | **有重力当"免费的积分器"**；实测姿态偏差只有 ±2°，没必要 |
| **偏航角度环** | 要加就从 0.01 起 | **不用** | **没有重力参考**，恒定力矩必须靠积分消掉 |
| **偏航速率环** | 保持 0 | **不用** | 速率环的静差会被外环积分吸收，两个积分器会打架 |
| 全轴 | — | 外环 Kd 与内环 P **功能重复** | 微分改成"对测量求导"后，外环 D = −Kd×角速度，内环 P 本来就在拿角速度做阻尼（#28 已论证） |

## 3. 磁力计航向在 0°/360° 边界有"换行野值"

### 3.1 现象

整段出现 **20 次**磁航向单拍跳变，**全部**发生在同一个位置：

```
0.1°  ←→  327.7°      （反复横跳，跳变 ±32°）
```

| 项 | 结果 |
|---|---|
| 磁航向跳变 >5° 的次数 | **20 次** |
| 其中发生在 0°/360° 或 327.7° 附近 | **20 次（100%）** |
| 发生在其它位置 | **0 次** |
| **同时**融合偏航角的单拍最大变化 | **仅 0.58°** |

**结论：这是磁航向在换行边界上的计算野值，不是真实转动。**（327.7 = 360 − 32.3，典型的换行算术问题）

### 3.2 影响评估：现在不严重，但会随增益放大

- ✅ 好消息：飞控**扛住了**。航向误差计算里用了 ±180° 化的处理，野值没有打穿控制
- ✅ 融合偏航角完全不受影响
- ⚠️ 隐患：每次野值会给偏航角度环注入一个 **32° 的虚假误差** → 约 **37 dps 的目标速率突变** → 约 **35 µs 的额外修正**

**现在 `yaw_angle_kp` 只有 1.15，所以扰动小。如果将来把角度环 Kp 提高，这个野值会线性放大。**

**建议**：列为**独立小问题**，在做偏航精调之前先加个"跳变门限/野值剔除"。现在不用动。

## 4. 起飞会往一个方向漂 2~5 米才稳住

### 4.1 现象

离地到稳定（约 20~30 cm 高）之间，会朝一个方向平移 **2~5 米**，之后就很稳（1 平方米内）。

### 4.2 原因（已量化）

**不是姿态环没工作** —— 实测爬升段姿态几乎是平的（roll −0.09°、pitch +0.28°）。

**真正的原因是：姿态环只管"角度"，不管"速度"。**

```
离地那一刻有点倾角（起落架不平 / 放置面有坡 / 单侧先离地）
   → 攒下水平速度
   → 姿态环把姿态扳平了，但【速度还在】
   → 它没有任何办法把速度刹住
   → 只能等空气阻力慢慢把速度耗掉
   → 这段时间里就飘出去 2~5 米
```

**算出来的应有速度**：约 **1.4~2.2 m/s**（对应漂移 2~5 米，用悬停段的阻力系数反推）。

**这是"没有位置/速度反馈"的必然结果，不是参数问题。** 姿态环没有"速度"这个输入，所以它治不了。

### 4.3 实测交叉验证（都很健康）

| 项 | 值 | 含义 |
|---|---|---|
| 悬停 `roll` 均值 | 1.46° | 姿态很稳 |
| 悬停 `pitch` 均值 | 0.70° | 姿态很稳 |
| 悬停 `roll_corr` 均值 | **−4.3 µs**（占限幅 2.1%） | 横滚几乎不用出力 |
| 悬停 `pitch_corr` 均值 | **+1.9 µs**（占限幅 0.9%） | 俯仰几乎不用出力 |
| **混控残差** | **0.42 µs**（偏航型 0.09 µs） | 四路脉宽 100% 由"油门+三个修正量"解释，混控无偏差 |

**注意**：`roll_corr` / `pitch_corr` 都只有几 µs，说明**横滚俯仰方向几乎没有不平衡力矩**；而 `yaw_corr` 有 −78 µs。**机械不平衡只在偏航轴上。**

### 4.4 解决方向（按性价比）

| 顺序 | 做法 | 成本 |
|---|---|---|
| **1** | **先确认漂移方向是否每次都一致**（连飞 3 次记录方向） | 零 |
| **2** | 若一致 → 用 `roll_trim_deg` / `pitch_trim_deg` 抵消 | 零（遥控改参数） |
| **3** | 起飞后**主动用杆修正**（打杆 10° 就是 1.7 m/s² 的刹车力） | 零（操作习惯） |
| 4 | 定高会接管起飞爬升 → 顺带缩短这段窗口 | 定高的一部分 |
| 5 | 根治 → 定点（水平位置环） | 后期 |

# 第二部分 · 定高与油门重做方案

## 8. 现在油门的根本毛病

### 8.1 当前逻辑

```
摇杆推到某个位置 → 电机就按那个位置出力 → 结束
```

**飞控完全不知道飞机在哪、多高、在升还是在降。它就是个"放大器"。**

### 8.2 由此产生的三个问题

**问题一：你永远找不到那个"刚好"的点**

飞机停在空中需要"推力 = 重量"。多一点点往上飘，少一点点往下掉。而那个"刚好"需要的摇杆位置，往往落在两个刻度之间 —— **手上捏不住。**

**问题二：那个"刚好"的位置是会变的**

- 电池满电 → 电多 → 同样油门出力更大
- 电池用一半 → 电少 → 同样油门出力变小
- 换了更重的电池 → 又要重新找

**所以今天调好的，明天、下一块电池、甚至飞了两分钟后，都不对了。**

**问题三：油门是"累积"的（关键）**

```
油门偏差 → 造成的是【加速度】→ 累积成【速度】→ 累积成【高度】
```

**油门偏一点点，不是让飞机偏一点点，而是让它一直加速往上/往下。时间越长偏得越多。**

**这才是为什么手动悬停本质上做不到 —— 不是没调好，是这条路走不通。**

## 9. 定高要做的事，就一句话

> **让飞控自己去找那个"刚好"的力。**

```
现在：你告诉我出多少力
定高：你告诉我停在哪，我来想办法稳住

  你：我想停在 0.5 米
  飞控：现在 0.3 米？加一点力
        现在 0.5 米了？稳住
        现在 0.6 米了？减一点力
        （每秒检查 250 次，一直在微调）
```

**直接好处**：你松杆，它就停在那，不掉也不飘。

## 10. "自动起飞 / 自动降落"其实是同一件事

| 你要的功能 | 其实就是定高在做什么 |
|---|---|
| **自动起飞** | 告诉定高："目标高度从 0 **慢慢升**到 0.5 米" |
| **自动降落** | 告诉定高："目标高度从 0.5 米**慢慢降**到 0" |
| **定高悬停** | 告诉定高："目标高度**保持** 0.5 米" |

**三个功能，同一个大脑。** 区别只是"目标高度"这个数字怎么变。

**所以做完定高，"自动起飞/降落"基本是顺手的事。**

## 11. 摇杆怎么设计（推荐方案）

**不建议"摇杆位置直接等于高度"** —— 那等于把"手动油门"换成了"手动高度"，还是难。

**推荐：摇杆控制"升/降的快慢"，不是"高度"**

```
摇杆在中间   → 别动，我自己保持高度     ← 【松手就稳住，这是最有用的】
摇杆往上推   → 往上爬，推得越多爬得越快  ← 但有速度上限
摇杆往下拉   → 往下掉，拉得越多掉得越快  ← 也有速度上限
```

**关键**：松手 → 目标变成"0 速度" → **飞机自己稳住不动**。不用你去捏那个"刚好"。

**速度上限**：比如最快爬升 0.3 米/秒、最快下降 0.2 米/秒。
- 0.2 米/秒什么概念：**从 1 米高落到地面要 5 秒**，足够平顺
- **自动降落用的就是这个 0.2 米/秒** —— 你要的"缓慢降落"，本质就是给它一个速度上限

> 注：现有 `altitude_control.c` 里已经有一套类似的逻辑（摇杆 <400 下降 / 400~600 定高 / >600 爬升），
> **与推荐方案的差别在于"摇杆权限给多大"**，这需要你拍板。

## 12. 定高需要"眼睛"——高度传感器

| 传感器 | 优点 | 缺点 |
|---|---|---|
| **激光测距**（用户计划） | 准、反应快、低空很稳 | 地面有草/深色/不平整时可能测不准；超出量程就没用 |
| 气压计（板子上已有） | 便宜、不挑地面；**硬件和代码都在，零成本** | 漂；螺旋桨的风会干扰 |

**建议：激光为主，但代码里必须留"测不到就自动放弃"的退路。**

### ⚠️ 激光要提前定的两件事

1. **量程**：要飞 5 米高，模块量程至少 6~8 米，不然 2 米的模块飞到 3 米就"瞎"了
2. **走哪条线**：现在磁力计占了 I2C2，激光若挂同一条总线要确认不打架，或换线

## 13. ⚠️ 安全：必须有"万一失灵"的退路（硬要求）

定高是让飞控**接管油门**。万一高度读数坏了（被挡住、反光不对、超出量程、倾角太大），**飞机会带着错误认知乱加油门** —— 这比手动危险得多。

**必须做到：**
```
一旦认为"高度读数不可信"
   → 立刻把油门还给摇杆
   → 并且告诉你（遥控器提示 / 飞机响一下）
```

**这不是可选项，是定高的一部分，不能"以后再补"。**

## 14. 动手顺序

```
第 1 步  把"悬停油门"这个参数理顺（见 6.3）
          —— 名不副实，不理顺后面会打架

第 2 步  打通遥控器与飞控之间的"高度"这条路
          —— 现在协议里没有"高度"字段，遥控器上也看不到；
             不打通，后面只能靠串口打印调试，很不方便

第 3 步  接激光，先只做"看"，不参与控制
          —— 台架上手动抬升/放下飞机，看数字跟不跟得上、稳不稳
          【进度】🔶 驱动与任务已完成（单次测量模式），零点方案已废弃（见第 18 节），待真机验证

第 4 步  把定高接进来，同时把摇杆改成"松手就稳住"

第 5 步  做自动起飞（目标高度慢慢爬到 0.5 米 → 保持）

```

**每一步都能单独验证，出问题好定位。**

## 18. 激光测距（ToF / VL53L1X）已接入 —— 现状与决策留档

> 2026-09-11 记录。对应遥控器第 2 步"打通高度显示" + 第 3 步"接激光，先只做看"。

### 18.1 硬件与接线（已确认可用）

| 项 | 内容 |
|---|---|
| 型号 | VL53L1X（ToF 激光测距），7 位 I2C 地址 **0x29** |
| 挂在哪 | **I2C2**（PA8/PA9），与磁力计 QMC5883P（0x2C）**共用同一条总线** |
| 型号自检 | 寄存器 `0x010F=0xEA`、`0x0110=0xCC` → model ID **0xEACC** |
| 总线互斥 | 驱动的每次 I2C 访问都在 `I2C2_Lock()/I2C2_Unlock()` 里 |
| 任务优先级 | `tofTask` = `osPriorityBelowNormal`，与 `magtask` 同级，每步 `osDelay` 让出 CPU，磁力计不会被饿死 |

### 18.2 ⭐ 为什么用"单次测量"而不是"连续测量"（踩坑记录）

**实测结论：本芯片的连续模式（`MODE_START=0x40`）写入成功、寄存器也读回 0x40，但永远不产生新测量结果。**

- 诊断过程：连续模式下 `RESULT__INTERRUPT_STATUS` 一直是 0、没有任何结果被锁存；反复烧录多次都一样。
- 单次模式（`MODE_START=0x10`）**每次都正常完成**：mode 自动回到 0x00，`RESULT__RANGE_STATUS` 读到 0x09（测距完成），距离正确。
- 因此驱动改成"**触发一次 → 轮询等完成 → 读结果 → 再触发**"，由 ToF 任务按固定节奏反复驱动。
- 节奏：每 20ms 走一步，一次测量占 **4 步**（触发 / 等 1 拍 / 等 2 拍转读 / 读结果），
  实测一轮约 83ms，即**约 12 Hz**。
  ⚠️ 这里原来写的是"3 步 / 约 16.7Hz"，是数错了步数，2026-09-11 按串口实测（`n=` 每 500ms 增加 6）更正。

其它两个寄存器事实：
- `GPIO__TIO_HV_STATUS` 的 bit0：**0 表示数据就绪**（1 表示未就绪，注意是反的）。
- 有结果锁存时 `RESULT__INTERRUPT_STATUS` 读到 0x07。

**驱动实现依据**：ST 数据手册 **DS12385 Rev 8**（地址、型号 ID、寄存器语义）+ **UM2356**（完整寄存器说明）+ Pololu `vl53l1x-arduino`（MIT 许可）的等价初始化序列。**不是**网上流传的 91 字节魔法表。

### 18.3 ⭐⭐ 决策：不做"地面零点"（已废弃，不要加回来）

**曾经的做法**：解锁那一刻采一次地面读数当零点，`高度 = 当前距离 − 零点`。

**废弃原因（三条）**：

1. **收益太小**：镜头装在机身底部，机械偏置只有约 **2cm**。为一个常数引入一套状态机、4 个静态变量、2 个外部调用点，不值。
2. **耦合出过真实故障**：零点必须绑定"飞机确实在地面"的时刻。当时在 `motor_test.c` 的上锁分支里放了一句 `ToF_ResetGroundZero()`，而那条分支跑在 **250Hz 控制环**里 → **每 4ms 清一次**采零点的累加器，而 ToF 数据 60ms 才来一个 → 计数永远到不了门槛 → **上锁状态下高度恒为 0**（遥控器一直显示 0cm）。这是本轮实际踩到的坑。
3. **它解决不了倾斜误差**：机身倾斜 θ 角时，镜头顺机身 -Z 轴打出去，测到的是 `d = h / cosθ`，**比真实垂直高度偏大**（θ=30° 时偏大 15%）。真正要补的是 `h = d·cosθ`（θ 用 MPU6050 的横滚/俯仰合成）——零点相减只是减一个常数，对这个误差毫无帮助。

**现在的做法**：`tof.c` **直接输出实测距离换算的厘米值**，不减任何零点。

- 飞机停在地面上时读数约 **2cm**（就是安装偏置），不显示 0。
- 上锁 / 解锁 / 落地 / 起飞，**任何时候都能看到高度**，与控制环的解锁状态完全解耦。
- 上电后第一个有效读数就有高度，不再有"等采满 N 次"的空白期。

### 18.4 保留的数据处理（都是必要的）

| 处理 | 参数 | 为什么 |
|---|---|---|
| **距离低通滤波** | α = 1/4（`TOF_LPF_ALPHA_SHIFT 2`），τ ≈ 330ms | 实测原始值峰峰 3~5mm、滤波后 0~1mm，约 **3~4 倍降噪**；⚠️ 这个滞后只影响显示，估计器吃的是原始值 |
| 滤波用**定点** | 1/4 毫米（`tof_distance_filtered_q2`） | ⭐ 整数毫米写法有 ~3mm **死区**（差值<4mm 时移位结果为 0，滤波值卡住不动），存 1/4 毫米后死区只剩 0.25mm |
| 差值**必须有符号** | `int32_t diff_q2` | ⭐ 无符号相减在距离变小时会**下溢**，滤波值直接跳到 2^30 量级 |
| 滤波器**起步** | `tof_distance_filter_primed` | 低通从 0 往上爬，前 8 拍明显偏低；第一个读数直接作为初值 |
| 毫米 → 厘米 | **四舍五入** `(mm + 5) / 10` | 直接整除会把 19mm 砍成 1cm，系统性少 0~1cm |
| 测不到时 | 保持上一次读数 + `fresh=0` + `age_ms` 累加 | 上层能一眼看出"这个数是新的还是旧的" |
| 连续失败 | `TOF_MISS_REINIT 10` 轮（约 1.6 秒）→ 重新初始化 | 真掉线时才重来，偶发一次不折腾 |

### 18.5 数据链路（从镜头到遥控器屏幕）

```
VL53L1X ──I2C2──> tofTask（单次测量 + 低通滤波 + 换算 cm）
                        │  ToF_GetAltitudeCm()   ← 250Hz 控制环只做一次 32 位读取，不碰 I2C2 锁
                        ▼
                  motor_test.c（控制环）
                        │  Radio_PublishFlightState(..., altitude_cm, ...)
                        ▼
                  radio.c → ApexTelemetry_t.altitude_cm（int32，payload 偏移 6，**单位：厘米**）
                        │  无线
                        ▼
                  遥控器 radio_snapshot.telemetry.altitude_cm → LVGL `高度` / `标签高度`
```

- 协议**没有改动**（`altitude_cm` 字段本来就存在，只是以前没人填）。
- 遥控器端由"米"改成"厘米"直接显示：仪表盘 `%.0fcm`、遥测页 `%.0f cm`。

### 18.6 已知限制（做定高前必须知道）

| 限制 | 数值 / 说明 |
|---|---|
| 量程 | 短距档约 **1.3m**；超出后读数失效，飞控**保持最后一个值**（不会归 0） |
| 最小测距 | 约 **4cm**。实测飞机静置在对镜面时距离约 **65mm**（`status=0` 全程有效），距最小测距还有余量，**不构成风险** |
| 倾斜误差 | `d = h / cosθ`，**定高前必须补 `h = d·cosθ`** |
| 地面反射 | 草地/深色/不平整地面会削弱信号，可能读不到 → 定高必须留"读数不可信就交还手动"的退路 |

# 附录 B · 一句话总结

> **油门现在只会傻出力，因为它不知道飞机在哪。定高就是给它装上眼睛和脑子，让它自己去找那个"刚好"的力。**
> **"自动起飞/自动降落"不是新功能，就是"让目标高度这个数字慢慢变"—— 同一个大脑，三种用法。**
> **摇杆建议改成"松手就稳住、推拉控制快慢"，这样就不用你手动捏那个"刚好"了。**
> **动手前必须先理顺那个"悬停油门"参数（现在名不副实），必须先打通遥控器上"高度"的显示与控制通道。**
> **硬要求：高度读数一旦不可信，必须立刻把油门还给摇杆。**
