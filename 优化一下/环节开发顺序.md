## 排序的核心规则

**凡是会改变"测量基准 / 被控对象动态特性 / 环路结构"的环节，必须排在 PID 整定之前；性能增强类放最后。**

理由：在这之前整定出来的 PID 参数，一旦上述环节改动就会失效——等于白调。

三条配套铁律：
1. 每次只改一个环节，改完立刻用黑匣子/台架对比。
2. 每个环节留档：`pid.csv` + 黑匣子场次号 + 一句结论。
3. 凡涉及滤波、频率、控制律的改动，必须重新整定 PID。

## #23 备注：混控下限取 1050us，四路起转点暂未实测（2026-09-09）

### 决定
- 混控输出有效下限统一为 **1050us**（新增 `MIXER_PWM_EFFECTIVE_MIN_US`）；
- 删除 `MotorTest_ApplyMixer()` 里"事后逐路硬抬到 1050us"的四行裁剪，让 `mixer.c` 的统一缩放保护真正生效。

### 1050 是"暂定值"
`1050us` 是按经验取的（电调起转点通常落在 1050–1100us 区间）。
**四路电调的实际起转点尚未台架实测**，等出现相关现象时再补测。

### 触发补测的现象
| 现象 | 可能原因 |
|---|---|
| 低油门段某一路不转 / 四路起转不同步 | 该路起转点高于 1050us |
| 起飞瞬间明显往一侧偏 | 四路起转点不一致 |
| 大修正时某路停转 | 有效下限低于该路实际起转点 |

### 台架测法（待用）
1. 拆桨，逐路单独从 1000us 缓慢增加；
2. 记录每路"开始连续转动"时的脉宽；
3. 取四路最大值 + 20~30us 余量，作为新的 `MIXER_PWM_EFFECTIVE_MIN_US`；
4. 同步更新 `MOTOR_ATTITUDE_ENABLE_PWM_US`（已引用同一常量）。

### 验证记录（2026-09-09，`[MIX]` 打印，10Hz）
| 现象 | 数据 | 判定 |
|---|---|---|
| 未饱和段 | `thr=1105 m1=1106 m2=1106 m3=1104 m4=1104 scale=1.00` | ✅ 四路差速正常 |
| 向下空间不足 | `thr=1085 m1=1120 m2=1103 m3=1067 m4=1050 scale=0.66` | ✅ 统一缩放，最低路恰好触底 |
| 修正反向 | `m1=1050 m2=1050 m3=1130 m4=1129 scale=0.95` | ✅ 差速方向随姿态反转 |
| 有无硬抬 | 最低路**恰好** 1050，其余三路按比例分布 | ✅ 无事后裁剪失真 |

算例核对：`thr=1085`，向下空间 `1085-1050=35us`，原始向下修正约 `53us` → `scale=35/53≈0.66`，与打印一致；缩放后 `1085-53×0.66=1050`（触底）。

> 附带发现（已随打印删除）：未解锁/低油门时 `mixer_output` 结构体未填充（走 `Motor_SetAllPulseUs()`），故打印显示 `m1~m4=0`，实际电机输出正常（1000us）。黑匣子样本只在解锁后提交，不受影响。

### 安全边界
| 项 | 说明 |
|---|---|
| 必须拆桨 | 测试模式上电后会自动让电机转起来 |
| 单路驱动 | 同一时刻只有一路有油门，其余三路 1000us，避免扭矩失衡 |
| 分辨率 10us→5us | 已按用户要求用 5us；若某路卡在两档之间，可把 `SPIN_BASE_US` 挪到该档附近再精测 |
| 无桨 ≠ 带桨 | 无桨负载小，**测得值是起转点下界**；带桨会更高，结论按"四路最大值 + 余量"取 |
| 不能飞 | 此模式无姿态控制、无混控、无解锁门禁 |

### 验证记录（2026-09-09，无桨逐路阶梯扫描，步进 5us）
| 电机 | 1030us 现象 | 稳定转动点 |
|---|---|---|
| M1 后右 | 有转动迹象但堵转、转一下停一下 | **1035us** |
| M2 前右 | 有转动迹象但堵转、转一下停一下 | **1035us** |
| M3 后左 | 直接正常转起 | **1030us** |
| M4 前左 | 有转动迹象但堵转、转一下停一下 | **1035us** |

极差仅 **5us**，四路一致性很好。

### 结论 1：起飞单向漂移**不是**起转点不一致造成的
四路起转点差异 ≤5us，低油门段推力差异可忽略，**该假设排除**。
漂移原因继续往别处查：IMU 水平零点（roll −1.54° / pitch −3.46°）、重心偏移、电机安装倾角、PID 极性/增益。

### 结论 2：1030us 是堵转区，1050us 下限太紧
M1/M2/M4 在 1030us 处于“转一下停一下”的堵转状态，1035us 才稳定转起。
原下限 1050us 只比最差起转点高 **15us**，带桨负载抬升后极可能不够。

**决定：`MIXER_PWM_EFFECTIVE_MIN_US` 1050 → 1100us**
- = 最差起转点 1035 + 65us 余量，覆盖带桨后负载变大导致的起转点抬升；
- 远离 1030us 堵转区；
- 悬停 1550us 时向下余量 450us、向上余量 450us，**正好对称**（原 1050 是 500/450）；
- 自动带到 `MOTOR_ATTITUDE_ENABLE_PWM_US`（引用同一常量）；
- `motor.h` 的 `MOTOR_PWM_IDLE_US` 同步改为 1100us（原本无代码引用，避免以后误用低于下限的值）；
- 未动：`altitude_control.c` 的 `ALT_OUT_MIN_US 1050.0f`（定高未启用，属死代码，启用定高时一并改）。

### 带桨起转点测试 —— 决定延后（2026-09-09）
本次只测了**无桨**起转点。带桨负载下起转点会往上抬，但**本次不做**：

| 原因 | 说明 |
|---|---|
| 带桨逐路单电机不安全 | 会产生巨大扭矩差，必须拆桨才能逐路测 |

## #25 备注：输出限幅与油门关系 —— 决定跳过（2026-09-09）

### 决定
**跳过**。根因已由 #23 修掉，清单给的备选方案经分析**不采用**。

### 根因已消除
#25 的原始描述是"三轴修正 ±200us 与基础油门无关，靠混控 scale 兜底，但 **1050 事后下限又破坏 scale**"。
"事后下限破坏 scale"正是 #23 删掉的那四行逐路裁剪。现在：
- 混控拿到 `minimum_pulse_us = MIXER_PWM_EFFECTIVE_MIN_US`，按 upward/downward room **统一缩放**；
- 事后裁剪不存在，`correction_scale` 真实生效。

#23 的 `[MIX]` 串口数据已直接验证：`thr=1105 scale=1.00`；`thr=1085 scale=0.66`；大倾角 `scale=0.36`。

### 为什么不做"按油门比例限制修正上限"
该方案要在 PID 层**逐轴**按油门封顶。但四路电机修正是三轴的线性组合
（`M1=−roll+pitch−yaw` …），逐轴封顶会在"某轴顶到上限、另一轴没顶到"时**扭曲力矩方向**；
混控的"四路乘同一系数"统一缩放严格保方向。现有结构更优，不改成逐轴。

### 限幅体系全貌（#26 之后）
| 限幅 | 当前值 | 可调范围 | 依据 |
|---|---|---|---|
| 混控有效下限 | 1100us | 编译常量 | #24 实测（最差起转 1035 + 65 余量） |
| 混控上限 | 2000us | 编译常量 | 电调量程 |
| 外环输出（目标角速度） | ±200 dps | 20～300（遥控） | 待 #29 定值 |
| 内环输出（混控修正） | ±200 us | 20～300（遥控） | 悬停 1550 时可用余量 450us，200 = 44% |
| 外环积分限幅 | out_max × 0.15 = 30 dps | 派生 | #26 |
| 内环积分限幅 | out_max × 0.25 = 50 us | 派生 | #26 |

## #26 备注：限幅语义拆解（rate / correction 分离）（2026-09-09）

### 问题
`pid_table.c` 原来 6 处都是同一写法：

```c
case APEX_PID_ROLL_MAX_RATE_DPS:
    pid->roll_angle.out_max = value;
    pid->roll_angle.out_min = -value;
    pid->roll_angle.i_limit = value;   /* 积分限幅被绑死成输出限幅 */
    break;
```

后果：改输出限幅连带改积分限幅；积分项理论上可独占 100% 输出（windup）；"MAX_RATE_DPS"这个名字同时表示两种量。

### 约束
协议 0x07 的 30 个参数 ID 已用满，`APEX_PROTOCOL_PID_RESPONSE_PAYLOAD_LENGTH = 4 + 30×4 = 124` 字节。
加 6 个独立 i_limit ID → 36 个 → 负载 148 字节 → **遥控端必须同步升级**。

### 决定：方案 A —— 比例派生（不动协议）
- `PidParam_t` **删掉 `i_limit` 字段**（参数表不再携带积分限幅）；
- `attitude_control.c` 新增比例常量：
  ```c
  #define ATTITUDE_OUTER_I_LIMIT_RATIO 0.15f  /* 外环：目标角速度 */
  #define ATTITUDE_INNER_I_LIMIT_RATIO 0.25f  /* 内环：混控修正 */
  ```
- 积分限幅在 `AttitudeControl_InitAxis()` 里按 `out_max × 比例` 推导，覆盖全部路径（编译默认 / 遥控 SET / Flash 回灌）；
- `pid_table.c` 的 6 处 `i_limit = value` 全部删除。

效果：外环 200 dps → i_limit 30 dps；内环 200 us → i_limit 50 us。
改输出限幅时积分限幅按比例跟随，**永远 ≤ 输出限幅且不再相等**。

### 未做（记为待办）
完全独立、遥控可调的 i_limit 需要协议扩展（30 → 36 个参数 ID，应答 124 → 148 字节，遥控端同步改）。
留到 **#30 整定 Ki** 时再决定是否需要。

### 验证记录（2026-09-09，串口 `[PIDL]`）

|---|---|---|

## #27 备注：积分限幅 + anti-windup（2026-09-09）

### 问题（改动前）
`Pid_Update()` 里积分和输出两套限幅互不知情：
- 积分只保证不超过 `i_limit`，不知道 `output` 已经撞到 `out_max` → **饱和期间继续积分（windup）**；
- 混控的 `correction_scale` 缩放对 PID 不可见 → **低油门段积分账面值虚高**，恢复油门时突然全额生效。

后果：大动作后回中过冲 / 低频来回摆；起飞后某方向过冲。
正常平飞碰不到（悬停 room 350us > 请求 200us），**只在"大姿态 + 高 Ki + 低油门"三者叠加时暴露**，
所以本质是给 #30 整定 Ki 买保险。

### 改动（A + B 都做）

**A. 条件积分**（`pid.c`）
先算试探性积分 → 试探性输出；若已撞上下限且误差还在往同侧推，本拍不采纳积分。
误差反向时照常积分，能自然退饱和。

**B. 交付比例收缩积分限幅**（`pid.h/.c` + `cascade_pid.h/.c` + `attitude_control.c`）
- `Pid_t` 新增 `delivery_scale`（默认 1.0），`Pid_Reset()` 一并复位；
- 新增 `Pid_SetDeliveryScale()` 与 `CascadePid_SetInnerDeliveryScale()`；
- `AttitudeControl_Update()` 把上一拍混控的 `correction_scale` 喂给三个内环，
  `AttitudeControl_Reset()` 复位为 1.0。

积分限幅 = `i_limit × delivery_scale`，保证积分占"实际交付量"的比例恒为 25%。
**不新增任何可调参数**；外环不参与（其输出是目标角速度，不经过混控缩放）。

### 明确不做
| 项 | 原因 |
|---|---|
| back-calculation 反算法 | 多一个待整定参数；冻结已能防发散。若 #30 发现退饱和过冲仍偏大再加 |
| 级联 anti-windup（外环随内环饱和冻结） | Ki_outer 当前为 0，待 #30 启用再评估 |
| 改动 `i_limit` 数值 | #26 已定 0.25，本环节只改"何时积分、积到多少" |

## #28 备注：微分项（改对测量微分 + 一阶低通）（2026-09-09）

### 问题（改动前）
`deriv = (error - last_error)/dt`，对**误差**求导且**无滤波**：
- **微分冲击**：`d(error)/dt = d(目标)/dt − d(测量)/dt`，目标值（摇杆、Trim、外环输出）一突变就出尖峰。
  内环目标跳 20 dps 时，Kd=0.01 就产生 20us 尖峰；Kd=0.1 直接打满 200us 限幅。
- **噪声放大 100 倍**：dt=10ms 时求导等于把噪声 ×100。陀螺 0.25dps 噪声 → 25 dps²，
  Kd=0.5 时变成 12.5us 的电机抖动。
- 后果：**Kd 根本调不上去**，#30 整定少一个阻尼手段。

### 改动
1. **微分改为对测量求导**：`deriv_raw = -(measured - last_measured)/dt`，丢掉 d(目标)/dt；
2. **一阶低通**：`alpha = tau/(tau+dt)`，`deriv_filtered = alpha*flt + (1-alpha)*raw`，
   `tau = PID_DERIV_FILTER_TAU_S = 0.008s`，系数由 dt 实时算出，**与采样率无关**；
3. **dt 异常时 `first_run = true`**，下一拍微分重新起算，避免用错的间隔求导。

`Pid_t` 字段：删 `last_error` / `last_deriv`，新增 `last_measured` / `deriv_raw` / `deriv_filtered`（净增 4 字节 × 6 组 = 24 字节）。

### 参数依据（用户选定 tau = 8ms）
| 项 | 值 |
|---|---|
| 时间常数 tau | 8ms |
| 截止频率 | ≈20Hz |
| 5Hz 处相位滞后 | −14° |
| 50Hz 处衰减 | −16dB（噪声压 6.4 倍） |

控制带宽约 5Hz、IMU DLPF 42Hz，截止取在两者之间。

### 明确不做
| 项 | 原因 |
|---|---|
| 对测量值本身滤波 | 整个环都吃延迟，不如只滤 D 项 |
| 二阶低通 / 陷波器 | 100Hz 采样下收益不明显，等 #33 提频再考虑 |
| 摇杆速率前馈 | 属于 #29 目标角速率限制的范畴，不能靠 D 项替代 |
| 改 Kd 数值 | #30 的事 |

### 副作用（记录）
- 丢掉了原来 `d(目标)/dt` 带来的轻微"打杆前馈"，打杆跟手度略降；
- **外环 D 与内环 P 重复**：对测量微分后，外环 D = −Kd×实际角速度，与内环的阻尼作用重叠，
  建议外环 Kd 保持 0（编译默认已是 0；Flash 参数里的 0.01 影响可忽略，可在 #30 设 0）。

### 验证（地面，无需飞行）
临时 `[D]` 打印（10Hz，输出这 10 拍内的绝对值峰值保持）：

```
[D] roll_r raw_peak=.. flt_peak=.. flt=.. kd=.. d=..
```

| # | 操作 | 预期 |
|---|---|---|
| 1 | Kd 全 0 解锁 | 输出与改动前逐位一致（回归） |
| 2 | 手快速敲 / 拧机体 | `raw_peak` 大幅跳变，`flt_peak` 明显小一个量级 |
| 3 | 静置不动 | `flt` 趋近 0，无噪声底 |
| 4 | 快速打满横滚杆再回中 | `raw_peak` **仍然很小**（改动前会出尖峰） |

## #29 备注：目标角速率限制（2026-09-09）

## #16 备注：温度补偿 —— 决定跳过（2026-09-08）

### 原理链
芯片自热（开机升温 10–20℃）→ 陀螺零偏漂移（典型 ±0.05 dps/℃，共 0.5–1 dps）→ 角速度输入偏 → roll/pitch 被重力修正拉回，yaw 无修正直接漂。

### 为什么跳过

| 理由 | 说明 |
|---|---|
| yaw 有绝对参考 | 外置磁力计提供绝对航向，陀螺零偏漂移不再累积成航向误差（原本这是温度补偿的主要收益） |
| roll/pitch 已有两层保护 | ① Mahony 重力修正；② **Ki 积分项本身就在线估计零偏**（Ki=0.03/s → 时间常数约 33s，跟得上分钟级的温度漂移） |
| 增量收益集中在起飞前 30s | 之后 Mahony 自己会收敛 |
| 标定成本高 | 需 30–60 分钟自然升温采集 + 曲线拟合 + Flash 存储 + 运行时修正 |
| 拟合风险 | 曲线标定不好会引入新的系统性偏差，比不补偿更糟 |

### 若将来要做（无需温箱）

1. 飞机静置上电，跑 30–60 分钟（芯片从室温到热稳定）；
2. 每秒记录陀螺三轴原始值 + 芯片温度（黑匣子或串口）；
3. 拟合 `bias = a + b×T`（每轴一组系数）；
4. 存 Flash，运行时按当前温度修正。

### 低成本替代

把 Mahony 的 `Ki` 从 0.03 提到 0.05–0.08（零偏自适应时间常数 33s → 12–20s），在 #30 整定时一起试；注意 Ki 过大易把重力噪声积分进姿态。

### 触发条件

出现"飞行 1–2 分钟后姿态/航向开始漂"，或要启用 yaw 航向环做长航时飞行时，再启动。

## #13 备注：加速度计标定 —— 方案变更与延后决定（2026-09-08）

### 原方案（六面法）已否决

| 原因 | 说明 |
|---|---|
| 无人机无法稳定放置 | 只有底面能平放，其余 5 个面必须手扶；手扶必然晃动 → 样本被污染 |
| 历史实测失败 | 之前用过一次六面法，效果很差，实际上只有底面能校准 |

### 替代方案：自由姿态椭球拟合（只标零偏 + 单一尺度）

**原理**：静止时加速度计读数满足 `|a_meas − b| = 1g`，展开成线性方程

```
|a_meas|² − 2·bᵀ·a_meas + (|b|² − 1) = 0
```

只需采集 N 个**任意姿态**的静止样本，最小二乘解 4 个未知数（`b_x, b_y, b_z` + 常数项）即可得到零偏。

**操作**：手持无人机缓慢翻转，每到一个姿态停 0.5–1 秒；系统用"静止检测"自动筛样本（连续 200ms 内加速度变化 <0.02g、陀螺 <2dps、模长 0.8–1.2g），采 30–50 个覆盖良好的样本后自动拟合。

**优势**：不需要精确对准、手扶可接受、无需稳定放置。

### 为什么延后：必须脱离电脑操作

用户现场校准只带**遥控器 + 无人机**（不带电脑，串口需要连线）。因此这项必须由遥控端配合：

1. 遥控器上有"开始校准"入口；
2. 校准过程中显示"采集进度 / 采集完成"；
3. 飞机需通过遥测回传采集状态（需协议字段或复用 flags 位）。

→ 工作量分布在飞控端 + 遥控端两侧，且权重不高（小倾角悬停下水平零点已吸收零偏影响）。

### 决定与触发条件

## #31 备注：#11 / #12 / #31 / #32 / #33 属于同一次架构改造

这五项本质是**一个整体**，必须一起做，拆开做等于返工两次：

| 步骤 | 内容 | 对应环节 |
|---|---|---|
| ① | `SMPLRT_DIV` 改为与控制环匹配（或保持 1kHz + 中断分频） | #11 |
| ② | `HAL_GPIO_EXTI_Callback()` 增加 IMU_INT 分支 → `xTaskNotifyFromISR` 唤醒控制任务 | #11 / #32 |
| ③ | 控制环由"定时驱动"改为"DRDY 事件驱动 + 超时兜底" | #11 |
| ④ | I2C 读改 DMA（消除阻塞，同时降低跨更新边界概率） | #12 / #31 |
| ⑤ | 控制频率提到 250–500Hz，DLPF 同步放宽、PID 重新整定 | #33 |

**当前暂缓的原因（2026-09-08 决定）**：

- 芯片内部 1kHz 采样 + 控制环 100Hz 定时读 → **每次读到的都是新样本**，数据新鲜度已经很高；
- DRDY 唯一能改善的是"14 字节读（0.4ms）跨芯片更新边界"（约 40% 概率、影响 <0.3°）；
- 改造涉及控制环驱动方式、3 个以上文件、超时保护 → **风险 > 收益**；
- 而真正的触发点是 #33：控制频率一旦提上去，阻塞读 + 定时驱动的开销和相位延迟会放大，届时 DRDY + DMA 成为必需品。

**结论**：等做 #33 时，把 #11、#12、#31、#32 一起实施。

## #33 备注：DLPF 档位必须随控制频率同步修改

**#10（DLPF 档位）已评估并决定不改**：当前控制频率 100Hz → 采样 Nyquist 50Hz，DLPF 保持 **42Hz（DLPF_CFG=3）** 是最优（略低于 Nyquist，抗混叠正确；电机振动 100–300Hz 被有效衰减）。

但 **#33 提升控制频率时，DLPF 必须同步放宽**，否则高频振动会混叠进低频污染姿态角：

| 控制频率 | 采样 Nyquist | 应改的 DLPF | 延迟 |
|---|---|---|---|
| 100Hz（现在） | 50Hz | **42Hz（档 3，现状）** | 4.9ms |
| 250Hz | 125Hz | 98Hz（档 2） | 2.8ms |
| 500Hz | 250Hz | 188Hz（档 1） | 1.9ms |

配套动作（#33 时一并做）：
1. 改 `mpu6050.c` 的 `MPU6050_REG_CONFIG` 值（0x03 → 0x02 或 0x01）；
2. **Mahony 的 Kp/Ki 必须重新整定**（滤波延迟从 4.9ms 降到 1.9–2.8ms，相位特性变了）；
3. 做完重新走一遍 PID 整定（#30）。

## 油门速率限制（不对称）—— 独立增强项（2026-09-11）

### 问题
`MotorTest_MapStickToThrottleUs()` 是纯静态映射、无记忆：摇杆动多少，基础油门一帧内（4ms）跟到位。

后果（实测推算）：从 1500us 松到 1400us 是 100us 阶跃 → 升力瞬间损失约 `100 × 3.1 = 310gf`，
约等于**整机重力的 31%** → 净力立刻变成 −0.31g → 以约 3m/s² 向下加速，0.5s 就到 1.5m/s。
降落时表现为"稍微松一点就砸下来"，容易摔机臂、震松固定螺丝。

**本质**：油门只有"位置维度"，没有"时间维度"。

### 改动
在映射之后插入一层一阶速率限制（**不对称**），只动 `Modules/Motor/motor_test.c` 一个文件。

| 常量 | 值 | 换算 |
|---|---|---|
| `MOTOR_THROTTLE_SLEW_UP_US_PER_S` | **800 us/s** | 满行程 1000→1600 约 0.75s |
| `MOTOR_THROTTLE_SLEW_DOWN_US_PER_S` | **300 us/s** | 满行程 1600→1000 约 2.0s |

**为什么不对称**：痛点在下降；上升取 800 是刻意保留"爬升要跟手"的能力。
**数值依据**：悬停附近推力斜率约 3.1gf/us，300us/s 下每拍(4ms)只变 1.2us，
远小于"温和修正"所需的 16us 量级，不影响姿态环正常补油。

**映射本身一行未动**：最高油门仍由 PID 表 `APEX_PID_HOVER_PWM_US` 决定，保持遥控可调。

### 实现要点（踩坑记录）
1. **状态必须回喂浮点值，不能回喂取整后的整数。**
   初版写成 `throttle_slew_us = (float)throttle_us;`（先取整再回喂），
   每拍丢弃小数部分 → 实测速率被系统性吃掉：**800→750、300→250（约 −6%）**。
   改成回喂 `MotorTest_ThrottleRampLimit()` 的浮点返回值后，实测 **797.9 / 300.0 us/s**，准确。
   （用宿主侧仿真复算发现，仿真脚本见 `_inbox_会话提取\提取脚本\sim_slew.js`）
2. **状态复位共三处，必须与既有的 `throttle_us = MOTOR_PWM_MIN_US` 成对**：
   ①任务初始化 ②外层循环重初始化 IMU ③**未解锁分支**。
   漏第 ③ 处会导致解锁瞬间从上一轮的残留值开始爬升（看起来像"解锁后油门自己动"）。
3. `dt_s` 用现成的 `control_dt_s`（已由控制环限幅到 2~12ms），异常 dt 不会产生大阶跃。
