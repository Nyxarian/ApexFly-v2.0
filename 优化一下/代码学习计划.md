# ApexFly V2.0 代码学习计划

> 目标：按照代码真正的开发顺序、启动顺序和数据流顺序，把项目从底层硬件一路读到飞行控制输出。
>
> 原则：每次只学习一条主链路；先看“谁调用谁”，再看函数内部；只读代码，不在学习过程中修改固件。

## 一、学习方法

每个阶段都回答同一组问题：

1. 这部分代码由谁初始化？
2. 初始化写了哪些寄存器、状态或默认值？
3. 数据从哪里来，原始单位是什么？
4. 中间经过了哪些换算、滤波、校准或状态判断？
5. 最终数据被谁使用，输出单位是什么？
6. 运行频率、任务、队列或中断关系是什么？
7. 失败、超时、数据无效时，系统会怎么处理？

每学完一个阶段，留下四项内容：

- 一张调用顺序图；
- 一张输入/输出和单位表；
- 关键状态和故障门禁；
- 用自己的话写出的三条结论。

学习过程中不按文件名从上到下阅读。先找到运行入口，再沿调用关系向下追。一个模块没有读完初始化、正常路径和故障路径，不进入下一个模块。

## 二、整体项目学习顺序

下面的顺序同时参考“为什么先开发它”和“飞机启动后先运行什么”。每一阶段先学底层依赖，再学它的上层使用者。

### 第 0 阶段：芯片启动和基础外设

目标是知道程序怎样从复位进入 FreeRTOS，以及每个外设由谁初始化。

阅读顺序：

```text
Core/Src/main.c
  → HAL_MspInit / 外设初始化
  → Core/Src/app_freertos.c
  → 任务创建和启动
  → Core/Src/stm32g4xx_it.c
  → 中断入口和回调转发
```

重点确认：

- I2C1 给 MPU6050；
- I2C2 给磁力计和其他总线设备；
- SPI3 给 W25Q64 黑匣子；
- TIM8 给电机 PWM；
- USART、DMA、EXTI 和 DRDY 怎样连接到任务。

完成标准：能画出“复位 → HAL 初始化 → FreeRTOS 任务创建 → 任务开始运行”的顺序。

### 第 1 阶段：PWM 和电机输出

这是第一个可观察的硬件结果：PWM 正确后，电机才有可能转动。

阅读顺序：

```text
Core/Src/main.c
  → MX_TIM8_Init()
  → Modules/Motor/motor.c
  → Motor_Init()
  → PWM 通道写入
  → Modules/Motor/motor_test.c
  → 解锁、油门映射、软启动、上锁
```

重点确认：

- PWM 频率、最小值、最大值和单位；
- 四个电机编号和安装位置；
- 油门从遥控值到微秒值的映射；
- 上锁时为什么必须立即回到最低值；
- 电机测试阶段为什么不能绕过安全条件。

完成标准：不用看 PID，也能解释“一个油门值怎样变成四个 PWM 输出”。

### 第 2 阶段：MPU6050 原始数据链

这是第一个完整传感器模块。必须从寄存器读到控制环输入。

阅读顺序：

```text
Modules/Motor/motor_test.c
  → MPU6050_Init()
  → MPU6050_ReadData()
  → MPU6050_ReadRaw()
  → 连续读取加速度/陀螺仪寄存器
  → 原始 int16 数据
  → g 和 °/s
```

文件顺序：

1. `Modules/IMU/mpu6050.h`
2. `Modules/IMU/mpu6050.c`
3. `Modules/Motor/motor_test.c` 中的初始化和读取位置

完成标准：能说明 WHO_AM_I、量程配置、采样寄存器起始地址、原始值缩放，以及一次读取失败会返回什么。

### 第 3 阶段：陀螺零偏和水平零点

原始数据不能直接用于控制，先看启动时怎样建立零点。

阅读顺序：

```text
motor_test.c
  → IMU_GyroBias_Start()
  → IMU_GyroBias_Update()
  → IMU_GyroBias_Apply()
  → IMU_Level_Start()
  → IMU_Level_Update()
  → IMU_Level_Apply()
```

文件：

- `Modules/IMU/imu_bias.h/.c`
- `Modules/IMU/imu_level.h/.c`
- `Modules/Motor/motor_test.c`

重点确认：

- 什么条件下才允许采样；
- 为什么移动或加速度模长异常会重新开始；
- 陀螺零偏和姿态水平零点有什么区别；
- 零点最终在哪一拍作用到数据上。

### 第 4 阶段：四元数和姿态角

这是 MPU6050 数据进入姿态解算的阶段。

阅读顺序：

```text
MPU6050_Data_t
  → IMU_Attitude_Update()
  → 加速度低通
  → 加速度有效性判断
  → 重力方向
  → Mahony 误差修正
  → 陀螺积分
  → 四元数归一化
  → roll / pitch / yaw
  → IMU_Attitude_MapToBody()
```

文件：

- `Modules/IMU/imu_attitude.h/.c`
- `Modules/Motor/motor_test.c`

重点确认：

- 四元数四个分量分别保存什么；
- Mahony 的比例项和积分项修正什么误差；
- 为什么偏航角没有加速度计绝对参考；
- 芯片坐标和机体坐标为什么要重新映射；
- 姿态角、角速度和加速度的正方向约定。

### 第 5 阶段：姿态 PID、混控和电机输出

姿态解算完成后，才看它如何控制飞机。

阅读顺序：

```text
IMU_BodyAttitude_t
  → AttitudeControl_Update()
  → 外环角度 PID
  → 内环角速度 PID
  → CascadePid_UpdateOuter()
  → CascadePid_UpdateInner()
  → Mixer_Calculate()
  → Motor_Write()
```

文件：

- `Modules/Control/pid.h/.c`
- `Modules/Control/cascade_pid.h/.c`
- `Modules/Control/attitude_control.h/.c`
- `Modules/Control/mixer.h/.c`
- `Modules/Motor/motor.c`

完成标准：给出一个具体例子：机体向右倾 5° 时，误差怎样进入外环、内环和四个电机的 PWM。

### 第 6 阶段：遥控链路和模式状态

控制输入必须在进入姿态环之前看懂。

阅读顺序：

```text
Radio_Task()
  → 协议帧接收
  → ControlLink_Update()
  → 遥控快照
  → 油门、Roll、Pitch、Yaw、模式和定点请求
  → motor_test.c
```

文件：

- `Modules/Communication/apex_protocol.h/.c`
- `Modules/Communication/radio.h/.c`
- `Modules/Communication/control_link.h/.c`
- `Modules/Motor/motor_test.c`

重点确认：

- 链路失联和数据无效如何区分；
- 解锁条件在哪里判断；
- 摇杆居中怎样影响定点门禁；
- 普通模式、定高模式和定点请求怎样同时存在。

### 第 7 阶段：磁力计和偏航保持

在姿态基础链路稳定后，再看绝对航向。

阅读顺序：

```text
Modules/Mag/mag.c
  → 设备识别
  → 原始磁场读取
  → 芯片坐标到机体坐标
  → 硬铁校准
  → 磁航向
  → attitude_control.c 的偏航保持
```

完成标准：能说明磁力计为什么只能给偏航提供绝对参考，为什么校准、安装方向和电机电流都会影响它。

### 第 8 阶段：ToF、垂速和定高

阅读顺序：

```text
ToF_Task()
  → 单次测距
  → 有效距离和滤波距离
  → VerticalEst_Update()
  → 高度、垂速和有效性
  → VerticalControl_Update()
  → 油门修正
```

文件：

- `Modules/ToF/tof.h/.c`
- `Modules/Control/vertical_est.h/.c`
- `Modules/Control/vertical_control.h/.c`
- `Modules/Motor/motor_test.c`

重点确认：

- 原始高度、滤波高度和估计高度的区别；
- ToF 多久没有新数据会判无效；
- 高度门禁怎样影响定点和定高；
- 油门上限和垂速控制怎样叠加。

### 第 9 阶段：光流、位置环和速度环

这是最后接入姿态目标的主要控制链。

阅读顺序：

```text
Flow_Task()
  → 光流帧读取
  → 零点扣除
  → 累计位移和瞬时速度
  → 固定坐标旋转
  → position_control.c
  → 位置环：位置误差 → 目标速度
  → 速度环：速度误差 → roll/pitch 修正角
  → motor_test.c
  → attitude_control.c
```

文件：

- `Modules/Flow/flow.h/.c`
- `Modules/Control/position_control.h/.c`
- `Modules/Motor/motor_test.c`
- `Modules/Control/attitude_control.c`

完成标准：能解释“摇杆回中后，当前位置怎样成为锚点；飞机移动后，位置误差怎样最终变成姿态修正角”。

### 第 10 阶段：参数、黑匣子和整机闭环

最后看参数怎样进入控制器，以及数据怎样留下来。

阅读顺序：

```text
遥控 PID GET/SET/SAVE/LOAD
  → pid_table.c
  → 姿态/高度/定点参数
  → 控制器读取参数
  → blackbox.c 写入场次、样本和参数版本
  → 串口 CSV 导出
```

文件：

- `Modules/Control/pid_table.h/.c`
- `Modules/Flash/blackbox.h/.c`
- 遥控端 `Algorithms/ui.c`
- 遥控端 `Apps/App_Radio_Task.c`

重点确认：

- RAM 参数、SAVE 到 Flash、LOAD 恢复的区别；
- 每次参数版本怎样和后续飞行数据对应；
- CSV 每一列来自哪个结构体字段；
- 旧日志和新日志为什么需要兼容。

## 三、单个模块的固定学习模板

以后学习 MPU6050、GPS、ToF、磁力计或光流，都套用下面的顺序：

```text
1. 头文件：结构体、枚举、单位、公开接口
2. 初始化：设备地址、寄存器、默认状态
3. 原始读取：总线操作、字节顺序、错误码
4. 数值转换：比例、单位、坐标和符号
5. 滤波/校准：输入、输出、状态保存
6. 有效性：超时、范围、重试和故障状态
7. 上层调用：谁消费这个数据
8. 输出：控制量、遥测或黑匣子字段
9. 最小例子：给一个输入，手算一拍输出
10. 验收：用日志、串口或仿真验证
```

## 五、第一轮学习安排

第一轮不改代码，只做阅读和复述：

1. `main.c` 与 `app_freertos.c`：画任务启动图；
2. `motor.c` 与 `motor_test.c`：看 PWM 和上锁保护；
3. `mpu6050.h/.c`：看寄存器读取和单位换算；
4. `imu_bias.c` 与 `imu_level.c`：看启动校准；
5. `imu_attitude.c`：看四元数和姿态角；
6. 回到 `motor_test.c`：把整条 MPU → 姿态角链路复述一遍。

第一轮完成后，再进入姿态 PID。这样每个 PID 输入都能追溯到真实传感器数据，不会只看到一个孤立的增益数字。

## 六、Codex 桌面端的配合方式

使用代码面板时，每次只打开一个源文件和一个对应的头文件。提问时带上文件名、函数名或行号，例如：

```text
请只解释 Modules/IMU/mpu6050.c 的 MPU6050_ReadRaw()。
不要修改代码，按寄存器读取、字节拼接、单位换算、错误处理四部分说明。
```

如果问题会打断主学习路线，就开一个 side chat；主聊天只保留学习路线和阶段结论。代码解释阶段默认只读，不提交、不烧录、不改工程。

这份计划本身只规定学习顺序，不代替每个阶段的详细讲解。正式开始时，从第 0 阶段和第 1 阶段进入，然后按顺序推进到 MPU6050。
